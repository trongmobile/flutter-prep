  1. var, let và const khác nhau thế nào? Khai báo object bằng const thì có sửa được thuộc tính không?

    Xem đáp án mẫu
    var có phạm vi theo function, được hoist và khởi tạo sẵn undefined, lại cho khai báo lại cùng tên nên dễ gây bug. let và const có phạm vi theo block {}; chúng cũng được hoist nhưng nằm trong temporal dead zone (TDZ) cho tới dòng khai báo, truy cập sớm sẽ ném ReferenceError. Riêng function declaration được hoist cả thân hàm nên gọi trước dòng khai báo vẫn chạy. const chỉ cấm gán lại biến chứ không làm object bất biến: sửa user.name vẫn được, gán user = {} mới lỗi. Quy ước hiện nay là mặc định dùng const, cần gán lại thì dùng let, không dùng var.
    const user = { name: 'An' };
user.name = 'Bình'; // OK: chỉ sửa thuộc tính
// user = {};       // lỗi: không gán lại được biến const

if (true) {
  var a = 1;
  let b = 2;
}
console.log(a); // 1: var không bị giới hạn trong block
// console.log(b); // ReferenceError: b is not defined

console.log(c); // ReferenceError: Cannot access 'c' before initialization
let c = 3;

  2. Closure là gì? Cho một ví dụ closure bạn gặp khi viết code thực tế.

    Xem đáp án mẫu
    Closure là khi một hàm ghi nhớ và truy cập được các biến của scope nơi nó được tạo, kể cả khi hàm bên ngoài đã chạy xong. Ví dụ createCounter trả về một hàm vẫn giữ được biến count; mỗi lần gọi createCounter lại tạo ra một closure với count riêng. Ứng dụng thực tế: giấu dữ liệu private, tạo hàm cấu hình sẵn (factory), viết debounce. Trong React, mỗi event handler khai báo trong component cũng là closure: nó nhìn thấy props và state của đúng lần render đã tạo ra nó. Bẫy kinh điển là dùng var trong vòng for với callback chạy sau: mọi callback dùng chung một biến, nên hãy dùng let.
    function createCounter() {
  let count = 0; // bên ngoài không truy cập trực tiếp được
  return () => {
    count += 1;
    return count;
  };
}

const next = createCounter();
next(); // 1
next(); // 2: count vẫn còn sống nhờ closure
const other = createCounter();
other(); // 1: closure mới, count riêng

  3. this trong JavaScript được xác định thế nào? Arrow function khác function thường ở điểm nào về this?

    Xem đáp án mẫu
    Với function thường, this được quyết định lúc gọi chứ không phải lúc khai báo: gọi user.greet() thì this là user, nhưng gán const f = user.greet rồi gọi f() thì this không còn là user: trong strict mode (mặc định của ES module và class) nó là undefined và truy cập this.name sẽ ném lỗi. Arrow function không có this riêng mà dùng this của scope bao quanh nơi nó được viết, và call/apply/bind cũng không đổi được. Vì vậy arrow function hợp làm callback bên trong method (setTimeout, map), còn method của object cần dùng this thì không nên viết bằng arrow. Với function component và hooks gần như không cần this; nó chủ yếu còn gặp ở class component cũ, nơi phải bind handler hoặc khai báo handler bằng arrow class field.

  4. == và === khác nhau thế nào? Những giá trị nào là falsy trong JavaScript?

    Xem đáp án mẫu
    === so sánh nghiêm ngặt: khác kiểu là false ngay; == ép kiểu trước khi so nên cho ra những kết quả khó đoán như '1' == 1 hay 0 == '' đều là true. Quy ước là luôn dùng ===; ngoại lệ hay gặp là x == null để bắt cùng lúc null và undefined, và TypeScript cũng báo lỗi nhiều phép so sánh giữa hai kiểu không liên quan. Falsy chỉ gồm false, 0, -0, 0n, '', null, undefined và NaN; mọi giá trị khác đều truthy, kể cả '0', [] và {}. Bẫy thường gặp: price || 'Liên hệ' hiển thị "Liên hệ" khi giá bằng 0, trong khi price ?? 'Liên hệ' chỉ thay thế khi giá là null hoặc undefined.

  5. Destructuring và spread ... dùng thế nào? Vì sao nói spread chỉ là shallow copy?

    Xem đáp án mẫu
    Destructuring tách giá trị từ object hoặc array ra biến: const { name, age = 18 } = user, const [first, ...rest] = list; giá trị mặc định chỉ áp dụng khi thuộc tính là undefined. Trong component, destructuring thường dùng ngay ở tham số để nhận props: function Card({ title, onPress }). Spread sao chép phần tử hoặc thuộc tính sang mảng/object mới, key viết sau ghi đè key trước, nên rất hợp để tạo state mới thay vì mutate. Nhưng spread chỉ copy một tầng: object lồng bên trong vẫn dùng chung tham chiếu, sửa bản copy cũng làm đổi bản gốc; khi cập nhật state lồng nhau phải spread lại từng tầng cần sửa.
    const user = { name: 'An', address: { city: 'Hà Nội' } };

const renamed = { ...user, name: 'Bình' }; // key sau ghi đè key trước

const shallow = { ...user };
shallow.address.city = 'Đà Nẵng';
console.log(user.address.city); // 'Đà Nẵng': address vẫn dùng chung

// Cập nhật đúng: copy lại từng tầng cần sửa
const moved = { ...user, address: { ...user.address, city: 'Huế' } };

  6. Promise và async/await liên quan thế nào? await có làm đứng UI không, và xử lý lỗi ra sao?

    Xem đáp án mẫu
    Promise đại diện cho một kết quả sẽ có trong tương lai, ở một trong ba trạng thái pending, fulfilled hoặc rejected, và được xử lý bằng .then/.catch/.finally. async/await là cú pháp viết Promise cho dễ đọc: hàm async luôn trả về Promise, còn await chỉ tạm dừng riêng hàm đó cho tới khi Promise xong. await không chặn JS thread, trong lúc chờ app vẫn render và nhận thao tác của người dùng. Lỗi được bắt bằng try/catch quanh await, còn finally dùng để tắt loading dù thành công hay thất bại. Bẫy hay gặp là quên await: bạn nhận về Promise thay vì dữ liệu và lỗi không rơi vào catch.
    const [loading, setLoading] = useState(false);

async function onSubmit() {
  setLoading(true);
  try {
    await api.saveProfile(form); // chờ nhưng không chặn UI
    Alert.alert('Đã lưu');
  } catch (e) {
    Alert.alert('Lỗi', 'Không lưu được, thử lại sau');
  } finally {
    setLoading(false); // luôn chạy
  }
}

  7. Trong TypeScript, type và interface khác nhau thế nào khi khai báo props cho component? Prop optional viết ra sao?

    Xem đáp án mẫu
    Cả hai đều mô tả được shape của object, nên với props gần như dùng thay nhau được; nhiều team chọn một cách và dùng thống nhất. interface mở rộng bằng extends và hỗ trợ declaration merging (hai khai báo trùng tên được gộp lại). type là alias cho mọi kiểu, nên chỉ type viết được union như 'primary' | 'secondary', tuple, hay kết hợp kiểu bằng &. Prop optional thêm dấu ?: bên trong component nó có kiểu string | undefined, nên phải gán giá trị mặc định khi destructuring hoặc kiểm tra trước khi dùng.
    type ButtonVariant = 'primary' | 'secondary'; // union: chỉ type làm được

interface AppButtonProps {
  title: string;
  variant?: ButtonVariant; // optional: có thể không truyền
  onPress: () => void;
}

function AppButton({ title, variant = 'primary', onPress }: AppButtonProps) {
  return (
    <Pressable onPress={onPress} style={variant === 'primary' ? styles.primary : styles.secondary}>
      <Text>{title}</Text>
    </Pressable>
  );
}

React & Hooks

Mọi rank →

  1. Props và state khác nhau thế nào? Component con có được sửa props mà nó nhận không?

    Xem đáp án mẫu
    Props là dữ liệu component cha truyền xuống, với component con chúng là read-only; state là dữ liệu component tự sở hữu, tạo bằng useState và chỉ thay đổi qua hàm setter. Khi props hoặc state thay đổi, component render lại để UI khớp với dữ liệu mới. Con không được sửa props vì React coi props là bất biến; muốn đổi dữ liệu do cha quản lý thì cha truyền xuống một callback như onChange và con gọi callback đó. Đây là luồng dữ liệu một chiều: dữ liệu chảy xuống qua props, sự kiện đi ngược lên qua callback, nhờ vậy dễ biết state nằm ở đâu và ai được phép đổi nó.

  2. Vì sao gọi setCount(count + 1) ba lần liên tiếp trong một handler mà count chỉ tăng 1? Sửa thế nào?

    Xem đáp án mẫu
    Setter của useState không đổi biến count ngay mà xếp yêu cầu cập nhật vào hàng đợi và lên lịch render lại. Trong cùng một lần render, count là hằng số của lần render đó, nên cả ba lời gọi đều tương đương setCount(0 + 1). Khi giá trị mới phụ thuộc giá trị cũ, hãy dùng updater function setCount((c) => c + 1): React chạy lần lượt từng updater với giá trị mới nhất trong hàng đợi, nên tăng đủ 3. Cũng vì cơ chế này, console.log(count) ngay sau khi gọi setter vẫn in ra giá trị cũ.
    const [count, setCount] = useState(0);

const addThreeWrong = () => {
  setCount(count + 1);
  setCount(count + 1);
  setCount(count + 1); // count chỉ thành 1
};

const addThree = () => {
  setCount((c) => c + 1);
  setCount((c) => c + 1);
  setCount((c) => c + 1); // count thành 3
};

  3. JSX là gì? Kể vài quy tắc JSX hay bị viết sai, đặc biệt khi dùng trong React Native.

    Xem đáp án mẫu
    JSX là cú pháp mở rộng của JavaScript, được Babel biên dịch thành lời gọi hàm (jsx() hoặc React.createElement) tạo ra object mô tả UI, nên bản chất nó là JavaScript chứ không phải HTML. Quy tắc cần nhớ: mỗi biểu thức JSX chỉ có một phần tử gốc (bọc bằng View hoặc Fragment <>...</>), mọi thẻ phải đóng (<Image />), trong {} chỉ đặt được biểu thức nên dùng toán tử ba ngôi hoặc map thay cho if/for, và tên component phải viết hoa chữ cái đầu. Riêng React Native, chữ phải nằm trong <Text>: đặt chuỗi trực tiếp trong <View> sẽ lỗi "Text strings must be rendered within a <Text> component". Style truyền qua prop style dưới dạng object, không có className như web.

  4. Khi render danh sách, key dùng để làm gì? Nên chọn giá trị nào làm key?

    Xem đáp án mẫu
    React dùng key để nhận ra phần tử nào giữ nguyên, được thêm, bị xoá hay đổi chỗ giữa hai lần render, từ đó tái sử dụng đúng component cùng state của nó. Key cần ổn định và duy nhất trong cùng một list, tốt nhất là id từ dữ liệu. Dùng index làm key chỉ an toàn khi list không bao giờ thêm, xoá hay sắp xếp; nếu chèn item lên đầu, index bị dịch chuyển khiến state như nội dung TextInput hay checkbox bị gắn nhầm sang item khác. Cũng đừng dùng Math.random() làm key, vì mỗi lần render ra key mới nên React huỷ và tạo lại toàn bộ item.
    {todos.map((todo) => (
  <TodoRow key={todo.id} todo={todo} /> // id ổn định từ dữ liệu
))}

// Tránh khi list có thể thêm/xoá/sắp xếp:
// todos.map((todo, index) => <TodoRow key={index} todo={todo} />)

  5. Có những cách nào để render có điều kiện trong React? Vì sao {count && <Text>…</Text>} có thể làm app React Native bị lỗi?

    Xem đáp án mẫu
    Với nhánh lớn như loading hoặc lỗi, dùng if rồi return sớm; với hai nhánh trong JSX dùng toán tử ba ngôi cond ? <A /> : <B />; khi chỉ hiện hoặc ẩn thì dùng cond && <A />; muốn không render gì thì trả về null. Bẫy nằm ở chỗ && trả về chính vế trái khi vế trái falsy: nếu count là 0 thì biểu thức cho ra số 0, và React render nó như một đoạn text. Trên web bạn chỉ thấy một số 0 thừa, còn trong React Native đoạn text nằm ngoài <Text> gây lỗi "Text strings must be rendered within a <Text> component". Cách tránh là ép điều kiện về boolean (count > 0 &&) hoặc dùng toán tử ba ngôi.
    function CartBadge({ count }: { count: number }) {
  return (
    <View>
      {/* Sai: count = 0 thì render số 0 ngoài <Text> → lỗi */}
      {/* {count && <Text>{count} sản phẩm</Text>} */}
      {count > 0 && <Text>{count} sản phẩm</Text>}
      {count === 0 ? <Text>Giỏ hàng trống</Text> : null}
    </View>
  );
}

  6. Controlled TextInput là gì? Vì sao form đăng nhập thường được làm theo kiểu controlled?

    Xem đáp án mẫu
    Controlled nghĩa là nội dung ô nhập lấy từ state qua prop value, và mỗi lần người dùng gõ thì onChangeText cập nhật lại state; state trở thành nguồn dữ liệu duy nhất. Nhờ vậy dễ validate ngay khi gõ, format dữ liệu, reset form hoặc disable nút submit khi dữ liệu chưa hợp lệ. onChangeText nhận thẳng chuỗi mới, còn onChange nhận event và text nằm ở e.nativeEvent.text. Bẫy: truyền value mà không cập nhật state trong onChangeText thì ô nhập luôn bị ép về giá trị cũ, gõ không đổi được; nếu chỉ cần giá trị ban đầu thì dùng defaultValue (uncontrolled).
    function LoginForm({ onLogin }: { onLogin: (email: string) => void }) {
  const [email, setEmail] = useState('');
  const isValid = email.includes('@');
  return (
    <View>
      <TextInput
        value={email}
        onChangeText={setEmail} // nhận thẳng chuỗi mới
        placeholder="Email"
        autoCapitalize="none"
      />
      <Button title="Đăng nhập" disabled={!isValid} onPress={() => onLogin(email)} />
    </View>
  );
}

Component & Styling

Mọi rank →

  1. View, Text, Image trong React Native được hiển thị ra sao trên máy? Vì sao ảnh tải từ URL không hiện dù link đúng?

    Xem đáp án mẫu
    React Native không dùng WebView hay HTML: mỗi core component được ánh xạ sang view native, ví dụ View tương ứng UIView trên iOS và ViewGroup trên Android, Image tương ứng UIImageView và ImageView. Mọi chuỗi chữ phải nằm trong Text, View không tự hiển thị text. Với ảnh local dùng require('./logo.png'), RN biết kích thước ảnh từ lúc build; còn ảnh mạng source={{ uri }} thì không biết trước, nên phải tự đặt width/height, nếu không ảnh có kích thước 0 và không hiện gì. resizeMode (cover, contain…) quyết định ảnh được co giãn thế nào trong khung đó.
    <View style={{ padding: 16 }}>
  <Text>Xin chào</Text>
  {/* ảnh local: RN biết kích thước lúc build */}
  <Image source={require('./logo.png')} />
  {/* ảnh mạng: bắt buộc tự đặt width/height */}
  <Image
    source={{ uri: 'https://example.com/avatar.png' }}
    style={{ width: 64, height: 64 }}
    resizeMode="cover"
  />
</View>

  2. ScrollView và FlatList khác nhau thế nào? Khi nào dùng cái nào?

    Xem đáp án mẫu
    ScrollView render toàn bộ con ngay một lần, hợp với nội dung ngắn và số lượng biết trước như form hay trang chi tiết. FlatList là list ảo hoá (virtualized): chỉ render các item trong và gần vùng nhìn thấy, item ở xa bị gỡ ra, nên bộ nhớ và thời gian render ổn định khi list dài hoặc dữ liệu lấy từ API. FlatList nhận data và renderItem thay vì children, có sẵn ListHeaderComponent, ListEmptyComponent, ItemSeparatorComponent và kéo để làm mới qua refreshing/onRefresh. Bẫy: đặt FlatList trong ScrollView cùng chiều cuộn làm mất ảo hoá và RN sẽ cảnh báo; phần nội dung phía trên list nên đưa vào ListHeaderComponent.

  3. Style trong React Native khác CSS trên web ở điểm nào? Vì sao nên dùng StyleSheet.create thay vì viết style inline?

    Xem đáp án mẫu
    Style trong RN là object JavaScript, tên thuộc tính viết camelCase (backgroundColor), số không có đơn vị và tính bằng density-independent pixel (dp trên Android, point trên iOS). Không có selector hay cascade: style gắn trực tiếp vào từng component và không kế thừa từ View cha, ngoại lệ là Text lồng trong Text. StyleSheet.create gom style ra ngoài hàm render nên code gọn, đặt tên được theo ý nghĩa và được editor gợi ý, kiểm tra kiểu; style inline thì tạo object mới ở mỗi lần render. Prop style nhận cả mảng: phần tử sau ghi đè phần tử trước và giá trị falsy bị bỏ qua, rất tiện cho style có điều kiện.
    function Tag({ label, active }: { label: string; active?: boolean }) {
  return (
    <View style={[styles.tag, active && styles.active]}>
      <Text style={styles.label}>{label}</Text>
    </View>
  );
}

const styles = StyleSheet.create({
  tag: { paddingHorizontal: 12, paddingVertical: 6, borderRadius: 16, backgroundColor: '#eee' },
  active: { backgroundColor: '#1e88e5' }, // ghi đè màu nền của tag
  label: { fontSize: 14 },
});

  4. Flexbox trong React Native khác Flexbox của CSS trên web ở những điểm nào?

    Xem đáp án mẫu
    Trong RN mọi View đều là flex container, không cần khai báo display: 'flex', và layout dựa hoàn toàn vào Flexbox (thông qua engine Yoga). Khác biệt lớn nhất nằm ở giá trị mặc định: flexDirection là 'column' thay vì row, alignContent là flex-start thay vì stretch, flexShrink là 0 thay vì 1, và flex chỉ nhận một con số. flex: 1 nghĩa là chiếm phần không gian còn lại, chia theo tỉ lệ với các view anh em cũng có flex. justifyContent căn theo trục chính, alignItems căn theo trục phụ (mặc định stretch). Lỗi hay gặp là View gốc của màn hình thiếu flex: 1 nên co lại theo nội dung, hoặc tưởng các phần tử tự xếp ngang như trên web.

  5. Button, TouchableOpacity và Pressable khác nhau thế nào? Làm nút bấm theo thiết kế riêng thì dùng gì?

    Xem đáp án mẫu
    Button của core rất đơn giản: chỉ có title, color, disabled…, giao diện theo nền tảng và không nhận prop style, nên hiếm khi khớp thiết kế. TouchableOpacity tự mờ đi khi nhấn, là API cũ nhưng vẫn chạy tốt. Pressable là API mới được khuyến nghị: có onPress, onPressIn, onPressOut, onLongPress, cho style và children là hàm nhận { pressed } để tự đổi giao diện khi nhấn, có hitSlop để mở rộng vùng chạm và android_ripple cho hiệu ứng gợn sóng. Nút theo thiết kế riêng thường dựng bằng Pressable + Text; nhớ giữ vùng chạm đủ lớn (khoảng 44pt trên iOS, 48dp trên Android) và disabled khi đang gửi request để tránh bấm hai lần.

  6. Làm sao để nội dung không bị tai thỏ hay thanh trạng thái che? Khi cần style khác nhau cho iOS và Android thì viết thế nào?

    Xem đáp án mẫu
    Máy có tai thỏ, Dynamic Island hay thanh home indicator có những vùng mép màn hình mà nội dung không nên nằm vào, gọi là safe area. SafeAreaView có sẵn trong react-native chỉ có tác dụng trên iOS và đã bị đánh dấu deprecated ở các bản gần đây, nên thực tế dùng thư viện react-native-safe-area-context (SafeAreaProvider ở gốc app, rồi SafeAreaView hoặc useSafeAreaInsets) cho cả hai nền tảng; React Navigation cũng dựa vào thư viện này. Để xử lý khác biệt nền tảng, kiểm tra Platform.OS ('ios' hoặc 'android') hoặc dùng Platform.select để chọn giá trị. Ví dụ hay gặp là đổ bóng: iOS dùng các thuộc tính shadow*, Android dùng elevation.
    import { SafeAreaView } from 'react-native-safe-area-context';

function ProfileScreen() {
  return (
    <SafeAreaView style={{ flex: 1 }}>
      <View style={styles.card}>
        <Text>Đang chạy trên {Platform.OS === 'ios' ? 'iOS' : 'Android'}</Text>
      </View>
    </SafeAreaView>
  );
}

const styles = StyleSheet.create({
  card: { padding: 16, backgroundColor: 'white', ...Platform.select({ ios: { shadowOpacity: 0.2 }, android: { elevation: 3 } }) },
});

Navigation

Mọi rank →

  1. Trong stack navigator của React Navigation, navigate, push, goBack và popToTop khác nhau thế nào?

    Xem đáp án mẫu
    Stack navigator giữ một chồng màn hình: navigation.navigate('Detail') chuyển tới màn hình theo tên, còn goBack() bỏ màn hiện tại để về màn trước, giống nút back của Android hay cử chỉ vuốt back trên iOS. push('Detail', params) luôn đẩy thêm một màn mới, kể cả khi đang đứng ở chính Detail, hợp với luồng như sản phẩm liên quan (chi tiết → chi tiết); còn navigate tới đúng màn đang hiển thị thì không tạo màn mới mà chỉ cập nhật params. popToTop() quay thẳng về màn đầu tiên của stack, ví dụ sau khi đặt hàng xong. Screen nhận navigation qua props; component con nằm sâu hơn thì lấy bằng hook useNavigation().

  2. Truyền dữ liệu sang màn hình khác bằng params thế nào? Nên truyền cả object sản phẩm hay chỉ truyền id?

    Xem đáp án mẫu
    Params đặt ở tham số thứ hai: navigation.navigate('ProductDetail', { productId: 42 }), màn hình đích đọc qua route.params (prop route hoặc hook useRoute()), và có thể đổi params của màn hiện tại bằng navigation.setParams. Tài liệu React Navigation khuyên params chỉ chứa dữ liệu tối thiểu để dựng màn hình như id hay bộ lọc, chứ không phải cả object lấy từ API: object truyền qua có thể đã cũ so với dữ liệu thật, và khi màn hình được mở từ deep link thì cũng chỉ có id. Params cũng nên serializable; truyền function hay class instance sẽ bị cảnh báo vì làm hỏng việc lưu, khôi phục state điều hướng và deep link. Màn hình đích dùng id để tự lấy dữ liệu từ API hoặc store.

Networking & Storage

Mọi rank →

  1. Gọi API bằng fetch thế nào? Vì sao server trả 404 hoặc 500 mà code không nhảy vào catch?

    Xem đáp án mẫu
    fetch(url, options) trả về Promise của Response; với POST cần method, header Content-Type: application/json và body: JSON.stringify(data), còn body trả về đọc bằng await res.json() (cũng là Promise). Promise của fetch chỉ reject khi có lỗi mạng như mất kết nối hay không phân giải được tên miền; HTTP 404 hay 500 vẫn là một response hợp lệ nên Promise vẫn resolve. Vì vậy phải tự kiểm tra res.ok (status 200–299) hoặc res.status rồi ném lỗi để tầng trên xử lý. Lưu ý thêm: bản release trên Android và iOS mặc định chặn request http:// không mã hoá, nên API thật cần dùng HTTPS.
    async function createTodo(title: string) {
  const res = await fetch('https://api.example.com/todos', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ title }),
  });
  if (!res.ok) {
    throw new Error(`HTTP ${res.status}`); // 4xx/5xx không tự reject
  }
  return res.json();
}

  2. AsyncStorage là gì, lưu một object vào đó thế nào? Có nên lưu mọi thứ vào AsyncStorage không?

    Xem đáp án mẫu
    AsyncStorage là kho key–value bất đồng bộ, lưu bền trên máy, hợp với dữ liệu nhỏ như cài đặt, theme hay cờ đã xem onboarding. Bản nằm trong core React Native đã bị tách ra, nay dùng package cộng đồng @react-native-async-storage/async-storage. Cả key và value đều là string và mọi hàm đều trả về Promise, nên object phải JSON.stringify khi ghi, JSON.parse khi đọc, và getItem trả về null khi key chưa tồn tại. Dữ liệu không được mã hoá nên không dùng cho token hay mật khẩu, và nó cũng không thay được database khi dữ liệu lớn hoặc cần truy vấn.
    import AsyncStorage from '@react-native-async-storage/async-storage';

type Settings = { darkMode: boolean };

async function saveSettings(settings: Settings) {
  await AsyncStorage.setItem('settings', JSON.stringify(settings));
}

async function loadSettings(): Promise<Settings> {
  const raw = await AsyncStorage.getItem('settings'); // string | null
  return raw ? JSON.parse(raw) : { darkMode: false };
}

Expo, Build & Release

Mọi rank →

  1. Expo và React Native CLI khác nhau thế nào? Dự án mới bạn sẽ chọn cái nào?

    Xem đáp án mẫu
    React Native CLI tạo project "bare" với sẵn thư mục android/ và ios/: bạn tự cài Android Studio, Xcode, tự quản lý code native và cấu hình build, đổi lại kiểm soát được mọi thứ. Expo là framework xây trên React Native: có Expo SDK với nhiều module dựng sẵn (camera, notification, file…), chạy thử nhanh bằng app Expo Go, build và phát hành trên cloud bằng EAS. Quan niệm cũ "dùng Expo thì không thêm được native code" không còn đúng: với development build, bạn vẫn dùng được thư viện native bất kỳ hoặc tự viết module; chỉ riêng Expo Go là giới hạn ở các module có sẵn trong nó. Tài liệu chính thức của React Native hiện khuyên bắt đầu dự án mới với một framework như Expo; RN CLI hợp khi cần tích hợp sâu vào hệ thống build native sẵn có.

  2. Metro là gì? Fast Refresh hoạt động thế nào và khi nào bạn buộc phải build lại app?

    Xem đáp án mẫu
    Metro là bundler của React Native: dùng Babel biên dịch JSX/TypeScript, gộp các module và asset thành bundle, khi phát triển thì chạy dev server (mặc định cổng 8081) để app tải bundle về. Babel chỉ bỏ phần type chứ không kiểm tra type, nên muốn bắt lỗi TypeScript phải chạy tsc hoặc dựa vào editor. Với Fast Refresh, khi bạn lưu file chỉ export component thì chỉ component đó được cập nhật và state của useState được giữ; nếu file export cả thứ khác, module đó cùng các module import nó được chạy lại nên state có thể mất. Mọi thay đổi native như cài thư viện có native code, sửa AndroidManifest.xml, Info.plist hay Podfile đều phải build lại app; reload JS hay xoá cache Metro không giải quyết được.
