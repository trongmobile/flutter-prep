Dart

Mọi rank →

  1. var, dynamic và Object khác nhau thế nào khi khai báo biến?

    Xem đáp án mẫu
    var để compiler tự suy ra kiểu từ giá trị khởi tạo và kiểu đó cố định: var name = 'An'; thì name là String, gán số vào sẽ lỗi compile. dynamic tắt kiểm tra kiểu tĩnh, gọi method nào cũng compile được nhưng sai thì crash lúc runtime; Object nhận mọi giá trị non-null nhưng vẫn được kiểm tra kiểu, muốn dùng method riêng phải kiểm tra is hoặc cast. Pitfall: var x; không có giá trị khởi tạo thì x thành dynamic, nên hạn chế dynamic và chỉ dùng khi thật cần (ví dụ dữ liệu JSON chưa parse).
    var name = 'An';    // name có kiểu String
// name = 10;       // lỗi compile

dynamic d = 'An';
d = 10;             // OK, không kiểm tra kiểu
// d.foo();         // compile OK, crash lúc runtime

Object o = 'An';
if (o is String) print(o.length); // phải kiểm tra kiểu trước

  2. List, Set và Map khác nhau thế nào? Cho ví dụ khi nào dùng mỗi loại.

    Xem đáp án mẫu
    List là danh sách có thứ tự, cho phép phần tử trùng và truy cập theo index, ví dụ danh sách tin nhắn. Set không chứa phần tử trùng và kiểm tra contains nhanh, hợp để lưu tập id đã chọn hoặc loại bỏ trùng lặp. Map lưu cặp key–value để tra cứu theo key, ví dụ số lượng theo mã sản phẩm hay dữ liệu JSON sau khi decode; lưu ý map[key] trả về null khi không có key, và literal {} rỗng là Map chứ không phải Set.
    final tags = <String>['a', 'b', 'a'];   // List: giữ phần tử trùng
final ids = [1, 2, 2].toSet();          // Set: {1, 2}
final stock = <String, int>{'A01': 5};  // Map

print(stock['A01']); // 5
print(stock['X']);   // null vì không có key

  3. Named parameter và optional positional parameter khác nhau thế nào? Từ khóa required dùng khi nào?

    Xem đáp án mẫu
    Optional positional parameter đặt trong [] và truyền theo vị trí, còn named parameter đặt trong {} và truyền theo tên nên lời gọi dễ đọc, không phụ thuộc thứ tự. Named parameter mặc định là tùy chọn, vì vậy tham số kiểu non-nullable phải có giá trị mặc định hoặc đánh dấu required, còn kiểu nullable như String? thì mặc định là null. Flutter dùng named parameter gần như khắp nơi, ví dụ Text('Hi', maxLines: 1).
    void greet(String name, [String greeting = 'Xin chào']) {
  print('$greeting $name');
}

void createUser({required String email, int age = 18, String? nickname}) {}

greet('An');                  // Xin chào An
greet('An', 'Hello');         // Hello An
createUser(email: 'a@b.com'); // age = 18, nickname = null

  4. Nói hàm trong Dart là first-class object nghĩa là gì? Arrow function => dùng khi nào?

    Xem đáp án mẫu
    Hàm có thể gán vào biến, truyền làm tham số và trả về từ hàm khác như mọi giá trị khác; Flutter dùng điều này liên tục qua các callback như onPressed, onChanged. Cú pháp => là cách viết tắt cho hàm chỉ có một biểu thức: => expr tương đương { return expr; }. Lưu ý => chỉ chứa được một expression, cần nhiều câu lệnh thì phải dùng thân hàm {}.
    int square(int x) => x * x;

void applyAll(List<int> nums, int Function(int) f) {
  print(nums.map(f).toList());
}

applyAll([1, 2, 3], square);       // [1, 4, 9]
applyAll([1, 2, 3], (x) => x + 1); // [2, 3, 4]

  5. Named constructor là gì? Viết gọn constructor bằng this. và initializer list thế nào?

    Xem đáp án mẫu
    Dart không hỗ trợ overload constructor, nên muốn có nhiều cách khởi tạo thì dùng named constructor như Point.origin() hay User.guest(). Cú pháp this.x trong danh sách tham số tự gán giá trị vào field, còn initializer list (sau dấu :) dùng để gán các field final trước khi thân constructor chạy. Ví dụ quen thuộc trong Flutter là EdgeInsets.all(8) và EdgeInsets.symmetric(horizontal: 16).
    class Point {
  final double x;
  final double y;

  Point(this.x, this.y);
  Point.origin() : x = 0, y = 0;
  Point.fromList(List<double> v) : x = v[0], y = v[1];
}

final p = Point.origin();

  6. Toán tử ! (null assertion) làm gì? Vì sao nên hạn chế dùng nó?

    Xem đáp án mẫu
    ! khẳng định với compiler rằng một giá trị nullable chắc chắn không null, ép String? thành String. Nếu lúc chạy giá trị thực sự là null thì app crash với lỗi 'Null check operator used on a null value', một lỗi rất hay gặp ở người mới. Nên ưu tiên kiểm tra if (x != null) để Dart tự promote kiểu cho biến local, hoặc dùng ?? để có giá trị mặc định, chỉ dùng ! khi thật sự chắc chắn.
    String? name = getName();

print(name!.length);       // crash nếu name == null

if (name != null) {
  print(name.length);      // đã được promote thành String
}

print(name?.length ?? 0);  // an toàn

  7. extends, implements và with khác nhau thế nào?

    Xem đáp án mẫu
    extends là kế thừa: lớp con nhận lại code của lớp cha và mỗi class chỉ extends được một lớp. implements coi lớp kia như một interface (mỗi class đều ngầm định một interface), lớp mới phải tự override toàn bộ thành viên và có thể implement nhiều lớp cùng lúc. with dùng để trộn mixin, giúp tái sử dụng code giữa các lớp không cùng cây kế thừa, ví dụ with SingleTickerProviderStateMixin trong State khi làm animation.

  8. Collection if, collection for và spread operator ... giúp gì khi viết UI Flutter?

    Xem đáp án mẫu
    Chúng cho phép xây dựng List ngay trong literal: if để thêm phần tử có điều kiện, for để sinh nhiều phần tử, ... để trải các phần tử của một list khác vào. Nhờ vậy children của Column/Row viết gọn mà không cần biến tạm hay toán tử ba ngôi trả về widget rỗng. Khi list có thể null thì dùng ...? để bỏ qua nếu nó là null.
    Column(
  children: [
    const Text('Tiêu đề'),
    if (isLoggedIn) const Text('Xin chào!'),
    for (final item in items) Text(item),
    ...extraWidgets,
  ],
)

  9. Dấu gạch dưới _ ở đầu tên biến, hàm hay class có ý nghĩa gì trong Dart?

    Xem đáp án mẫu
    Dart không có từ khóa private; tên bắt đầu bằng _ là private ở mức library (thường là một file), không phải ở mức class. Nghĩa là hai class trong cùng một file vẫn truy cập được thành viên _ của nhau, còn file khác import vào thì không thấy. Đó là lý do class State của StatefulWidget thường đặt tên kiểu _CounterState: nó chỉ được dùng nội bộ trong file đó.

  10. File pubspec.yaml dùng để làm gì? Ký hiệu ^2.1.0 trong phần dependencies nghĩa là gì?

    Xem đáp án mẫu
    pubspec.yaml mô tả project: tên, version, ràng buộc SDK, các package phụ thuộc (dependencies, dev_dependencies) và khai báo assets, fonts. ^2.1.0 (caret syntax) nghĩa là chấp nhận từ 2.1.0 đến dưới 3.0.0, tức các bản không phá vỡ API theo semantic versioning; riêng bản 0.x như ^0.13.0 chỉ cho phép tới dưới 0.14.0. Sau khi sửa file thì chạy flutter pub get (hoặc dùng flutter pub add tên_package), phiên bản thực tế được khóa lại trong pubspec.lock.

  11. Sự khác biệt giữa final và const? Khi nào nên dùng cái nào?

    Xem đáp án mẫu
    const là compile-time constant (giá trị phải biết được lúc compile), final là runtime constant (gán một lần nhưng có thể tính lúc chạy). Ưu tiên const cho giá trị bất biến tuyệt đối để Flutter tái sử dụng widget, dùng final khi giá trị phụ thuộc runtime.

  12. Toán tử ??, ??= và ?. khác nhau thế nào?

    Xem đáp án mẫu
    ?? trả về giá trị bên phải nếu bên trái null; ??= chỉ gán giá trị mới nếu biến đang null; ?. gọi method/property an toàn, trả null thay vì crash nếu object là null.

Async & Isolate

Mọi rank →

  1. async/await hoạt động thế nào? await có làm đứng (block) UI không?

    Xem đáp án mẫu
    Hàm đánh dấu async luôn trả về Future; tại mỗi await, hàm tạm dừng và trả quyền điều khiển cho event loop, khi Future hoàn thành thì chạy tiếp từ chỗ đã dừng. Vì vậy chờ gọi API hay đọc file bằng await không làm đứng UI, các frame và sự kiện chạm vẫn được xử lý. Tuy nhiên async không biến code thành chạy song song: một vòng lặp tính toán nặng bên trong hàm async vẫn chạy trên main isolate và vẫn gây giật.
    Future<String> fetchName() async {
  await Future.delayed(const Duration(seconds: 1));
  return 'An';
}

Future<void> main() async {
  print('Bắt đầu');
  final name = await fetchName(); // tạm dừng, không block
  print('Tên: $name');
}

  2. Làm sao bắt lỗi khi gọi một hàm async, ví dụ gọi API thất bại?

    Xem đáp án mẫu
    Đặt lời gọi await bên trong try/catch giống code đồng bộ, và dùng finally cho việc luôn phải làm như tắt loading. Nếu không dùng await thì có thể nối .then(...).catchError(...), nhưng try/catch dễ đọc hơn. Lỗi thường gặp là gọi hàm async mà quên await, khi đó lỗi xảy ra sau khi đã ra khỏi khối try nên catch không bắt được.
    Future<void> loadUser() async {
  isLoading = true;
  try {
    final user = await api.getUser();
    print(user.name);
  } catch (e) {
    print('Lỗi: $e');
  } finally {
    isLoading = false;
  }
}

Widget & Lifecycle

Mọi rank →

  1. Câu 'Trong Flutter, mọi thứ đều là widget' nghĩa là gì?

    Xem đáp án mẫu
    Widget là bản mô tả (cấu hình) của một phần UI, và Flutter xây giao diện bằng cách lồng các widget vào nhau thành cây widget. Không chỉ nút bấm hay chữ, mà cả khoảng đệm (Padding), căn chỉnh (Center, Align), theme hay bắt gesture (GestureDetector) cũng là widget. Thay vì sửa trực tiếp một view như cách làm native truyền thống, ta mô tả UI theo state hiện tại, khi state đổi thì Flutter gọi lại build để tạo cấu hình mới.

  2. StatelessWidget và StatefulWidget khác nhau thế nào? Khi nào chọn loại nào?

    Xem đáp án mẫu
    StatelessWidget chỉ hiển thị dựa trên tham số nhận từ widget cha, bản thân nó không giữ dữ liệu thay đổi theo thời gian. StatefulWidget đi kèm một object State được giữ lại qua các lần rebuild, chứa dữ liệu có thể thay đổi và gọi setState để cập nhật UI. Chọn Stateless khi UI chỉ phụ thuộc input (ví dụ card hiển thị sản phẩm), chọn Stateful khi widget tự quản lý dữ liệu như bộ đếm, checkbox, form, hoặc cần initState/dispose để tạo và giải phóng controller.

  3. Vai trò của MaterialApp và Scaffold là gì?

    Xem đáp án mẫu
    MaterialApp thường là widget gốc của app: cấu hình theme, Navigator/routes, localization, title và cung cấp các thiết lập Material cho toàn bộ cây bên dưới. Scaffold là khung bố cục của một màn hình Material với các slot như appBar, body, floatingActionButton, drawer, bottomNavigationBar. Thường cả app chỉ có một MaterialApp còn mỗi màn hình có một Scaffold; lồng thêm MaterialApp trong từng màn hình là lỗi hay gặp, vì nó tạo Navigator và theme riêng tách khỏi phần còn lại của app.

  4. Làm sao lấy nội dung người dùng nhập trong TextField?

    Xem đáp án mẫu
    Cách phổ biến là tạo một TextEditingController trong State, gán vào controller của TextField và đọc controller.text khi cần, ví dụ lúc bấm nút Gửi. Controller phải được dispose() trong dispose() của State để tránh rò rỉ bộ nhớ. Nếu chỉ cần phản ứng theo từng ký tự thì dùng callback onChanged; với form nhiều trường cần validate thì dùng Form kết hợp TextFormField.
    class _LoginState extends State<Login> {
  final _emailCtrl = TextEditingController();

  @override
  void dispose() {
    _emailCtrl.dispose();
    super.dispose();
  }

  void _submit() => print(_emailCtrl.text);
  // trong build: TextField(controller: _emailCtrl)
}

  5. Flutter 3 có những loại button Material nào? Làm sao để disable một button?

    Xem đáp án mẫu
    Các button chính hiện nay là ElevatedButton, FilledButton, OutlinedButton, TextButton và IconButton; các widget cũ RaisedButton, FlatButton đã bị xóa khỏi framework. Để disable chỉ cần truyền onPressed: null, button tự chuyển sang style disabled. Muốn tùy biến màu hay bo góc thì truyền style: bằng ElevatedButton.styleFrom(...) hoặc cấu hình chung cho cả app qua theme.

  6. Cách hiển thị ảnh từ assets và từ internet trong Flutter?

    Xem đáp án mẫu
    Ảnh local đặt trong thư mục của project (ví dụ assets/images/), khai báo trong pubspec.yaml dưới mục flutter: assets: rồi dùng Image.asset('assets/images/logo.png'). Ảnh từ mạng dùng Image.network(url), nên thêm loadingBuilder/errorBuilder để xử lý lúc đang tải và lúc lỗi. Lỗi hay gặp là quên khai báo asset hoặc sai đường dẫn; khi khai báo cả thư mục (kết thúc bằng /) thì chỉ file nằm trực tiếp trong đó được đóng gói, thư mục con phải khai báo riêng.
    // pubspec.yaml:
// flutter:
//   assets:
//     - assets/images/

Image.asset('assets/images/logo.png', width: 120)

Image.network(
  'https://example.com/avatar.png',
  errorBuilder: (context, error, stack) => const Icon(Icons.broken_image),
)

  7. Làm sao cấu hình theme chung cho toàn app và lấy màu từ theme bên trong widget?

    Xem đáp án mẫu
    Truyền ThemeData vào theme: (và darkTheme: cho dark mode) của MaterialApp, thường tạo bảng màu bằng ColorScheme.fromSeed(seedColor: ...); từ Flutter 3.16, Material 3 đã là mặc định. Trong widget, đọc giá trị qua Theme.of(context), ví dụ Theme.of(context).colorScheme.primary hay Theme.of(context).textTheme.titleLarge. Dùng theme thay vì hard-code màu giúp đổi giao diện hoặc hỗ trợ dark mode chỉ ở một chỗ.
    MaterialApp(
  theme: ThemeData(
    colorScheme: ColorScheme.fromSeed(seedColor: Colors.teal),
  ),
  darkTheme: ThemeData(
    colorScheme: ColorScheme.fromSeed(
      seedColor: Colors.teal,
      brightness: Brightness.dark,
    ),
  ),
  home: const HomePage(),
)

  8. GestureDetector và InkWell khác nhau thế nào?

    Xem đáp án mẫu
    Cả hai đều bắt sự kiện chạm như onTap, onLongPress. InkWell là widget Material, vẽ hiệu ứng ripple khi chạm nên cần một widget Material phía trên (có sẵn trong Scaffold, Card...), và ripple sẽ bị che nếu child có màu nền đục. GestureDetector không có hiệu ứng hình ảnh nào nhưng hỗ trợ nhiều loại gesture hơn như kéo (drag), pan, scale.

Layout & Rendering

Mọi rank →

  1. mainAxisAlignment và crossAxisAlignment trong Row/Column khác nhau thế nào?

    Xem đáp án mẫu
    Main axis là trục mà widget xếp các con: với Row là chiều ngang, với Column là chiều dọc; cross axis là trục vuông góc với nó. mainAxisAlignment (như start, center, spaceBetween) phân bố các con dọc theo trục chính, còn crossAxisAlignment (như start, center, stretch) căn các con theo trục phụ. Pitfall: Column mặc định mainAxisSize: MainAxisSize.max nên chiếm hết chiều cao được phép, muốn nó chỉ cao vừa nội dung thì đặt MainAxisSize.min.

  2. Expanded và Flexible khác nhau thế nào?

    Xem đáp án mẫu
    Cả hai dùng trong Row/Column/Flex để chia phần không gian còn trống cho các con theo tỉ lệ flex. Expanded ép con phải lấp đầy phần được chia (FlexFit.tight), còn Flexible mặc định FlexFit.loose nên con được phép nhỏ hơn phần đó. Thực tế Expanded chính là Flexible với fit: FlexFit.tight; dùng Expanded khi muốn chia đều không gian, dùng Flexible khi muốn con co lại lúc thiếu chỗ nhưng không bị kéo giãn.

  3. Lỗi vạch vàng đen 'A RenderFlex overflowed by ... pixels' là gì và xử lý thế nào?

    Xem đáp án mẫu
    Lỗi xảy ra khi tổng kích thước các con của Row/Column vượt quá không gian mà widget cha cho phép, thường gặp với Text dài trong Row hoặc màn hình bị bàn phím thu nhỏ. Tùy trường hợp: bọc con bằng Expanded/Flexible để nó co theo chỗ trống, cho Text dùng overflow: TextOverflow.ellipsis, dùng Wrap để tự xuống dòng, hoặc bọc nội dung bằng SingleChildScrollView nếu cần cuộn. Dải vàng đen chỉ được vẽ ở debug mode; ở release không có cảnh báo nhưng layout vẫn hỏng, nên phải sửa tận gốc.

  4. Vì sao đặt ListView trực tiếp trong Column thường bị lỗi, và sửa thế nào?

    Xem đáp án mẫu
    Column cho các con không bị giới hạn chiều cao (unbounded), trong khi ListView là vùng cuộn nên muốn chiếm hết chiều cao được cho, dẫn tới lỗi 'Vertical viewport was given unbounded height'. Cách sửa phổ biến là bọc ListView bằng Expanded để nó nhận đúng phần chiều cao còn lại, hoặc đặt trong SizedBox có chiều cao cố định. shrinkWrap: true cũng hết lỗi nhưng list phải tính kích thước theo toàn bộ nội dung nên tốn chi phí hơn, chỉ hợp với list ngắn.

  5. Stack và Positioned dùng để làm gì? Cho ví dụ thực tế.

    Xem đáp án mẫu
    Stack xếp các con chồng lên nhau, con khai báo sau được vẽ đè lên con trước. Positioned (chỉ dùng làm con trực tiếp của Stack) đặt widget theo khoảng cách top, left, right, bottom so với cạnh của Stack, còn con không có Positioned được căn theo alignment của Stack. Ví dụ thường gặp: chấm online ở góc avatar, badge số lượng trên icon giỏ hàng, hay chữ đè lên ảnh banner.
    Stack(
  children: [
    const CircleAvatar(radius: 24, child: Icon(Icons.person)),
    const Positioned(
      right: 0,
      bottom: 0,
      child: Icon(Icons.circle, size: 12, color: Colors.green),
    ),
  ],
)

  6. Container, SizedBox và Padding khác nhau thế nào? Khi nào nên dùng cái nào?

    Xem đáp án mẫu
    Container là widget đa năng gộp padding, margin, màu nền, decoration (bo góc, viền, shadow), kích thước và căn chỉnh. SizedBox chỉ để đặt kích thước cố định hoặc tạo khoảng trống (ví dụ SizedBox(height: 16) giữa hai widget), còn Padding chỉ thêm khoảng đệm quanh con. Khi chỉ cần một chức năng thì nên dùng widget chuyên biệt vì gọn hơn và dùng được const; lưu ý Container không cho truyền đồng thời color và decoration, phải đặt màu bên trong BoxDecoration.

State Management

Mọi rank →

  1. setState làm gì? Nếu đổi giá trị biến mà không gọi setState thì chuyện gì xảy ra?

    Xem đáp án mẫu
    setState chạy callback để cập nhật dữ liệu rồi đánh dấu State cần rebuild, framework sẽ gọi lại build ở frame kế tiếp để vẽ UI mới. Nếu đổi biến mà không gọi setState, dữ liệu trong bộ nhớ đã đổi nhưng UI vẫn hiển thị giá trị cũ cho tới khi có lý do khác khiến widget rebuild. Callback của setState phải đồng bộ: hãy await lấy dữ liệu xong rồi mới gọi setState để gán kết quả, không truyền hàm async vào setState.
    int count = 0;

void _increment() {
  setState(() {
    count++; // UI sẽ hiển thị giá trị mới
  });
}

  2. Hot reload, hot restart và chạy lại app (full restart) khác nhau thế nào?

    Xem đáp án mẫu
    Hot reload nạp code Dart mới vào app đang chạy và rebuild cây widget nhưng giữ nguyên state, rất nhanh khi chỉnh UI. Hot restart chạy lại app từ main() nên mất toàn bộ state, nhưng không phải build lại phần native. Các thay đổi trong main(), initState() hay giá trị khởi tạo của biến global/static không được áp dụng khi hot reload, cần hot restart; còn sửa code native, thêm plugin có code native hoặc sửa cấu hình Android/iOS thì phải dừng app và chạy lại từ đầu.

Navigation

Mọi rank →

  1. Navigator.push và Navigator.pop hoạt động thế nào?

    Xem đáp án mẫu
    Navigator quản lý các màn hình (route) theo dạng stack: push đẩy một route mới lên đỉnh để hiển thị, pop gỡ route trên cùng để quay về màn hình trước. Cách dùng thường gặp là Navigator.push(context, MaterialPageRoute(builder: (_) => const DetailPage())) và Navigator.pop(context); nút back Android hay thao tác vuốt back trên iOS cũng dẫn tới pop. Lưu ý context phải nằm bên dưới MaterialApp (nơi tạo Navigator), nếu không sẽ gặp lỗi không tìm thấy Navigator.

  2. Làm sao truyền dữ liệu sang màn hình mới và nhận kết quả trả về khi quay lại?

    Xem đáp án mẫu
    Cách đơn giản nhất là truyền qua constructor của màn hình đích, ví dụ DetailPage(productId: 42). Để nhận kết quả, await lời gọi Navigator.push (nó trả về một Future), còn màn hình đích gọi Navigator.pop(context, value) để trả giá trị về. Nếu người dùng bấm back mà không chọn gì thì kết quả là null, nên phải xử lý trường hợp này.
    // Màn hình A
final color = await Navigator.push<String>(
  context,
  MaterialPageRoute(builder: (_) => const PickColorPage()),
);
if (color != null) print('Đã chọn $color');

// Trong PickColorPage
onPressed: () => Navigator.pop(context, 'red'),

  3. Sau khi đăng nhập thành công, chuyển sang Home thế nào để người dùng không bấm back quay lại màn Login được?

    Xem đáp án mẫu
    Dùng Navigator.pushReplacement để thay route Login hiện tại bằng Home, hoặc Navigator.pushAndRemoveUntil(..., (route) => false) để xóa toàn bộ stack cũ và chỉ còn Home. Nếu chỉ dùng push thì Login vẫn nằm bên dưới trong stack và nút back sẽ đưa người dùng về đó. Tương tự, khi đăng xuất cũng nên xóa stack để không quay lại được các màn hình cần đăng nhập.
    Navigator.pushAndRemoveUntil(
  context,
  MaterialPageRoute(builder: (_) => const HomePage()),
  (route) => false,
);

Networking & Storage

Mọi rank →

  1. Làm sao chuyển một chuỗi JSON thành object Dart?

    Xem đáp án mẫu
    Dùng jsonDecode trong dart:convert để chuyển chuỗi thành Map<String, dynamic> (hoặc List<dynamic> nếu JSON là mảng), rồi viết factory constructor fromJson để map từng key sang field có kiểu rõ ràng. Nhờ vậy phần còn lại của app làm việc với object type-safe thay vì map['name'] rải rác khắp nơi. Pitfall: số trong JSON có thể là int hoặc double, nên với giá tiền hay dùng (json['price'] as num).toDouble(); dự án lớn thường dùng json_serializable để sinh code.
    import 'dart:convert';

class User {
  final String name;
  final int age;
  User({required this.name, required this.age});

  factory User.fromJson(Map<String, dynamic> json) =>
      User(name: json['name'] as String, age: json['age'] as int);
}

final user = User.fromJson(jsonDecode('{"name":"An","age":20}'));

  2. Gọi một REST API đơn giản trong Flutter thế nào? Cần lưu ý gì?

    Xem đáp án mẫu
    Thêm package http (hoặc dio), gọi await http.get(Uri.parse(url)), kiểm tra statusCode rồi jsonDecode(response.body) và chuyển sang model. Cần bọc trong try/catch để xử lý mất mạng, timeout, và hiển thị trạng thái loading/lỗi trên UI. Trên Android, bản release phải khai báo quyền INTERNET trong AndroidManifest.xml của src/main; template chỉ thêm sẵn quyền này cho debug/profile nên hay gặp cảnh 'debug gọi được, release thì không'.
    import 'dart:convert';
import 'package:http/http.dart' as http;

Future<List<dynamic>> fetchPosts() async {
  final res = await http.get(
    Uri.parse('https://jsonplaceholder.typicode.com/posts'),
  );
  if (res.statusCode != 200) {
    throw Exception('Lỗi ${res.statusCode}');
  }
  return jsonDecode(res.body) as List<dynamic>;
}

Native & Platform

Mọi rank →

  1. Ở mức tổng quan, Flutter khác gì so với phát triển native (Kotlin/Swift) và React Native?

    Xem đáp án mẫu
    Flutter dùng một codebase Dart cho nhiều nền tảng và tự vẽ toàn bộ UI bằng engine riêng (Impeller/Skia) thay vì dùng component có sẵn của hệ điều hành, nên giao diện đồng nhất giữa Android và iOS. React Native viết bằng JavaScript/TypeScript và hiển thị bằng component native của từng nền tảng; còn native thuần phải viết riêng Kotlin cho Android và Swift cho iOS nhưng truy cập API nền tảng trực tiếp nhất. Trên mobile, bản release của Flutter được compile AOT ra mã máy nên hiệu năng tốt, và khi cần tính năng nền tảng chưa có package thì gọi code native qua platform channel.

Performance

Mọi rank →

  1. Flutter có những build mode nào (debug, profile, release)? Dùng mỗi mode khi nào?

    Xem đáp án mẫu
    Debug mode (trên mobile dùng JIT) hỗ trợ hot reload, bật assertion và công cụ debug, nên chạy chậm hơn và không phản ánh hiệu năng thật. Profile mode compile AOT gần giống release nhưng vẫn giữ khả năng đo hiệu năng bằng DevTools, dùng khi cần kiểm tra giật lag, và nên chạy trên máy thật vì emulator/simulator không phản ánh đúng hiệu năng. Release mode compile AOT, tối ưu tối đa, tắt assertion và công cụ debug, dùng để phát hành (flutter build apk, flutter build ipa) hoặc chạy thử bằng flutter run --release.
