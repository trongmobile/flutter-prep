App tải một gói nội dung .zip từ server rồi giải nén bằng đoạn code dưới. Nếu file zip bị kẻ xấu chế tác, rủi ro bảo mật chính của đoạn code là gì?

fun unzip(input: InputStream, targetDir: File) {
  ZipInputStream(input).use { zip ->
    var entry = zip.nextEntry
    while (entry != null) {
      val out = File(targetDir, entry.name)
      out.parentFile?.mkdirs()
      out.outputStream().use { zip.copyTo(it) }
      entry = zip.nextEntry
    }
  }
}
  1. AcopyTo đọc cả entry vào RAM nên zip lớn gây OutOfMemoryError và crash app
  2. Bentry.name chứa ../ làm file bị ghi ra ngoài targetDir, có thể đè lên file của app
  3. CZipInputStream giải nén được cả file đã mã hoá mà không cần mật khẩu, lộ nội dung
  4. Dmkdirs() cấp quyền ghi cho mọi app khác trên thư mục vừa tạo, làm lộ dữ liệu
Xem đáp án
Đáp án đúng: B
Đây là lỗ hổng Zip Path Traversal (Zip Slip): entry.name do người tạo file zip quyết định, nên tên như ../../databases/app.db làm File(targetDir, entry.name) trỏ ra ngoài targetDir và ghi đè database, shared preferences hay cả code được load động của chính app. Cách sửa là tính out.canonicalPath và từ chối entry nếu đường dẫn đó không bắt đầu bằng targetDir.canonicalPath + File.separator. copyTo đọc theo từng khối nên không nạp cả entry vào RAM (zip bomb là rủi ro về dung lượng đĩa, không phải ghi sai chỗ), ZipInputStream không giải mã gì cả, còn mkdirs() không đổi quyền truy cập của thư mục.
