export default và named export khác nhau thế nào? Vì sao import { Button } from './Button' đôi khi nhận về undefined?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Một file module có thể có nhiều named export nhưng chỉ có một export default. Named export được import bằng đúng tên trong ngoặc nhọn (import { formatPrice } from './utils', đổi tên bằng as), còn default export import không có ngoặc và đặt tên tuỳ ý (import Button from './Button'). Nhầm hai kiểu là lỗi kinh điển: import { Card } từ một file chỉ có default thì nhận về undefined, và khi render sẽ báo "Element type is invalid: expected a string... but got: undefined". Ngoài ra undefined còn xuất hiện khi hai file import vòng tròn lẫn nhau (circular import), hay gặp khi gom export qua file index.ts (barrel file). Quy ước thường thấy là cả team chọn một kiểu; nhiều nhóm ưu tiên named export vì tên cố định ở mọi nơi nên auto-import và đổi tên (refactor) của editor hoạt động tốt hơn.
// Button.tsx
export const Button = () => null;                // named export
export default function Card() { return null; }  // default export (chỉ một)

// App.tsx
import Card, { Button } from './Button';         // default không ngoặc, named có ngoặc
import { Button as AppButton } from './Button';  // đổi tên khi bị trùng

// SAI: Card là default export, import kiểu named sẽ ra undefined
// import { Card } from './Button';
