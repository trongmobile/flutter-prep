Vì sao nên dùng TypeScript trong React Native? Khai báo kiểu cho useState và dữ liệu API thế nào, và any khác unknown ra sao?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
TypeScript bắt lỗi sai kiểu, sai tên prop hay thiếu tham số ngay trong editor trước khi chạy app và cho gợi ý code tốt hơn; template của React Native hiện cũng mặc định dùng TS. Nó chỉ kiểm tra lúc phát triển, lúc chạy vẫn là JavaScript thuần. useState suy luận kiểu từ giá trị khởi tạo, nên khi khởi tạo bằng null hoặc mảng rỗng bạn phải chỉ rõ bằng generic, như useState<User | null>(null). Dữ liệu API chỉ là kiểu bạn "hứa" với compiler (as User), TS không kiểm tra response thật, nên nếu server không đáng tin hãy kiểm tra thêm bằng thư viện như Zod. any tắt hoàn toàn việc kiểm tra kiểu cho giá trị đó, dùng nhiều thì mất ý nghĩa của TS; unknown an toàn hơn: nhận mọi giá trị nhưng phải thu hẹp kiểu (typeof, instanceof) rồi mới dùng được, hợp cho lỗi trong catch hay JSON chưa rõ cấu trúc. Union literal như 'idle' | 'loading' | 'error' mô tả trạng thái chặt hơn nhiều so với string.
type User = { id: number; name: string };
type Status = 'idle' | 'loading' | 'error';       // union: chỉ nhận 3 giá trị này

const [user, setUser] = useState<User | null>(null); // cần generic vì khởi tạo là null
const [status, setStatus] = useState<Status>('idle');

async function load() {
  setStatus('loading');
  try {
    const res = await fetch('https://api.example.com/me');
    setUser((await res.json()) as User);          // chỉ "hứa" với TS, không kiểm tra lúc chạy
    setStatus('idle');
  } catch (e: unknown) {
    const message = e instanceof Error ? e.message : 'Lỗi không xác định';
    console.warn(message);
    setStatus('error');
  }
}

// user?.name có kiểu string | undefined, phải xử lý null trước khi dùng
