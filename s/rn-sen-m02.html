Một TurboModule có method đồng bộ đọc và giải mã file mất khoảng 300ms, được gọi trong onPress. Khi user bấm nút, điều gì xảy ra?

export interface Spec extends TurboModule {
  readEncryptedSync(path: string): string; // đồng bộ, ~300ms
}

const onPress = () => {
  const data = NativeVault.readEncryptedSync(filePath);
  setContent(data);
};
  1. AJS thread bị chặn khoảng 300ms, mọi xử lý JS kể cả touch và render đều phải chờ
  2. BJSI tự chuyển lời gọi đồng bộ sang thread nền nên JS thread không bị ảnh hưởng
  3. CUI thread bị chặn 300ms nên cả scroll native lẫn animation native driver cùng đứng
  4. DCodegen từ chối build vì method đồng bộ không được phép trả về kiểu string

Đáp án đúng: A
Method đồng bộ qua JSI chạy ngay trên JS thread của lời gọi, nên native chậm bao lâu thì JS đứng bấy lâu. UI thread không bị chặn (scroll native vẫn chạy) nhưng mọi thứ cần JS đều trễ; việc tốn thời gian nên khai báo trả Promise và chạy ở thread khác.
