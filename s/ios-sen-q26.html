Một service cũ dùng DispatchSemaphore.wait() bên trong hàm async để chờ callback, và app thỉnh thoảng treo hoàn toàn dù CPU rất rảnh. Thread pool của Swift Concurrency hoạt động thế nào, vì sao chặn thread trong code async nguy hiểm, và Task { } khác Task.detached ra sao?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Swift Concurrency chạy task trên cooperative thread pool có số thread xấp xỉ số core CPU, thay vì mỗi tác vụ một thread như GCD. Giả định nền tảng là task không chặn thread: khi await, task suspend và thread được trả lại cho task khác. Nếu trong hàm async bạn gọi API chặn như DispatchSemaphore.wait(), DispatchQueue.sync chờ kết quả từ task khác hay Thread.sleep, bạn chiếm mất một thread của pool; vài task như vậy đủ chiếm hết pool, và task cần chạy để signal semaphore không còn thread nào để chạy, thế là deadlock (treo mà CPU rảnh). Cách sửa là withCheckedContinuation để chờ callback mà không chặn thread, hoặc đưa việc blocking bắt buộc (I/O đồng bộ của thư viện C) sang một queue GCD riêng rồi await qua continuation. Để phát hiện, chạy với biến môi trường LIBDISPATCH_COOPERATIVE_POOL_STRICT=1 (thu pool còn một thread) để lộ các chỗ chặn. Về Task { } và Task.detached: Task { } là task không có cấu trúc nhưng thừa hưởng context nơi tạo (actor isolation, priority, task-local), nên Task { } trong hàm @MainActor mà làm việc CPU nặng vẫn chiếm main thread; Task.detached không thừa hưởng gì, chạy ngoài actor, nhưng cũng không bị huỷ theo task cha nên phải tự quản lý. Swift 6.2 thêm @concurrent để đánh dấu hàm async luôn chạy ngoài actor của caller, giúp rõ ràng hơn việc nặng chạy ở đâu.
// Sai: chiếm một thread của cooperative pool, vài task như vậy là pool cạn thread và treo
func loadConfig() async -> Config {
  let semaphore = DispatchSemaphore(value: 0)
  var result: Config!
  legacy.load { config in
    result = config
    semaphore.signal()
  }
  semaphore.wait() // chặn thread
  return result
}

// Đúng: suspend, thread được trả lại cho pool
func loadConfig() async -> Config {
  await withCheckedContinuation { continuation in
    legacy.load { continuation.resume(returning: $0) }
  }
}

@MainActor
func onTap() {
  Task { heavyCompute() }          // thừa hưởng MainActor: vẫn chiếm main thread
  Task.detached { heavyCompute() } // không thừa hưởng actor: chạy ngoài main, tự quản lý việc huỷ
}
