Test Jest kiểm tra hàm divide dưới đây cho kết quả gì khi chạy?

function divide(a: number, b: number) {
  if (b === 0) throw new Error('Không chia được cho 0');
  return a / b;
}

test('chia cho 0 phải ném lỗi', () => {
  expect(divide(1, 0)).toThrow();
});
  1. APass, vì divide ném đúng lỗi mà toThrow đang kiểm tra trong test này
  2. BFail, vì lỗi bị ném ngay lúc gọi divide(1, 0), trước khi expect kịp nhận gì
  3. CPass, vì Jest tự bắt mọi lỗi ném ra bên trong test và coi như hợp lệ
  4. DFail, vì toThrow chỉ dùng được với hàm bất đồng bộ trả về một Promise đã bị reject
Xem đáp án
Đáp án đúng: B
JavaScript tính đối số trước: divide(1, 0) chạy và ném lỗi trước khi expect kịp được gọi, lỗi thoát ra khỏi callback của test nên Jest đánh dấu test fail (lỗi ném ra không được coi là kết quả mong đợi). toThrow cần nhận một hàm để tự gọi và bắt lỗi: expect(() => divide(1, 0)).toThrow('Không chia được cho 0'). Với Promise thì dùng await expect(promise).rejects.toThrow().
