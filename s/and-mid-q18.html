Access token hết hạn, nhiều request song song cùng nhận 401. Bạn dùng OkHttp Interceptor hay Authenticator để refresh token, và làm sao để chỉ refresh một lần?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Interceptor hợp để gắn header Authorization vào mọi request; Authenticator được OkHttp gọi riêng khi nhận 401, trả về request mới để retry hoặc null để bỏ cuộc. Khi nhiều request cùng 401, đặt đoạn refresh trong vùng khoá (synchronized), và trong vùng khoá so sánh token mà request bị 401 đã gửi với token hiện tại: nếu đã khác nghĩa là thread khác vừa refresh xong, chỉ cần retry với token mới. Phải chặn vòng lặp vô hạn, ví dụ dựa vào response.priorResponse, và trả null khi refresh thất bại để app chuyển về màn đăng nhập. authenticate() chạy blocking trên thread của OkHttp nên gọi API refresh đồng bộ, qua một client không gắn chính Authenticator này.
class TokenAuthenticator(
  private val store: TokenStore,
  private val authApi: AuthApi, // client riêng, không gắn authenticator này
) : Authenticator {
  override fun authenticate(route: Route?, response: Response): Request? {
    if (response.priorResponse != null) return null // đã retry mà vẫn 401
    val newToken = synchronized(this) {
      val sent = response.request.header("Authorization")?.removePrefix("Bearer ")
      if (store.accessToken != sent) store.accessToken // thread khác đã refresh
      else authApi.refreshBlocking(store.refreshToken)?.also { store.accessToken = it }
    } ?: return null // refresh thất bại: đăng xuất
    return response.request.newBuilder().header("Authorization", "Bearer $newToken").build()
  }
}
