Thiết kế phía client cho tính năng chat trong app RN: gửi được khi mất mạng, hiển thị tin ngay, không trùng tin, cuộn mượt với lịch sử dài.

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Nguồn sự thật trên client là DB local (SQLite qua op-sqlite/expo-sqlite, hoặc WatermelonDB), UI chỉ subscribe DB. Gửi tin: tạo bản ghi với clientId (UUID) trạng thái pending, hiển thị ngay (optimistic), đưa vào outbox; worker gửi lần lượt khi có mạng, retry với exponential backoff, server dùng clientId làm idempotency key nên gửi lại không tạo bản trùng, ack trả về serverId và thời gian server để chuyển sang sent. Nhận tin: WebSocket khi app ở foreground, tự reconnect có backoff, và sau mỗi lần reconnect gọi API lấy tin sau cursor cuối để lấp khoảng trống; ở background thì dựa vào push notification vì OS không cho giữ socket lâu. Hiển thị: list đảo chiều (inverted), phân trang theo cursor khi cuộn lên, key dùng clientId để tin không bị remount khi nhận serverId. Thêm trạng thái failed cho user gửi lại, sắp xếp theo thời gian server, và giới hạn dữ liệu lưu local.
type Message = {
  clientId: string; // UUID tạo ở client, dùng làm idempotency key
  serverId?: string; // có sau khi server ack
  conversationId: string;
  body: string;
  status: 'pending' | 'sent' | 'failed';
  createdAt: number; // giờ server khi đã ack, giờ máy khi pending
};
