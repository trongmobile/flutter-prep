Bạn bọc API huỷ được của một SDK bằng withTaskCancellationHandler(operation:onCancel:). Điều nào đúng về closure onCancel?

  1. AChỉ chạy sau khi phần operation kết thúc hoặc ném lỗi, tương tự một khối defer
  2. BTự động dừng phần operation ngay lập tức, nên operation không cần kiểm tra Task.isCancelled hay gọi API huỷ
  3. CChạy ngay khi task bị cancel, cả lúc operation đang suspend; chạy song song nên phải thread-safe
  4. DLuôn chạy trên main actor, nên an toàn để sửa trực tiếp state của view model hoặc cập nhật UI
Xem đáp án
Đáp án đúng: C
Theo thiết kế (SE-0304), onCancel được gọi ngay lúc cancel() xảy ra (đồng bộ trong lời gọi cancel()), có thể song song với operation và trên thread khác với nó, nên phải thread-safe: thường chỉ làm việc như urlTask.cancel() hay continuation.resume(throwing: CancellationError()) trên state đã được bảo vệ. Nó không chờ operation xong, không tự dừng operation (cancellation vẫn là hợp tác, operation phải tự kiểm tra hoặc gọi API hỗ trợ huỷ), và không gắn với actor nào nên không được sửa state của main actor trực tiếp.
