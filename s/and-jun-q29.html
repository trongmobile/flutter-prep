Danh sách có checkbox: tick một dòng rồi cuộn xuống thì thấy dòng khác cũng bị tick, bấm vài dòng thì xử lý nhầm item. Lỗi nằm ở đâu trong adapter và sửa thế nào?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
RecyclerView tái sử dụng ViewHolder: khi dòng trượt khỏi màn hình, chính ViewHolder đó được dùng lại cho item khác và view vẫn giữ trạng thái cũ (checkbox đang tick) nếu onBindViewHolder không ghi đè. Vì vậy trạng thái phải nằm trong data model (ví dụ done của Task) và mỗi lần bind phải gán đầy đủ mọi thuộc tính, kể cả nhánh false. Lỗi thứ hai là bắt position trong listener tạo ở onBindViewHolder: sau khi chèn hoặc xoá item phía trên, onBindViewHolder không chạy lại cho các dòng chỉ bị dịch chỗ nên position đã cũ. Cách đúng là gắn listener một lần trong init của ViewHolder và đọc bindingAdapterPosition lúc bấm, bỏ qua RecyclerView.NO_POSITION. Với checkbox, dùng setOnClickListener thay vì setOnCheckedChangeListener để việc gán isChecked trong bind không kích hoạt lại callback.
class TaskAdapter(
    private val onToggle: (Task) -> Unit
) : ListAdapter<Task, TaskAdapter.VH>(TaskDiff) {

    inner class VH(private val binding: ItemTaskBinding) : RecyclerView.ViewHolder(binding.root) {
        init {
            // Gắn listener một lần, đọc vị trí tại thời điểm bấm
            binding.check.setOnClickListener {
                val pos = bindingAdapterPosition
                if (pos != RecyclerView.NO_POSITION) onToggle(getItem(pos))
            }
        }

        fun bind(task: Task) {
            binding.title.text = task.title
            binding.check.isChecked = task.done // luôn gán, kể cả khi false
        }
    }

    override fun onCreateViewHolder(parent: ViewGroup, viewType: Int) =
        VH(ItemTaskBinding.inflate(LayoutInflater.from(parent.context), parent, false))

    override fun onBindViewHolder(holder: VH, position: Int) = holder.bind(getItem(position))
}
