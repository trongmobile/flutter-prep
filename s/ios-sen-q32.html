App có 40 endpoint, mỗi chỗ tự dựng URLRequest và tự retry khác nhau; khi server quá tải (429/503) app còn làm nó tệ hơn bằng cách retry dồn dập. Bạn thiết kế tầng networking thế nào: cấu hình URLSession, chính sách retry và backoff, idempotency, đo lường?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Tôi gom về một APIClient mỏng: endpoint mô tả bằng type (path, method, body, kiểu response Decodable), một URLSession dùng chung với cấu hình rõ ràng (timeoutIntervalForRequest, waitsForConnectivity, httpMaximumConnectionsPerHost, cache policy), và pipeline các bước tách riêng: gắn auth (refresh khi 401 chỉ một lần), logging có che dữ liệu nhạy cảm, kiểm tra status code, decode. Retry là một chính sách chứ không phải thói quen: chỉ retry lỗi tạm thời (URLError kiểu timeout hay mất kết nối, 5xx, 429), không retry các 4xx khác; chỉ tự retry method idempotent (GET, PUT, DELETE), còn POST cần gửi kèm idempotency key để server chống trùng. Dùng exponential backoff có jitter (ngẫu nhiên hoá) để hàng nghìn client không retry đồng loạt, tôn trọng header Retry-After của 429 và 503, giới hạn số lần và tổng thời gian, và dừng ngay khi Task bị huỷ. Các request trùng (nhiều màn cùng xin một resource) nên gộp qua cache các task đang chạy. Tránh retry amplification: nếu SDK hay tầng khác cũng retry thì nhân hệ số số lần gọi lên server, nên chỉ một tầng được retry. Đo lường bằng URLSessionTaskMetrics (DNS, TLS, từng pha), gắn request id để đối chiếu log server. Về test, tầng trên phụ thuộc protocol APIClient, còn client được test bằng URLProtocol stub kèm đồng hồ giả để kiểm tra backoff mà không phải chờ thật.
struct RetryPolicy {
  var maxAttempts = 3
  var baseDelay: Duration = .milliseconds(500)

  func shouldRetry(status: Int, method: String) -> Bool {
    let idempotent = ["GET", "PUT", "DELETE"].contains(method)
    return idempotent && (status == 429 || (500...599).contains(status))
  }

  func delay(attempt: Int, retryAfter: Duration?) -> Duration {
    if let retryAfter { return retryAfter } // server bảo chờ bao lâu thì chờ đúng vậy
    let exponential = baseDelay * (1 << (attempt - 1))
    return exponential * Double.random(in: 0.5...1.5) // jitter: tránh mọi client retry cùng lúc
  }
}

func send<T: Decodable>(_ endpoint: Endpoint<T>) async throws -> T {
  var attempt = 1
  while true {
    // Task bị huỷ thì data(for:) và Task.sleep đều throw, vòng lặp tự thoát
    let (data, response) = try await session.data(for: endpoint.urlRequest())
    guard let http = response as? HTTPURLResponse else { throw APIError.invalidResponse }
    if (200..<300).contains(http.statusCode) { return try decoder.decode(T.self, from: data) }

    guard attempt < policy.maxAttempts, policy.shouldRetry(status: http.statusCode, method: endpoint.method) else {
      throw APIError.http(status: http.statusCode, body: data)
    }
    let retryAfter = http.value(forHTTPHeaderField: "Retry-After").flatMap(Double.init).map { Duration.seconds($0) }
    try await Task.sleep(for: policy.delay(attempt: attempt, retryAfter: retryAfter))
    attempt += 1
  }
}
