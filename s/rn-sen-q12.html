App RN có 30 dev, mỗi PR chạy CI hơn 40 phút mà bug vẫn lọt lên production. Bạn thiết kế lại test strategy thế nào?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Đầu tiên nhìn dữ liệu: bug lọt thuộc loại gì (logic, tích hợp API, UI trên một nền tảng, lỗi native sau khi nâng thư viện) và thời gian CI tốn ở đâu (build native, E2E, retry test flaky). Tầng nhanh và nhiều nhất là Jest + React Native Testing Library cho logic, hook và component theo hành vi; trong monorepo chỉ chạy test của package bị ảnh hưởng (Nx/Turborepo) và cache kết quả. Lỗi tích hợp API bắt bằng contract test hoặc kiểm tra schema chạy ở CI của cả backend. E2E (Maestro hoặc Detox) chỉ giữ cho vài luồng sống còn như đăng nhập, thanh toán, onboarding, chạy trên build release; binary native chỉ build lại khi fingerprint phần native đổi, PR chỉ sửa JS thì dùng lại binary đã cache. Test flaky phải được cách ly và có người chịu trách nhiệm, không retry vô hạn. Cuối cùng chấp nhận test không bắt được mọi thứ: staged rollout, feature flag và giám sát crash là lớp an toàn cuối cùng.
