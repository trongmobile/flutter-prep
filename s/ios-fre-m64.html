Trong viewDidLoad, bạn dùng Task { } để gọi hàm async rồi gán kết quả cho label ngay sau await như đoạn code sau. Cập nhật UI ở đây có cần thêm DispatchQueue.main.async không?

func fetchName() async -> String { "An" }

class ProfileViewController: UIViewController {
    @IBOutlet var nameLabel: UILabel!

    override func viewDidLoad() {
        super.viewDidLoad()
        Task {
            let name = await fetchName()
            nameLabel.text = name
        }
    }
}
  1. ACần: Task { } luôn chạy trên thread nền nên mọi dòng bên trong đều phải chuyển về main trước khi đổi UI
  2. BCần: mọi dòng sau await chạy trên thread mà hàm async vừa dùng, tức là một thread nền
  3. CKhông cần: UIViewController thuộc main actor, Task { } kế thừa nên sau await code vẫn chạy trên main
  4. DKhông cần: UIKit tự gom mọi thay đổi giao diện về main thread dù code được gọi từ thread nào, nên an toàn
Xem đáp án
Đáp án đúng: C
UIViewController được đánh dấu @MainActor, và closure của Task { } tạo trong ngữ cảnh đó kế thừa actor này, nên dù fetchName() chạy ở đâu thì dòng sau await vẫn quay lại main actor. Task.detached mới không kế thừa nên cần quay về main thủ công. UIKit không tự chuyển thread cho bạn: đổi UI từ thread nền vẫn là lỗi, chỉ là ở đây code đã chạy đúng trên main.
