findViewById có nhược điểm gì? ViewBinding giải quyết thế nào, và khác Kotlin synthetics ra sao?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
findViewById trả về View rồi phải ép kiểu, nên sai id hoặc sai kiểu chỉ lộ ra lúc chạy (null, ClassCastException), và phải gọi lại ở nhiều nơi. ViewBinding sinh sẵn một class cho mỗi file layout (activity_main.xml thành ActivityMainBinding) với property cho từng view có id, đúng kiểu sẵn, nên gõ sai id là lỗi compile. Property là non-null nếu view có ở mọi cấu hình layout, và nullable nếu chỉ có ở một số biến thể như layout-land. Bật bằng buildFeatures { viewBinding = true } trong Gradle. Kotlin synthetics (kotlinx.android.synthetic) đã bị deprecated và không còn được khuyên dùng, ViewBinding thay thế nó mà không cần plugin. Khác DataBinding ở chỗ ViewBinding không có biểu thức @{} trong XML nên nhẹ và build nhanh hơn. Trong Fragment cần gán _binding = null ở onDestroyView vì Fragment sống lâu hơn view của nó, nếu không sẽ leak view.
// build.gradle.kts (module app):
// android { buildFeatures { viewBinding = true } }

class MainActivity : AppCompatActivity() {
  private lateinit var binding: ActivityMainBinding

  override fun onCreate(savedInstanceState: Bundle?) {
    super.onCreate(savedInstanceState)
    binding = ActivityMainBinding.inflate(layoutInflater)
    setContentView(binding.root)

    binding.title.text = "Xin chào"          // đúng kiểu TextView, sai id là lỗi compile
    binding.btnSave.setOnClickListener { save() }
  }
}
