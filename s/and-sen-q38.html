Người dùng máy 3–4GB RAM phàn nàn app hay bị tải lại từ đầu khi quay lại sau khi dùng app khác, dù không thấy crash nào trên Crashlytics. Một dev đề xuất bật android:largeHeap="true" cho yên chuyện. Bạn nhìn vấn đề bộ nhớ ở quy mô lớn thế nào, và xử lý ra sao?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Android không cấp bộ nhớ cố định cho app: khi RAM thiếu, lmkd (low memory killer daemon) giết process theo độ ưu tiên, process nền (đã vào danh sách cached/LRU) bị giết trước và process càng nặng càng dễ bị chọn. Hậu quả không hiện thành crash mà là cold start thay cho warm start và mất state khi người dùng quay lại, nên 'ngân sách bộ nhớ' phải tính cả heap Java, native, bitmap, graphics (đo bằng PSS/RSS chứ không chỉ Java heap). Hệ thống báo áp lực bộ nhớ qua ComponentCallbacks2.onTrimMemory(level) (Application, Activity, Service...): TRIM_MEMORY_UI_HIDDEN là lúc UI không còn hiển thị, nên nhả cache hình và tài nguyên chỉ phục vụ UI; các mức khác thay đổi theo phiên bản Android nên đừng dựa vào việc nhận đủ mọi mức. largeHeap chỉ nâng trần heap chứ không sửa leak, mà process to hơn lại dễ bị lmkd giết hơn, nên chỉ dùng cho tính năng thật sự cần (chỉnh ảnh, tài liệu lớn). Cache phải co giãn theo máy: LruCache tính bằng byte từ Runtime.maxMemory(), Coil dùng maxSizePercent và tự thu nhỏ khi nhận onTrimMemory, máy isLowRamDevice thì giảm độ phân giải ảnh và tắt prefetch. Đo: Memory Profiler (heap dump, allocation tracking quanh luồng nặng, tìm bitmap trùng kích thước), adb shell dumpsys meminfo <package> để xem PSS theo loại; ở production ghi lại ApplicationExitInfo có REASON_LOW_MEMORY để biết tỉ lệ bị giết thật.
class ShopApp : Application() {
  override fun onTrimMemory(level: Int) {
    super.onTrimMemory(level)
    if (level >= ComponentCallbacks2.TRIM_MEMORY_UI_HIDDEN) {
      thumbnailCache.trimToSize(thumbnailCache.size() / 2) // UI ẩn: nhả bớt cache hình
    }
  }
}

// LruCache tính theo KB và theo bộ nhớ của từng máy, không dùng con số cố định
val maxKb = (Runtime.getRuntime().maxMemory() / 1024).toInt()
val thumbnailCache = object : LruCache<String, Bitmap>(maxKb / 8) {
  override fun sizeOf(key: String, value: Bitmap): Int = value.byteCount / 1024
}

// Coil 2: memory cache theo % bộ nhớ app, tự thu nhỏ khi hệ thống báo thiếu RAM
val imageLoader = ImageLoader.Builder(context)
  .memoryCache { MemoryCache.Builder(context).maxSizePercent(0.15).build() }
  .build()

// Production: đếm số lần process bị lmkd giết (API 30+)
val killedByLowMemory = context.getSystemService(ActivityManager::class.java)
  .getHistoricalProcessExitReasons(null, 0, 10)
  .count { it.reason == ApplicationExitInfo.REASON_LOW_MEMORY }
