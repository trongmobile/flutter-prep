Hai hàm cùng nhận int là getUser(int userId) và getOrder(int orderId) nên rất dễ truyền nhầm id. Extension type của Dart 3.3 giải quyết việc này thế nào, và nó khác một class bọc thông thường ở điểm nào?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Extension type tạo một kiểu mới ở thời điểm compile bọc quanh một 'representation type' mà không tốn thêm object lúc chạy: với extension type UserId(int value) {} và OrderId tương tự, hai kiểu này khác nhau nên truyền nhầm là lỗi compile, nhưng ở runtime chúng chỉ là int (zero-cost, không cấp phát thêm như một class bọc). Nó chỉ lộ ra các thành viên bạn khai báo (hoặc implements int để dùng lại API của int), cho phép thêm method, getter và constructor kiểm tra hợp lệ (OrderId.parse). Đánh đổi: vì không tồn tại lúc chạy nên x is UserId thực chất kiểm tra is int, ép kiểu từ dynamic hay JSON không được kiểm tra thêm, và runtimeType thấy int. Do đó không dùng extension type thay cho class khi cần đa hình (override theo kiểu thật) hoặc lưu thêm thông tin theo từng instance. Chúng hợp cho id, đơn vị (Meters, Seconds), và wrapper quanh JSON (extension type User(Map<String, Object?> json)) khi muốn API gọn mà không tốn chi phí cấp phát.
extension type const UserId(int value) {}

extension type const OrderId(int value) {
  OrderId.parse(String raw) : value = int.parse(raw);
  bool get isValid => value > 0;
}

Future<User> getUser(UserId id) async => api.fetchUser(id.value);
Future<Order> getOrder(OrderId id) async => api.fetchOrder(id.value);

void main() {
  const userId = UserId(7);
  // getOrder(userId); // lỗi compile: UserId không phải OrderId
  getUser(userId);

  final dynamic raw = 'abc';
  // UserId(raw as int) vẫn lỗi lúc chạy: extension type không kiểm tra thêm kiểu của dữ liệu động
}
