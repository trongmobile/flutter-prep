Module :core:model hoặc một SDK nội bộ được đóng gói thành AAR biên dịch sẵn cho các team khác dùng. Sau khi bạn thêm một property mới có giá trị mặc định vào data class public hoặc sửa thân một hàm public inline, nhiều app vẫn compile qua nhờ build cache nhưng lại crash NoSuchMethodError hoặc chạy logic cũ lúc runtime. Giải thích nguyên nhân ở mức bytecode JVM và cách bạn kiểm soát binary compatibility trong Kotlin?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Khi thay đổi một data class public bằng cách thêm property mới dù có giá trị mặc định, compiler Kotlin thay đổi signature của primary constructor, hàm copy(), cũng như các hàm synthetic $default kèm bitmask và DefaultConstructorMarker, đồng thời làm lệch thứ tự componentN() nếu chèn vào giữa. Những caller đã compile từ trước vẫn gọi đúng descriptor constructor hoặc copy$default cũ nên lúc runtime JVM không tìm thấy method và ném NoSuchMethodError. Tương tự, một hàm public inline được copy trực tiếp bytecode vào nơi gọi lúc biên dịch; nếu bản AAR mới sửa thân hàm inline hoặc đổi signature một hàm @PublishedApi internal mà nó gọi, các module chưa compile lại vẫn chạy bytecode cũ hoặc crash NoSuchMethodError hay IllegalAccessError khi liên kết với helper mới. Ngay cả với hàm thường, thêm tham số có giá trị mặc định cũng làm đổi signature hàm $default cho caller Kotlin, còn @JvmOverloads chỉ tạo thêm các overload cho caller Java chứ không giữ được binary compatibility cho code Kotlin gọi bằng default argument. Để giữ ABI ổn định trong SDK hoặc core module dùng chung, hãy tránh dùng data class ở public API (dùng class thường tự cài equals, hashCode, toString), hạn chế public inline và giữ phần @PublishedApi internal tối giản. Khi cần thêm tham số mới, hãy giữ nguyên overload cũ và đánh dấu @Deprecated(..., level = DeprecationLevel.HIDDEN) để caller cũ vẫn liên kết được ở runtime trong khi code mới không gọi nhầm. Cuối cùng, tích hợp JetBrains Binary Compatibility Validator vào CI để đối chiếu file .api mỗi khi mở PR, phát hiện sớm mọi phá vỡ ABI trước khi phát hành.
// Thay vì thêm tham số mặc định trực tiếp vào hàm cũ (làm đổi signature $default),
// giữ overload cũ ở mức binary bằng DeprecationLevel.HIDDEN:
@Deprecated("Use overload with timeout", level = DeprecationLevel.HIDDEN)
fun fetchConfig(url: String): Config = fetchConfig(url, timeoutMs = 5_000L)

fun fetchConfig(url: String, timeoutMs: Long = 5_000L): Config {
  return loadRemoteConfig(url, timeoutMs)
}
