Màn hình đang hiển thị danh sách LogEntry đọc từ viewContext (qua NSFetchedResultsController hoặc @FetchRequest). Sau khi chạy đoạn code dưới đây, trạng thái của SQLite và viewContext ra sao?

let fetch = NSFetchRequest<NSFetchRequestResult>(entityName: "LogEntry")
fetch.predicate = NSPredicate(format: "isSynced == YES")
let request = NSBatchDeleteRequest(fetchRequest: fetch)
try viewContext.execute(request)
  1. ACác object đang giữ trong viewContext cũng tự bị xoá theo ngay lập tức, vì lệnh chạy trực tiếp trên viewContext.
  2. BHàng trên SQLite đã bị xoá nhưng object trong viewContext vẫn còn; cần lấy resultTypeObjectIDs để mergeChanges.
  3. CDữ liệu trên SQLite chưa bị xoá cho tới khi gọi try viewContext.save(), nên UI và database hiện tại vẫn khớp nhau.
  4. DThao tác tự kích hoạt delete rule Cascade trong memory rồi tự phát NSManagedObjectContextObjectsDidChange tới UI.
Xem đáp án
Đáp án đúng: B
NSBatchDeleteRequest thực thi trực tiếp xuống persistent store (SQLite) mà không nạp object vào memory và không đi qua NSManagedObjectContext, nên không cần save() nhưng cũng không tự cập nhật các NSManagedObject đang nằm trong viewContext, không chạy delete rule trong memory và không tự phát notification thay đổi. Muốn UI và viewContext đồng bộ, cần đặt request.resultType = .resultTypeObjectIDs rồi gọi NSManagedObjectContext.mergeChanges(fromRemoteContextSave:into:).
