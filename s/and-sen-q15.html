Bạn xây design system bằng Compose cho 5 team cùng dùng thế nào để UI nhất quán mà không làm chậm tốc độ phát triển?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Tôi đặt design system trong module :core:designsystem gồm hai lớp. Lớp token: màu, typography, spacing, shape được cung cấp qua CompositionLocal trong một AppTheme (bọc hoặc thay MaterialTheme), dùng staticCompositionLocalOf cho giá trị hiếm khi đổi vì đọc rẻ, đổi thì recompose cả subtree. Lớp component: AppButton, AppTextField… với API hẹp, nhận tham số ngữ nghĩa như variant = Primary thay vì màu tuỳ ý, để thiết kế có thể thay đổi tập trung. Mỗi component có @Preview và screenshot test cho light/dark, font scale lớn, RTL để chặn regression. Về quy trình: designer và dev dùng chung tên token, có owner và cách đóng góp component mới, lint cấm hard-code màu hoặc dùng thẳng MaterialTheme.colorScheme trong feature module. Màn hình View cũ thì ánh xạ cùng bộ token sang theme XML trong thời gian chuyển đổi.
@Immutable
data class AppColors(val primary: Color, val surface: Color, val danger: Color)
val LocalAppColors = staticCompositionLocalOf<AppColors> { error("Chưa bọc trong AppTheme") }

@Composable
fun AppTheme(dark: Boolean = isSystemInDarkTheme(), content: @Composable () -> Unit) {
  val colors = if (dark) DarkColors else LightColors
  CompositionLocalProvider(LocalAppColors provides colors, content = content)
}

// Feature module đọc token qua AppTheme.colors.primary
object AppTheme {
  val colors: AppColors
    @Composable get() = LocalAppColors.current
}
