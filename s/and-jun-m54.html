Màn tìm kiếm dùng @RawQuery và dựng câu SQL như đoạn code dưới, trong đó input là chuỗi người dùng gõ. Rủi ro bảo mật của cách này và cách sửa đúng là gì?

@Dao
interface UserDao {
  @RawQuery
  fun search(query: SupportSQLiteQuery): List<User>
}

fun searchUsers(dao: UserDao, input: String): List<User> {
  val sql = "SELECT * FROM users WHERE name = '$input'"
  return dao.search(SimpleSQLiteQuery(sql))
}
  1. ARoom tự escape mọi chuỗi trong SimpleSQLiteQuery, nên cách viết này an toàn tuyệt đối
  2. BSQLite chỉ chạy một câu lệnh mỗi lần gọi nên không thể chèn thêm SQL như vậy
  3. CChỉ cần dùng @Query thay cho @RawQuery, câu SQL ghép chuỗi vẫn an toàn
  4. DChuỗi người dùng bị ghép thẳng vào SQL nên có thể chèn lệnh; phải truyền qua bindArgs
Xem đáp án
Đáp án đúng: D
SimpleSQLiteQuery(sql) chạy nguyên văn chuỗi bạn đưa, Room không escape giúp. Nếu input là ' OR '1'='1 thì điều kiện luôn đúng và trả về cả bảng (hoặc chèn ký tự phá cú pháp để dò cấu trúc), tức là SQL injection. SQLite không chạy nhiều lệnh một lúc không có nghĩa là an toàn, vì chèn vào chính câu lệnh đó đã đủ lộ dữ liệu. Cách đúng là SimpleSQLiteQuery("SELECT * FROM users WHERE name = ?", arrayOf(input)) để giá trị đi qua bind argument, hoặc dùng @Query("... WHERE name = :name") (Room luôn bind tham số) khi không cần SQL động.
