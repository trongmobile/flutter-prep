Từ FeedFragment, app điều hướng sang DetailFragment bằng replace + addToBackStack, rồi người dùng bấm Back. Sau đó ViewModel phát thêm một giá trị mới vào items. render được gọi mấy lần cho giá trị đó?

class FeedFragment : Fragment(R.layout.fragment_feed) {
  private val viewModel: FeedViewModel by viewModels()

  override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
    super.onViewCreated(view, savedInstanceState)
    viewModel.items.observe(this) { items -> // items là LiveData<List<Item>>
      render(items)
    }
  }
}
  1. AMột lần, vì LiveData bỏ qua observer mới nếu LifecycleOwner đã có observer
  2. BMột lần, vì observer tự bị gỡ ngay khi onDestroyView của Fragment chạy
  3. CHai lần, vì observer cũ gắn với Fragment vẫn còn, onViewCreated thêm cái nữa
  4. DKhông lần nào, vì Fragment mới quay lại chỉ ở CREATED nên không nhận được giá trị
Xem đáp án
Đáp án đúng: C
Khi Fragment nằm trong back stack, view bị huỷ nhưng chính Fragment vẫn sống nên observer đăng ký bằng this không bị gỡ. Mỗi lần onViewCreated chạy lại thêm một observer mới (mỗi lambda là một observer riêng), nên mỗi giá trị phát ra gọi render nhiều lần, kèm side effect trùng lặp nếu có. Dùng viewLifecycleOwner để observer tự gỡ cùng view.
