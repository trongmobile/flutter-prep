Crash-free rate của app rất cao, nhưng review trên App Store than 'app đơ vài giây' và Xcode Organizer báo hang rate tăng. Bạn tìm các hang xảy ra ở production mà không tái hiện được trên máy dev bằng cách nào?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Hang là khoảng thời gian main thread không xử lý nổi sự kiện của user; Apple coi từ khoảng 250ms trở lên là hang đáng kể (ngắn hơn là hitch), nên crash-free không phản ánh được chúng. Nguồn đầu tiên là Xcode Organizer: mục Hangs thống kê theo phiên bản và hiện các call stack hay gặp, tổng hợp ẩn danh từ những user bật chia sẻ dữ liệu phân tích. Tiếp theo tích hợp MetricKit: đăng ký MXMetricManagerSubscriber, nhận MXMetricPayload (số liệu tổng hợp mỗi ngày, gồm hang time, launch, memory) và từ iOS 14 có MXDiagnosticPayload chứa MXHangDiagnostic (cây call stack lúc hang), cùng MXCrashDiagnostic và MXCPUExceptionDiagnostic; app upload JSON lên backend để gộp theo stack. Khi phân loại call stack, tôi tìm: main thread chờ lock hay semaphore do thread khác giữ, I/O đồng bộ (đọc file lớn, Core Data trên viewContext, Keychain), decode ảnh hay JSON, DispatchQueue.sync, layout nặng. Với bản dev, dùng template Hangs và Time Profiler của Instruments, và bật Main Thread Checker cùng Thread Performance Checker trong scheme để cảnh báo gọi UI sai thread hay priority inversion. Có thể tự đo thêm bằng watchdog nhẹ: từ thread nền ping main queue mỗi vài trăm ms, quá ngưỡng thì chụp stack của main thread, nhưng phải cân nhắc chi phí và quyền riêng tư. Sửa xong thì theo dõi lại hang rate ở bản sau để xác nhận.
final class DiagnosticsCollector: NSObject, MXMetricManagerSubscriber {
  func start() { MXMetricManager.shared.add(self) }

  // Số liệu tổng hợp, thường mỗi 24 giờ
  func didReceive(_ payloads: [MXMetricPayload]) {
    upload(payloads.map { $0.jsonRepresentation() })
  }

  // Chẩn đoán chi tiết: hang, crash, CPU exception kèm call stack (iOS 14+)
  func didReceive(_ payloads: [MXDiagnosticPayload]) {
    for payload in payloads {
      for hang in payload.hangDiagnostics ?? [] {
        log("hang \(hang.hangDuration)") // call stack nằm trong hang.callStackTree
      }
    }
    upload(payloads.map { $0.jsonRepresentation() }) // backend gộp theo call stack
  }
}
