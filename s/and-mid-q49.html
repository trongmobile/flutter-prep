Màn danh sách đơn hàng collect dao.observeOrders() (trả Flow<List<OrderEntity>>): mỗi lần sync cập nhật một dòng không liên quan thì UI lại nháy, và sync 5.000 dòng bằng vòng for gọi insert từng dòng mất vài giây. Giải thích cách Room phát lại Flow, và cách dùng @Transaction, @Upsert, @Index, @RawQuery cho đúng.

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Flow của Room dựa trên InvalidationTracker, theo dõi theo bảng chứ không theo dòng hay điều kiện: bất kỳ ghi nào vào bảng mà query đọc, kể cả không đổi kết quả, đều chạy lại query và emit list mới, vì Room không so sánh kết quả. Vì vậy thêm distinctUntilChanged() (entity là data class nên equals đúng) để UI không nhận lại list y hệt, và dùng key trong LazyColumn để chỉ item đổi mới recompose. Insert hàng loạt: @Insert/@Upsert nhận List<T> chạy trong một transaction, nhanh hơn hẳn 5.000 lần gọi riêng (mỗi lần một transaction và một lần ghi đĩa). @Upsert (Room 2.5+) insert, trùng khoá chính thì update; khác OnConflictStrategy.REPLACE vốn là xoá rồi chèn lại, nên kích hoạt ON DELETE CASCADE của khoá ngoại và xoá luôn bản ghi con. @Transaction gom nhiều thao tác thành một khối atomic, ví dụ xoá cũ rồi chèn mới: observer chỉ được báo sau khi commit nên UI không thấy list rỗng giữa chừng. @Index đặt trên cột dùng trong WHERE, ORDER BY, JOIN và cột khoá ngoại để tránh quét toàn bảng; đánh đổi là insert/update chậm hơn và tốn dung lượng, kiểm chứng bằng EXPLAIN QUERY PLAN. @RawQuery cho câu SQL ghép động (bộ lọc tuỳ chọn): mất kiểm tra SQL lúc compile và phải khai báo observedEntities nếu muốn quan sát; nếu được thì dùng @Query với tham số nullable (:status IS NULL OR status = :status).
@Entity(
  tableName = "orders",
  indices = [Index("user_id"), Index("created_at")], // cột dùng để lọc và sắp xếp
)
data class OrderEntity(
  @PrimaryKey val id: String,
  @ColumnInfo(name = "user_id") val userId: String,
  val status: String,
  @ColumnInfo(name = "created_at") val createdAt: Long,
)

@Dao
abstract class OrderDao {
  @Query("SELECT * FROM orders ORDER BY created_at DESC")
  abstract fun observeOrders(): Flow<List<OrderEntity>>

  @Upsert // một transaction, khác REPLACE: không xoá rồi chèn lại
  abstract suspend fun upsertAll(orders: List<OrderEntity>)

  @Query("DELETE FROM orders")
  abstract suspend fun clear()

  @Insert
  abstract suspend fun insertAll(orders: List<OrderEntity>)

  @Transaction // observer chỉ thấy trạng thái sau commit
  open suspend fun replaceAll(orders: List<OrderEntity>) {
    clear()
    insertAll(orders)
  }
}

// Room phát lại mỗi khi bảng bị ghi, kể cả khi kết quả y hệt
val orders = dao.observeOrders().distinctUntilChanged()
