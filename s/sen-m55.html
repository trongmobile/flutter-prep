Monorepo có 40 package Flutter/Dart, mỗi PR chạy toàn bộ test trên CI mất 45 phút. Cách giảm thời gian mà vẫn bắt lỗi đáng tin cậy nhất là gì?

  1. AChỉ chạy test của package có file thay đổi trong PR, vì package khác không bị ảnh hưởng nếu code của chính nó không đổi gì
  2. BBỏ toàn bộ widget test khỏi CI của PR, chỉ giữ unit test vì chạy nhanh hơn; widget test sẽ chạy thủ công trước mỗi lần release
  3. CChỉ chạy test mỗi đêm trên nhánh chính thay vì mỗi PR, vì chạy test cho từng PR quá tốn tài nguyên và thời gian của cả nhóm
  4. DDùng đồ thị phụ thuộc: chỉ chạy test của package bị đổi cùng các package phụ thuộc vào chúng, song song và có cache; chạy đủ định kỳ ở nhánh chính
Xem đáp án
Đáp án đúng: D
Một package đổi có thể làm vỡ những package dùng nó, nên chỉ chạy test của package có file thay đổi sẽ bỏ sót đúng loại lỗi tích hợp mà monorepo cần bắt; phải mở rộng sang các package phụ thuộc (công cụ như Melos có thể lọc theo git diff và đồ thị phụ thuộc). Kết hợp chạy song song, cache pub/build và chạy toàn bộ định kỳ trên nhánh chính làm lưới an toàn. Bỏ widget test hay chuyển sang chạy hằng đêm chỉ dời lỗi tới muộn hơn: lỗi lọt vào nhánh chính rồi mới bị phát hiện, và khó xác định PR nào gây ra.
