API trả 401 khi access token hết hạn. Bạn viết interceptor Axios để tự gắn token và tự làm mới token, nhưng khi màn Home bắn 4 request cùng lúc thì app gọi /refresh tới 4 lần, và có lần người dùng bị đăng xuất oan. Nguyên nhân và cách xử lý?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Request interceptor gắn token vào header Authorization; response interceptor bắt 401, gọi refresh rồi gửi lại request gốc. Khi bốn request cùng nhận 401, mỗi cái tự gọi refresh nên có bốn lần refresh chạy song song; nếu server xoay vòng refresh token (mỗi token chỉ dùng một lần) thì các lần sau dùng token đã bị vô hiệu, bị từ chối và người dùng bị đăng xuất. Cách xử lý: giữ một Promise refresh dùng chung ở cấp module; request 401 đầu tiên tạo ra nó, các request còn lại await cùng Promise đó, rồi tất cả gửi lại với token mới và biến được xoá khi xong. Đánh dấu _retry để không lặp vô hạn nếu request gửi lại vẫn 401, và gọi /refresh bằng một instance Axios không gắn interceptor này. Refresh thất bại thì xoá token và đưa người dùng về màn đăng nhập.
let refreshing: Promise<string> | null = null;

api.interceptors.request.use((config) => {
  const token = tokenStore.access;
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});

api.interceptors.response.use(
  (res) => res,
  async (error: AxiosError) => {
    const original = error.config as (InternalAxiosRequestConfig & { _retry?: boolean }) | undefined;
    if (error.response?.status !== 401 || !original || original._retry) throw error;
    original._retry = true;

    if (!refreshing) {
      // authClient: instance riêng, không gắn interceptor này
      refreshing = refreshAccessToken(authClient).finally(() => {
        refreshing = null;
      });
    }
    const newToken = await refreshing; // mọi request 401 cùng chờ một lần refresh
    original.headers.Authorization = `Bearer ${newToken}`;
    return api(original);
  },
);
