Team dùng useTransition để giữ ô tìm kiếm mượt khi lọc list lớn nhưng không thấy khác biệt nào. App vẫn chạy kiến trúc cũ. Giải thích nào đúng?

const [isPending, startTransition] = useTransition();

const onChangeText = (text: string) => {
  setQuery(text); // cập nhật khẩn cấp cho ô input
  startTransition(() => setFilter(text)); // cập nhật có thể ngắt
};
  1. AstartTransition chỉ có tác dụng khi bọc một lời gọi fetch hoặc Promise
  2. BPhải bọc màn hình trong Suspense thì transition mới được kích hoạt
  3. CPhải đưa cả setQuery vào trong startTransition thì mới có hiệu quả
  4. DConcurrent rendering của React chỉ hoạt động khi app chạy New Architecture

Đáp án đúng: D
Concurrent features (transition, Suspense đầy đủ, automatic batching) cần renderer Fabric; ở kiến trúc cũ, cập nhật trong startTransition vẫn được render đồng bộ như thường. Đưa setQuery vào transition còn làm ô input phản hồi chậm hơn, ngược với mục đích.
