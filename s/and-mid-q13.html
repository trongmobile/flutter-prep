Trong Hilt, khi nào dùng @Binds, khi nào dùng @Provides? Bạn chọn scope (@Singleton, @ViewModelScoped…) cho một dependency dựa trên tiêu chí gì?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
@Binds dùng để nối interface với implementation mà Hilt đã biết cách tạo (có @Inject constructor): khai báo bằng hàm abstract trong module abstract, module không cần instance và Dagger sinh ít code hơn. @Provides dùng khi phải tự viết code tạo object: class của thư viện ngoài không sửa được constructor (Retrofit, OkHttpClient, Room database) hoặc cần builder và cấu hình. Về scope, không gắn scope nghĩa là mỗi lần inject tạo instance mới, và đó nên là mặc định. Chỉ gắn scope khi cần chia sẻ state hoặc object tốn kém để tạo: @Singleton cho OkHttpClient, database; @ViewModelScoped để dùng chung trong một ViewModel; @ActivityRetainedScoped để sống qua xoay màn hình. Scope phải khớp component mà module được @InstallIn, và lạm dụng scope sẽ giữ object lâu hơn cần thiết.
@Module
@InstallIn(SingletonComponent::class)
abstract class RepositoryModule {
  @Binds
  abstract fun bindUserRepo(impl: UserRepositoryImpl): UserRepository
}

@Module
@InstallIn(SingletonComponent::class)
object NetworkModule {
  @Provides
  @Singleton
  fun provideOkHttp(): OkHttpClient = OkHttpClient.Builder().build()
}
