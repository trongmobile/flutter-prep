Layout Inspector cho thấy ProductCard bị recompose mỗi khi cuộn LazyColumn dù dữ liệu của item không đổi, và báo cáo của Compose compiler đánh dấu tham số tags: List<String> là unstable. Giải thích cơ chế skipping, strong skipping mode, và các cách bạn giảm recomposition thừa?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Compose bỏ qua (skip) một composable khi mọi tham số đều không đổi so với lần recompose trước. Tham số kiểu stable được so sánh bằng equals; List<T> của Kotlin là interface không đảm bảo bất biến nên compiler coi là unstable. Từ Kotlin 2.0.20, strong skipping mode bật mặc định: composable có tham số unstable vẫn skip được nhưng so sánh bằng instance (===), và lambda capture giá trị unstable cũng được tự remember. Hệ quả là nếu list là instance mới mỗi lần, ví dụ .map { } ngay trong composable hoặc ViewModel emit list mới cho mỗi thay đổi nhỏ, thì mọi item vẫn recompose dù nội dung y hệt. Cách xử lý: map sang UI model một lần ở ViewModel và giữ nguyên instance khi dữ liệu không đổi; đánh dấu data class UI là @Immutable/@Stable và dùng ImmutableList của kotlinx.collections.immutable (hoặc khai báo stability configuration file cho class của thư viện); với giá trị đổi liên tục như scroll offset hay animation thì đọc state bên trong lambda của modifier (Modifier.offset { }, graphicsLayer { }) hoặc qua derivedStateOf, để chỉ phase layout/draw chạy lại chứ không recompose. Đo bằng Compose compiler reports/metrics và recomposition counts của Layout Inspector, rồi đo lại bằng Macrobenchmark; đừng tối ưu mù vì mỗi lần skip cũng tốn một phép so sánh.
@Immutable
data class ProductUi(val id: String, val name: String, val tags: ImmutableList<String>)

// ViewModel: map một lần khi dữ liệu đổi, không map lại trong composable
val products: StateFlow<ImmutableList<ProductUi>> = repo.products
  .map { list -> list.map { it.toUi() }.toImmutableList() }
  .stateIn(viewModelScope, SharingStarted.WhileSubscribed(5_000), persistentListOf())

// Đọc state trong lambda của modifier: chỉ phase layout chạy lại, không recompose
Box(Modifier.offset { IntOffset(0, -listState.firstVisibleItemScrollOffset / 2) })
