App xử lý lỗi không nhất quán: chỗ ném HttpException lên tận UI, chỗ catch (e: Exception) rồi hiện 'Có lỗi xảy ra', chỗ trả null. Bạn thiết kế mô hình lỗi xuyên các tầng data, domain và UI thế nào?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Lỗi cũng là một phần hợp đồng của API mỗi tầng. Tầng data bắt lỗi kỹ thuật (IOException, HttpException, SerializationException, SQLiteException) và ánh xạ sang lỗi có ý nghĩa với miền nghiệp vụ, ví dụ sealed interface AppError gồm NoConnection, Unauthorized, NotFound, Validation(fields), Server(code); tầng trên không biết Retrofit hay Room. Phân biệt lỗi dự kiến (hết mạng, nhập sai, 404) và lỗi lập trình: lỗi dự kiến được mô hình hoá thành giá trị trả về (sealed class kiểu Success/Failure) buộc caller phải xử lý; lỗi lập trình (IllegalStateException, bug) cứ để ném lên và ghi lại, không nuốt. Không dùng exception để điều khiển luồng, và nhớ ném lại CancellationException. Dùng sealed type riêng thay vì kotlin.Result, vì lỗi trong Result chỉ là Throwable không có kiểu. UI không hiển thị thông điệp kỹ thuật: ViewModel map AppError sang chuỗi resource có i18n kèm hành động phù hợp (thử lại với NoConnection, đăng nhập lại với Unauthorized). Với lỗi server có body nghiệp vụ, parse errorBody() thành Validation để hiện lỗi theo từng ô. Retry chỉ cho lỗi tạm thời và request idempotent. Xử lý 401 tập trung ở Authenticator thay vì rải ở từng màn, còn log gắn cause và request id nhưng không chứa dữ liệu nhạy cảm.
sealed interface AppError {
  data object NoConnection : AppError
  data object Unauthorized : AppError
  data class Validation(val fields: Map<String, String>) : AppError
  data class Server(val code: Int) : AppError
}

sealed interface Outcome<out T> {
  data class Success<T>(val value: T) : Outcome<T>
  data class Failure(val error: AppError) : Outcome<Nothing>
}

// Chỉ bắt lỗi dự kiến; lỗi lập trình không bị nuốt, cứ để ném lên và ghi lại
suspend fun <T> safeCall(block: suspend () -> T): Outcome<T> = try {
  Outcome.Success(block())
} catch (e: CancellationException) {
  throw e
} catch (e: IOException) {
  Outcome.Failure(AppError.NoConnection)
} catch (e: HttpException) {
  Outcome.Failure(
    when (e.code()) {
      401 -> AppError.Unauthorized
      422 -> AppError.Validation(parseFieldErrors(e))
      else -> AppError.Server(e.code())
    },
  )
}
