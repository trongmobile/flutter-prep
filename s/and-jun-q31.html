Dependency Injection khác gì việc tự tạo UserRepository() bên trong ViewModel? Với Hilt, cần những annotation tối thiểu nào để ViewModel nhận được repository, và thiếu annotation nào thì app crash?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
DI nghĩa là class nhận thứ nó cần (dependency) từ bên ngoài, thường qua constructor, thay vì tự khởi tạo bên trong. Nhờ vậy ViewModel chỉ biết interface nên test truyền fake vào được, và việc dựng cả chuỗi phụ thuộc (OkHttp, Retrofit, API, Repository) nằm tập trung một chỗ. Hilt sinh code lúc compile nên thiếu binding là lỗi build chứ không phải crash lúc chạy. Cấu hình tối thiểu: @HiltAndroidApp trên Application (khai báo trong Manifest), @AndroidEntryPoint trên Activity/Fragment, @HiltViewModel cùng @Inject constructor trên ViewModel rồi lấy bằng by viewModels(). Bẫy hay gặp: quên @HiltViewModel thì by viewModels() không dựng được ViewModel có tham số và crash Cannot create an instance of class; Fragment có @AndroidEntryPoint mà Activity chứa nó thiếu annotation cũng crash; @Inject một interface mà thiếu @Binds/@Provides thì build báo thiếu binding.
@HiltAndroidApp
class ShopApp : Application()

class UserRepositoryImpl @Inject constructor(
    private val api: UserApi
) : UserRepository

@Module
@InstallIn(SingletonComponent::class)
abstract class RepositoryModule {
    @Binds
    abstract fun bindUserRepository(impl: UserRepositoryImpl): UserRepository
}

@HiltViewModel
class ProfileViewModel @Inject constructor(
    private val repository: UserRepository
) : ViewModel()

@AndroidEntryPoint
class ProfileFragment : Fragment(R.layout.fragment_profile) {
    private val viewModel: ProfileViewModel by viewModels()
}
