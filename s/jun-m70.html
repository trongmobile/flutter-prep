Màn hình có ô tìm kiếm và danh sách 5.000 sản phẩm; mỗi lần build đều chạy lọc và sắp xếp lại như dưới đây. Khi gõ chữ hoặc chạy animation, UI bị giật. Hướng xử lý đúng là gì?

@override
Widget build(BuildContext context) {
  final visible = products
      .where((p) => p.name.contains(query))
      .toList()
    ..sort((a, b) => a.price.compareTo(b.price));

  return ListView.builder(
    itemCount: visible.length,
    itemBuilder: (context, i) => ProductTile(visible[i]),
  );
}
  1. AThêm const trước ListView.builder để Flutter bỏ qua việc chạy lại lọc và sắp xếp mỗi khi rebuild màn hình
  2. BTính danh sách đã lọc ngoài build (khi query hoặc dữ liệu đổi), build chỉ đọc kết quả đã lưu
  3. CBọc ListView.builder trong RepaintBoundary để việc lọc và sắp xếp chạy ở luồng raster
  4. DĐánh dấu build là async để việc lọc và sắp xếp chạy nền, không chặn luồng giao diện
Xem đáp án
Đáp án đúng: B
build có thể chạy rất nhiều lần (mỗi setState, mỗi frame của animation, đổi theme, bàn phím mở...) và chạy trên luồng UI nên phải nhẹ. Lọc và sắp xếp 5.000 phần tử mỗi lần là việc O(n log n) lặp lại vô ích khi dữ liệu không đổi; hãy tính một lần khi query hoặc products thay đổi (trong handler kèm setState, getter có cache, ViewModel hay provider dẫn xuất) rồi lưu kết quả. const không áp dụng cho dữ liệu động, build không thể là async (phải trả Widget ngay) và RepaintBoundary chỉ tách layer vẽ chứ không chuyển phép tính sang luồng nào. Nếu việc tính vẫn nặng sau khi cache, chuyển sang Isolate.run.
