Bạn triển khai SSL pinning cho app RN thế nào, và cần chuẩn bị gì để pinning không 'khoá' toàn bộ user khi server đổi chứng chỉ?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
fetch của RN đi qua stack mạng native (OkHttp trên Android, NSURLSession trên iOS), nên pinning phải làm ở tầng native: trên Android cấu hình CertificatePinner cho OkHttp client mà RN dùng thông qua OkHttpClientProvider.setOkHttpClientFactory, trên iOS dùng TrustKit hoặc một thư viện pinning dựng sẵn cho RN. Nhớ rằng SDK có HTTP client riêng hay WebView sẽ không được bao phủ. Pin public key (hash SPKI) thay vì cả certificate để gia hạn chứng chỉ với cùng key không làm vỡ pin, và luôn có ít nhất một pin dự phòng (key backup tạo sẵn hoặc key của CA trung gian). Cần quy trình xoay key phối hợp với backend/infra: phát hành app chứa pin mới trước, đợi đa số user cập nhật rồi mới đổi chứng chỉ; không trông vào OTA vì cấu hình pin nằm trong code native. Pinning chặn được MITM qua proxy trên máy bình thường, nhưng trên máy root/jailbreak có Frida thì vẫn bị bypass, nên chỉ là một lớp bảo vệ.
class PinnedClientFactory : OkHttpClientFactory {
  override fun createNewNetworkModuleClient(): OkHttpClient {
    val pinner = CertificatePinner.Builder()
      .add("api.shop.vn", "sha256/AAAA...=") // key đang dùng
      .add("api.shop.vn", "sha256/BBBB...=") // key dự phòng
      .build()
    return OkHttpClientProvider.createClientBuilder()
      .certificatePinner(pinner)
      .build()
  }
}
