Cache dùng chung bên dưới đọc bằng sync và ghi bằng async(flags: .barrier) trên global queue, nhưng thỉnh thoảng vẫn xảy ra data race. Nguyên nhân là gì?

final class Cache {
  private var storage: [String: Data] = [:]
  private let queue = DispatchQueue.global(qos: .userInitiated)

  func value(for key: String) -> Data? {
    queue.sync { storage[key] }
  }

  func set(_ data: Data, for key: String) {
    queue.async(flags: .barrier) { self.storage[key] = data }
  }
}
  1. Async không được dùng để đọc dữ liệu; mọi lần đọc phải chuyển sang async kèm completion, kẻo deadlock
  2. B.barrier chỉ dùng được với sync; khi ghi bằng async thì cờ này bị bỏ qua hoàn toàn
  3. C.barrier chỉ hiệu lực trên concurrent queue tự tạo; trên global queue nó chạy như async thường
  4. Dstorage là value type nên mỗi closure ghi vào một bản sao riêng thay vì biến dùng chung

Đáp án đúng: C
Theo tài liệu của GCD, cờ barrier chỉ có hiệu lực trên concurrent queue do bạn tự tạo, còn trên serial queue hoặc global concurrent queue thì thao tác ghi chạy như async thường nên có thể chạy đồng thời với các lần đọc. Cách đúng là DispatchQueue(label: "cache", attributes: .concurrent): các lần đọc sync chạy song song, còn ghi .barrier chờ các tác vụ đang chạy xong và chạy độc quyền. storage là property của self (reference type) nên closure không ghi vào bản sao.
