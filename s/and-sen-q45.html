Production có hai triệu chứng: một crash IllegalStateException mà stack trace trên Crashlytics chỉ toàn frame kotlinx.coroutines, không thấy dòng code nào của app; và thỉnh thoảng một màn hình 'quay mãi' mà không có lỗi nào được ghi. Bạn debug và quan sát coroutine ở production thế nào?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Stack trace của coroutine khó đọc vì sau mỗi lần suspend, code chạy tiếp trên thread khác nên stack chỉ còn phần từ điểm resume, mất thông tin 'ai đã gọi'. Stack trace recovery của kotlinx.coroutines ghép lại phần stack ở nơi gọi vào exception, nhưng chỉ bật ở debug mode: đặt System.setProperty("kotlinx.coroutines.debug", "on") thật sớm trong Application.onCreate (trước lần dùng coroutine đầu tiên) cho bản debug/internal; chế độ này còn thêm #id và CoroutineName vào tên thread nên Logcat và Perfetto dễ lần ra. Với bản release đừng trông chờ vào nó mà chủ động để lại dấu vết: đặt CoroutineName("sync-orders") cho các coroutine quan trọng, gắn CoroutineExceptionHandler ở scope gốc để đẩy tên coroutine, màn hình, phiên bản lên Crashlytics (log/custom key), và bọc lỗi ở ranh giới các layer bằng exception có ngữ cảnh. Với 'quay mãi', tìm các điểm có thể treo vô hạn: await() hay Channel.receive() không có phía gửi, CompletableDeferred không bao giờ complete, collect trên flow không kết thúc, runBlocking trên main. Đặt withTimeoutOrNull kèm log cho thao tác nên có hạn chót (withTimeout ném TimeoutCancellationException, vốn là một CancellationException nên handler không thấy), dùng invokeOnCompletion để log vòng đời job, và có công cụ debug in job.children của scope (tên và trạng thái Active/Completing) để thấy coroutine nào đang mắc kẹt hoặc bị leak vì scope sống quá lâu. DebugProbes.dumpCoroutines() (module kotlinx-coroutines-debug) hợp với test JVM hơn là thiết bị thật; khi tái hiện trên máy dev thì dùng tab Coroutines của debugger trong Android Studio để xem trạng thái và stack từng coroutine.
class ShopApp : Application() {
  override fun onCreate() {
    super.onCreate()
    // Chỉ bản debug/internal; đặt trước lần dùng coroutine đầu tiên vì cờ chỉ được đọc một lần
    if (BuildConfig.DEBUG) System.setProperty("kotlinx.coroutines.debug", "on")
  }
}

val handler = CoroutineExceptionHandler { ctx, e ->
  val name = ctx[CoroutineName]?.name ?: "unnamed"
  Firebase.crashlytics.log("coroutine $name lỗi ở màn ${currentScreen()}")
  Firebase.crashlytics.recordException(e)
}

appScope.launch(CoroutineName("sync-orders") + handler) {
  val done = withTimeoutOrNull(30_000) { repo.syncOrders() }
  if (done == null) Log.w("sync", "sync-orders quá 30s, có thể đang treo")
}

// Công cụ debug: coroutine nào đang sống? Job.toString() có tên và trạng thái
fun CoroutineScope.dumpChildren() =
  coroutineContext.job.children.forEach { Log.d("Coroutines", it.toString()) }
