Màn hình chi tiết sản phẩm gọi API theo id trong useEffect. Bạn tổ chức trạng thái loading/error thế nào, và cần xử lý gì khi người dùng thoát màn hình hoặc đổi id trước khi request xong?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
fetch chỉ reject khi không có response (mất mạng, lỗi DNS, request bị huỷ); 4xx/5xx vẫn resolve bình thường, nên phải tự kiểm tra res.ok hoặc res.status rồi ném lỗi. Màn hình nên có đủ ba trạng thái loading, error, data để UI không quay loading mãi khi API lỗi. Khi unmount hoặc id đổi, cleanup gọi abort() của AbortController để huỷ request cũ, tránh race condition: kết quả của id cũ về sau đè lên id mới. Request bị abort cũng reject, nên kiểm tra signal.aborted để không set state hay hiện lỗi cho trường hợp này.
useEffect(() => {
  const controller = new AbortController();
  setLoading(true);
  setError(null);
  fetch(`${API_URL}/products/${id}`, { signal: controller.signal })
    .then((res) => {
      if (!res.ok) throw new Error(`HTTP ${res.status}`); // 4xx/5xx không tự reject
      return res.json();
    })
    .then(setProduct)
    .catch((e) => !controller.signal.aborted && setError(e))
    .finally(() => !controller.signal.aborted && setLoading(false));
  return () => controller.abort(); // rời màn hình hoặc đổi id
}, [id]);
