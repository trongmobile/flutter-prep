Trên máy dùng chung, user A đăng xuất rồi user B đăng nhập, nhưng thông báo đẩy dành cho A vẫn hiện trên máy. App chỉ gửi token FCM lên server ngay lúc A đăng nhập lần đầu và không làm gì khi đăng xuất. Thiết kế nào đúng?

  1. AKhi đăng xuất gọi API gỡ token khỏi A, khi đăng nhập đăng ký token cho B; mỗi token chỉ thuộc một user
  2. BGiữ nguyên ánh xạ ở server và để app tự ẩn những thông báo có userId khác với user đang đăng nhập khi nhận được chúng
  3. CXoá AsyncStorage và Keychain khi đăng xuất, vì server sẽ tự phát hiện được là token đó không còn được máy sử dụng
  4. DGửi lại token mới lên server mỗi lần mở app, vì token FCM của thiết bị bị đổi sau mỗi lần app khởi động lại
Xem đáp án
Đáp án đúng: A
Thông báo được gửi theo token của thiết bị, còn ánh xạ token với user nằm ở server; nếu không gỡ ánh xạ khi đăng xuất thì server vẫn gửi nội dung của A tới máy. Lọc ở client không đáng tin: với tin kiểu notification khi app ở nền, hệ điều hành tự hiển thị mà không chạy code của app, và dữ liệu riêng tư của A cũng đã được gửi tới máy của B. Server không tự biết user đã đăng xuất (xoá dữ liệu cục bộ không báo gì cho server), nó chỉ phát hiện token hỏng khi gửi lỗi. Token FCM ổn định cho tới khi cài lại hoặc xoá dữ liệu app, nên giả định 'đổi mỗi lần khởi động' là sai. Luồng đúng: đăng xuất thì huỷ liên kết token (và có thể xoá token cục bộ để lấy token mới), đăng nhập thì đăng ký lại cho tài khoản mới.
