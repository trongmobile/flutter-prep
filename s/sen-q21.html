App 4 năm tuổi dùng Provider và ChangeNotifier rải rác (hàng trăm class), team muốn chuyển sang Riverpod (hoặc Bloc) mà không dừng làm tính năng. Bạn lập lộ trình migration tăng dần thế nào, và rủi ro lớn nhất là gì?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Bắt đầu bằng mục tiêu và số liệu: đau nhất là gì (rebuild thừa, khó test, phụ thuộc BuildContext ở mọi nơi, state lẫn lộn UI và dữ liệu), thay vì chuyển vì 'xu hướng'. Sau đó áp dụng kiểu strangler: hai hệ thống sống song song trong một thời gian dài, feature mới viết bằng stack mới, feature cũ chỉ chuyển khi đằng nào cũng phải sửa lớn. Điều kiện để chạy song song an toàn: tách logic nghiệp vụ và dữ liệu ra khỏi lớp state (repository hay service thuần Dart, không phụ thuộc Provider hay Riverpod) để hai stack dùng chung một nguồn dữ liệu; nếu mỗi bên tự giữ bản sao thì sinh ra hai nguồn sự thật, nguyên nhân bug khó nhất của các cuộc migration. Cầu nối: stack cũ chỉ còn là lớp mỏng (ChangeNotifier nghe repository rồi notifyListeners), stack mới đọc cùng repository (qua StreamProvider hay Provider); quy ước rõ 'dữ liệu này thuộc về ai'. Đặt quy tắc kiểm soát bằng lint hoặc review: cấm class mới dùng ChangeNotifier cũ, đếm số file còn dùng stack cũ như chỉ số tiến độ. Test hành vi (widget test theo màn hình) làm lưới an toàn thay vì test từng provider; chuyển từ lá lên (màn ít phụ thuộc trước) và mỗi PR nhỏ, merge được ngay. Rủi ro lớn nhất là bỏ dở giữa chừng (hai stack tồn tại vô thời hạn) và regression do khác biệt thời điểm cập nhật state; nên đặt mốc thời gian, người sở hữu và tiêu chí dừng nếu migration không đem lại lợi ích đo được.
// Nguồn dữ liệu thuần Dart, dùng chung cho cả hai stack: một nguồn sự thật
class CartRepository {
  final _controller = StreamController<Cart>.broadcast();
  Cart _cart = const Cart.empty();

  Cart get current => _cart;
  Stream<Cart> get changes => _controller.stream;

  void add(Item item) {
    _cart = _cart.add(item);
    _controller.add(_cart);
  }
}

// Stack cũ: ChangeNotifier chỉ còn là lớp mỏng nghe repository
class CartModel extends ChangeNotifier {
  CartModel(this._repo) {
    _sub = _repo.changes.listen((_) => notifyListeners());
  }
  final CartRepository _repo;
  late final StreamSubscription<Cart> _sub;

  Cart get cart => _repo.current;
  void add(Item item) => _repo.add(item);

  @override
  void dispose() {
    _sub.cancel();
    super.dispose();
  }
}

// Stack mới: Riverpod đọc cùng repository, màn hình mới dùng provider này
final cartProvider = StreamProvider<Cart>((ref) {
  final repo = ref.watch(cartRepositoryProvider);
  return repo.changes.startWith(repo.current); // startWith (rxdart): phát giá trị hiện tại trước, rồi các thay đổi
});
