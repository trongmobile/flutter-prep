Backend đổi API: field avatar lúc bị bỏ hẳn, lúc là null, còn full_name khác tên property fullName trong data class. Dùng Gson thì parse không báo lỗi nhưng app crash NullPointerException ở màn sau đó, còn dùng kotlinx.serialization thì crash MissingFieldException. Giải thích nguyên nhân và cách khai báo model cho đúng.

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Với kotlinx.serialization, property không có giá trị mặc định là bắt buộc: thiếu field thì MissingFieldException, gặp null cho property non-null thì SerializationException. Gson dùng reflection nên bỏ qua null-safety và giá trị mặc định của Kotlin: field thiếu hoặc null vẫn được gán null vào property non-null (String) mà không báo lỗi, đến khi dùng mới NPE ở chỗ khác, rất khó truy. Khai báo đúng: field có thể thiếu hoặc null thì để kiểu nullable kèm mặc định val avatar: String? = null; đổi tên bằng @SerialName("full_name") (kotlinx), @SerializedName (Gson) hay @Json(name = ...) (Moshi). Cấu hình Json { ignoreUnknownKeys = true } để backend thêm field mới không làm app crash (mặc định kotlinx ném lỗi khi gặp field lạ), và coerceInputValues = true để giá trị null hoặc enum lạ của property có mặc định rơi về mặc định. Nên tách DTO (khớp JSON) khỏi domain model rồi map bằng toDomain(), để chỗ xử lý dữ liệu server "bẩn" nằm ở một nơi, thay vì rải !! khắp app.
@Serializable
data class UserDto(
    val id: Long,
    @SerialName("full_name") val fullName: String,
    val avatar: String? = null, // thiếu field hoặc null đều an toàn
)

val json = Json {
    ignoreUnknownKeys = true // backend thêm field mới không làm app crash
    coerceInputValues = true // null/enum lạ ở property có mặc định -> dùng mặc định
}

val retrofit = Retrofit.Builder()
    .baseUrl(BASE_URL)
    .addConverterFactory(json.asConverterFactory("application/json".toMediaType()))
    .build()

fun UserDto.toDomain() = User(id = id, name = fullName, avatarUrl = avatar.orEmpty())
