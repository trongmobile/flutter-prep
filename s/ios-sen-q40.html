App có khoảng 30 màn hình và Resolver.shared.resolve() được gọi rải rác khắp ViewModel; viết test phải đăng ký lại nửa graph, còn lúc chạy thỉnh thoảng crash vì "service not registered". Bạn thiết kế DI cho app lớn thế nào: container runtime, composition root thủ công hay công cụ compile-time?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Tôi bắt đầu từ một nguyên tắc: chỉ một nơi (composition root ở app target) biết kiểu cụ thể, mọi tầng dưới chỉ nhận protocol qua init. Có ba hướng. Composition root thủ công: thiếu dependency là lỗi compile, không phụ thuộc thư viện, graph dễ đọc và dễ debug; đổi lại là boilerplate tăng theo số feature và phải truyền dependency xuyên nhiều tầng. Container runtime (Swinject, Resolver, Factory hay @Dependency của swift-dependencies): tiện cho scope và cho việc override trong test hay preview, nhưng nếu gọi container từ bên trong class thì nó thành service locator, dependency bị ẩn và lỗi thiếu đăng ký chỉ lộ lúc chạy. Công cụ sinh code compile-time (như Needle) cho an toàn lúc build ở quy mô lớn, đổi lại thêm bước codegen và độ phức tạp cho team. Tiêu chí chọn: số team và module, mức cần override trong test, và khả năng team duy trì công cụ. Với phần lớn app tôi chọn composition root thủ công kèm factory theo feature, và chia vòng đời rõ: scope app (API client, analytics), scope phiên đăng nhập (repository, database của user, tạo lại khi logout để không rò dữ liệu người cũ), scope màn hình (ViewModel). Nếu đã dùng container thì chỉ resolve ở root, và thêm một test dựng toàn bộ graph trên CI để bắt thiếu đăng ký trước khi lên production. Bẫy hay gặp: singleton giữ state qua logout, và hai service phụ thuộc vòng khi resolve lười gây đệ quy vô hạn.
// Composition root: chỉ chỗ này biết kiểu cụ thể
struct AppContainer {
  let api: APIClient            // scope app
  let analytics: Analytics

  func makeSession(for user: User) -> UserSession {   // scope phiên đăng nhập
    let store = OrderStore(userID: user.id)
    return UserSession(orders: OrdersRepository(api: api, store: store), analytics: analytics)
  }
}

@MainActor
struct UserSession {
  let orders: OrdersRepository
  let analytics: Analytics

  // Feature chỉ nhận dependency qua init, thiếu cái nào là lỗi compile
  func makeCheckout(orderID: Order.ID) -> some View {
    CheckoutView(model: CheckoutModel(orderID: orderID, repository: orders, analytics: analytics))
  }
}
// Logout: bỏ UserSession cũ, đăng nhập lại thì tạo UserSession mới từ AppContainer
