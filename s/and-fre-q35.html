Main thread (UI thread) là gì? Vì sao gọi mạng ngay trong onCreate thì crash, và vì sao cập nhật UI từ thread khác cũng báo lỗi?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Mỗi app Android có một main thread chạy onCreate, xử lý thao tác chạm và vẽ UI; với màn hình 60Hz mỗi khung hình chỉ có khoảng 16ms. Việc nặng như gọi mạng, đọc file hay truy vấn database trên main thread làm UI đứng hình, và nếu kẹt quá khoảng 5 giây thì app bị ANR. Vì vậy gọi mạng trên main thread bị hệ thống ném NetworkOnMainThreadException, và Room mặc định cũng từ chối truy vấn trên main thread. Chiều ngược lại, view không thread-safe nên chỉ main thread mới được đụng vào: cập nhật UI từ thread khác ném CalledFromWrongThreadException. Cách làm hiện nay là Coroutines: lifecycleScope.launch chạy trên main, chuyển việc nặng sang withContext(Dispatchers.IO) rồi quay lại main để cập nhật UI (hàm suspend của Retrofit đã tự chạy ngoài main thread). Cách cũ là AsyncTask (đã deprecated), Handler/Looper hoặc Thread kèm runOnUiThread.
class ProfileActivity : AppCompatActivity() {
  override fun onCreate(savedInstanceState: Bundle?) {
    super.onCreate(savedInstanceState)
    // val user = api.getUserBlocking() // SAI: NetworkOnMainThreadException

    lifecycleScope.launch {             // bắt đầu trên main thread
      val user = withContext(Dispatchers.IO) {
        repository.loadUser()           // việc nặng chạy nền
      }
      nameText.text = user.name         // về lại main, cập nhật UI an toàn
    }
  }
}
