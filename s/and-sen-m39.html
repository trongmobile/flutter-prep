Request gửi tin nhắn bị timeout nhưng thực ra server đã lưu; worker retry gửi lại. Cách nào tránh tin bị nhân đôi?

  1. ATắt retry trong WorkManager, timeout thì coi như gửi thất bại
  2. BTăng timeout của OkHttp đủ lớn để request không bao giờ bị timeout
  3. CMỗi tin có clientId (UUID) từ client, server bỏ qua bản trùng
  4. DTrước khi gửi lại, so nội dung với tin cuối cùng đang có trên server
Xem đáp án
Đáp án đúng: C
Với mạng không tin cậy, client không phân biệt được 'server chưa nhận' với 'server nhận rồi nhưng phản hồi bị mất', nên retry là bắt buộc và server phải idempotent theo một id do client sinh. So nội dung thì sai khi user cố ý gửi hai tin giống nhau.
