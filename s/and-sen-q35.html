Android vitals báo ANR rate của app vượt ngưỡng xấu, nhưng trên máy dev chưa bao giờ tái hiện được. Bạn điều tra thế nào, và những nguyên nhân ANR khó thấy là gì?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
ANR xảy ra khi main thread không phản hồi đúng hạn: input dispatch quá khoảng 5 giây, BroadcastReceiver chạy quá khoảng 10 giây (broadcast foreground; 60 giây với broadcast nền), hoặc service không xử lý xong hay không gọi startForeground kịp. Điều tra bắt đầu từ dữ liệu thật: Android vitals trong Play Console nhóm ANR theo stack trace và loại (input, broadcast, service), cho biết thiết bị và phiên bản OS tập trung; trong app, ApplicationExitInfo (API 30 trở lên) với REASON_ANR kèm traceInputStream là thread dump lúc xảy ra, có thể upload lên Crashlytics hay Sentry ở lần mở app sau; ở bản debug dùng StrictMode để bắt I/O trên main thread. Khi đọc thread dump, xem main thread đang BLOCKED chờ lock do thread nào giữ, đang đứng ở một binder call tới process khác, hay chờ Future.get(). Các nguyên nhân khó thấy: lock contention với thread nền giữ lock lâu; SharedPreferences.apply() tưởng bất đồng bộ nhưng khi Activity dừng hay service kết thúc, hệ thống chờ ghi xong (QueuedWork.waitToFinish), nên file lớn hoặc ghi dồn sẽ chặn main, nên chuyển sang DataStore; process bị khởi động chỉ để nhận broadcast mà Application.onCreate nặng, vì thời gian khởi tạo cũng tính vào hạn của receiver; binder call đồng bộ tới process chậm; deadlock; máy yếu thiếu CPU. Sửa nguyên nhân gốc rồi theo dõi ANR rate qua các bản.
// Chạy lúc app khởi động: gửi thread dump của lần ANR trước lên hệ thống báo lỗi (API 30+)
val am = context.getSystemService(ActivityManager::class.java)
am.getHistoricalProcessExitReasons(context.packageName, 0, 5)
  .filter { it.reason == ApplicationExitInfo.REASON_ANR }
  .forEach { info ->
    val trace = info.traceInputStream?.bufferedReader()?.use { it.readText() }
    reporter.log("ANR", info.description, trace)
  }

// Bản debug: phát hiện I/O trên main thread ngay khi dev chạy
if (BuildConfig.DEBUG) {
  StrictMode.setThreadPolicy(
    StrictMode.ThreadPolicy.Builder()
      .detectDiskReads().detectDiskWrites().detectNetwork()
      .penaltyLog()
      .build(),
  )
}
