compileSdk, targetSdk và minSdk khác nhau thế nào? Mỗi giá trị ảnh hưởng gì đến app?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
minSdk là API thấp nhất app hỗ trợ: máy cũ hơn không cài được và Google Play không hiện app cho máy đó; gọi API mới hơn minSdk thì phải kiểm tra Build.VERSION.SDK_INT hoặc dùng thư viện AndroidX tương thích, lint sẽ cảnh báo nếu quên. compileSdk là phiên bản SDK dùng để biên dịch, quyết định bạn gọi được những API nào; nó chỉ ảnh hưởng lúc build chứ không đổi hành vi lúc chạy, và thường đặt bản mới nhất. targetSdk khai báo bạn đã kiểm thử app với phiên bản Android nào: hệ thống bật các hành vi và hạn chế của phiên bản đó (ví dụ từ targetSdk 33 phải xin quyền POST_NOTIFICATIONS để hiện thông báo), nên nâng targetSdk phải test lại app. Google Play bắt app mới và bản cập nhật phải nhắm tới targetSdk đủ mới, mốc cụ thể đổi theo từng năm. Quan hệ thường gặp: minSdk ≤ targetSdk ≤ compileSdk.
android {
  namespace = "com.example.shop"
  compileSdk = 35            // biên dịch với SDK Android 15 (chỉ ảnh hưởng lúc build)

  defaultConfig {
    minSdk = 24              // chỉ máy Android 7.0 trở lên mới cài được
    targetSdk = 35           // đã kiểm thử với hành vi của Android 15
  }
}

// Gọi API mới hơn minSdk thì phải kiểm tra phiên bản
if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.TIRAMISU) {
  requestPermissions(arrayOf(Manifest.permission.POST_NOTIFICATIONS), 0)
}
