User tự viết == chỉ so sánh id, còn Hashable để compiler tự sinh phần còn lại. Đoạn code sau in ra gì?

struct User: Hashable {
  let id: Int
  var name: String

  static func == (lhs: User, rhs: User) -> Bool {
    lhs.id == rhs.id
  }
}

let a = User(id: 1, name: "An")
let b = User(id: 1, name: "Bình")
print(a == b, a.hashValue == b.hashValue)
  1. Atrue true, vì Hashable tự sinh chỉ dùng id khi == chỉ so sánh id, nên hai hàm luôn khớp nhau
  2. BLỗi compile vì đã tự viết == thì bắt buộc phải tự viết cả hash(into:) cho cùng một kiểu
  3. Ctrue false, vì hash tự sinh tính cả name nên hai giá trị bằng nhau có hash khác nhau
  4. Dfalse false, vì name khác nhau nên hai giá trị không thể được coi là bằng nhau

Đáp án đúng: C
== tự viết cho true, nhưng hash(into:) vẫn do compiler tự sinh từ mọi stored property nên hai giá trị có name khác nhau cho hash khác nhau. Điều này vi phạm hợp đồng của Hashable (hai giá trị bằng nhau phải có cùng hash) và làm Set, Dictionary hoạt động sai (chứa trùng, tra cứu trượt). Phải tự viết func hash(into hasher: inout Hasher) { hasher.combine(id) } cho khớp với ==; compiler không bắt buộc việc này nên không có lỗi compile.
