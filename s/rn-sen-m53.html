Chức năng tải video lên server đọc file 250MB bằng đoạn code dưới đây; trên máy thật app thường bị hệ điều hành kill vì hết RAM (OOM). Nguyên nhân chính và hướng xử lý đúng là gì?

const uploadVideo = async (fileUri: string, uploadUrl: string) => {
  const base64 = await FileSystem.readAsStringAsync(fileUri, {
    encoding: FileSystem.EncodingType.Base64,
  });
  await fetch(uploadUrl, {
    method: 'PUT',
    body: JSON.stringify({ data: base64 }),
  });
};
  1. AChuỗi base64 phình dung lượng hơn file gốc và nằm toàn bộ trong JS heap cùng bản sao khi JSON.stringify; nên stream upload trực tiếp từ fileUri ở native
  2. Bfetch giới hạn payload PUT tối đa 10MB trên Android và iOS; nên đổi method sang POST và nén chuỗi base64 bằng gzip trước khi gửi lên server
  3. CEncodingType.Base64 chạy đồng bộ trên UI thread làm watchdog của OS kill app; nên bọc readAsStringAsync trong InteractionManager.runAfterInteractions
  4. DHermes không giải phóng chuỗi sau khi fetch hoàn tất; nên gán base64 = '' sau await fetch và dùng ArrayBuffer thay cho JSON.stringify
Xem đáp án
Đáp án đúng: A
Đọc toàn bộ file 250MB thành chuỗi base64 làm dung lượng tăng thêm khoảng 33% trong JS heap, cộng thêm chuỗi mới tạo ra bởi JSON.stringify và bản sao chuyển xuống native khiến bộ nhớ vượt ngưỡng cho phép của OS và bị OOM kill. Cách đúng là dùng API upload stream trực tiếp từ đường dẫn file trên đĩa ở tầng native (như FileSystem.uploadAsync, react-native-blob-util hoặc chia chunk nhỏ) để không nạp cả file vào JS RAM. Các giả thiết về giới hạn 10MB của fetch, chạy đồng bộ trên UI thread hay lỗi GC của Hermes đều sai.
