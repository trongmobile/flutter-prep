DownloadManager tự tạo URLSession với delegate: self và lưu vào property. Sau khi màn hình dùng nó bị đóng và biến giữ manager về nil, deinit không chạy. Vì sao?

final class DownloadManager: NSObject, URLSessionDownloadDelegate {
  private var session: URLSession!

  override init() {
    super.init()
    session = URLSession(configuration: .default, delegate: self, delegateQueue: nil)
  }

  func urlSession(_ session: URLSession, downloadTask: URLSessionDownloadTask,
                  didFinishDownloadingTo location: URL) { /* lưu file */ }

  deinit { print("DownloadManager deinit") }
}
  1. ASession giữ strong delegate tới khi bị invalidate
  2. BdelegateQueue: nil khiến main queue giữ delegate mãi
  3. CSession chỉ thả delegate khi mọi task chạy xong
  4. DDelegate của URLSession là weak nên lỗi ở chỗ khác
Xem đáp án
Đáp án đúng: A
Khác với delegate của UIKit, URLSession giữ strong reference tới delegate cho tới khi session bị invalidate bằng finishTasksAndInvalidate() hoặc invalidateAndCancel(), kể cả khi không còn task nào chạy; manager lại giữ session nên thành vòng. Hãy invalidate khi xong việc, hoặc dùng một session sống suốt app thay vì tạo mới cho mỗi màn hình.
