Form chỉnh sửa hồ sơ dùng Notifier dưới đây. Khi currentUserProvider phát giá trị mới (ví dụ vừa đồng bộ từ server), nội dung người dùng đang gõ dở trong form bị reset về dữ liệu từ server. Nguyên nhân là gì?

class ProfileFormNotifier extends Notifier<ProfileDraft> {
  @override
  ProfileDraft build() {
    final user = ref.watch(currentUserProvider);
    return ProfileDraft(name: user.name, bio: user.bio);
  }

  void setName(String v) => state = state.copyWith(name: v);
}
  1. ANotifier bị huỷ rồi tạo instance mới mỗi lần widget rebuild nên state luôn quay về giá trị khởi tạo ban đầu
  2. BcopyWith tạo object mới nhưng Riverpod chỉ giữ tham chiếu tới object đầu tiên của state nên các chỉnh sửa tiếp theo không được lưu lại
  3. CThiếu autoDispose nên state không được giải phóng và bị ghi đè bởi lần khởi tạo trước đó của provider này
  4. Dbuild() chạy lại mỗi khi provider được watch đổi giá trị và gán state mới, nên phần chỉnh sửa trong draft bị ghi đè
Xem đáp án
Đáp án đúng: D
Trong Notifier, build() là một phép tính phản ứng: khi một provider được ref.watch bên trong nó thay đổi, build() chạy lại và giá trị trả về trở thành state mới, nên mọi chỉnh sửa lưu qua setName bị thay bằng dữ liệu server. Instance Notifier thì vẫn giữ nguyên (không bị tạo lại mỗi lần widget rebuild). Nếu dữ liệu chỉ cần làm giá trị khởi tạo, hãy đọc một lần bằng ref.read(currentUserProvider) trong build(), hoặc dùng ref.listen để tự quyết định khi nào nhập dữ liệu mới vào draft; cũng có thể tách draft khỏi phần dữ liệu đến từ server.
