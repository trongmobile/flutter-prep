Sau khi người dùng xoay màn hình vài lần, LeakCanary báo nhiều instance MapActivity đã destroy vẫn bị giữ trong bộ nhớ. Nguyên nhân là gì?

object LocationBus {
  private val listeners = mutableListOf<(Location) -> Unit>()
  fun register(l: (Location) -> Unit) { listeners += l }
  fun unregister(l: (Location) -> Unit) { listeners -= l }
}

class MapActivity : AppCompatActivity() {
  override fun onCreate(savedInstanceState: Bundle?) {
    super.onCreate(savedInstanceState)
    LocationBus.register { location -> moveMarker(location) }
  }

  private fun moveMarker(location: Location) { /* ... */ }
}
  1. AHàm moveMarker là private nên Activity bị tham chiếu và không được GC thu hồi
  2. BActivity bị giữ bởi savedInstanceState của lần tạo trước đó
  3. CLambda bắt this, còn singleton LocationBus giữ lambda mà không unregister
  4. DmutableListOf tạo list không thread-safe nên phần tử cũ không bị dọn
Xem đáp án
Đáp án đúng: C
moveMarker là method của Activity nên lambda ngầm bắt this; LocationBus là singleton sống suốt process nên chuỗi tham chiếu singleton → list → lambda → Activity khiến Activity cũ không được GC. Giữ lambda trong field rồi unregister ở callback đối xứng (onDestroy), hoặc đăng ký theo lifecycle để tự huỷ.
