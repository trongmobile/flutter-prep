Khi test ViewModel, bạn dùng fake repository hay mock bằng MockK? Mỗi cách có đánh đổi gì?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Mock bằng MockK cho phép stub nhanh từng lời gọi (coEvery { repo.getUser(any()) } returns user) và kiểm tra tương tác (coVerify), hợp khi cần xác nhận một side effect như có gửi analytics đúng tham số không, hoặc với dependency khó tạo. Nhược điểm là test gắn chặt với chi tiết implementation: đổi cách gọi repository là test vỡ dù hành vi không đổi, và stub có thể khác hành vi thật (vd. Flow không emit lại sau khi ghi) khiến test xanh giả. Fake là implementation đơn giản chạy thật trong bộ nhớ, như repository dùng MutableStateFlow, test theo state đầu ra nên bền khi refactor và dùng lại được ở nhiều test; dự án mẫu Now in Android chọn fake thay vì thư viện mock. Thực tế: fake cho repository và data source mình sở hữu, mock cho side effect cần verify hoặc class bên ngoài; với hàm suspend nhớ dùng coEvery/coVerify.
