Sau khi App Center/CodePush ngừng hoạt động, team chuyển sang EAS Update. runtimeVersion dùng để làm gì, và cấu hình sai thì hậu quả là gì?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
OTA chỉ thay được JS bundle và asset; phần native (thư viện native, quyền, cấu hình Info.plist/Manifest, bản thân React Native) chỉ đổi được qua binary mới trên store. runtimeVersion là hợp đồng giữa một bản build native và các update: app chỉ nhận update có cùng runtimeVersion. Nếu thêm thư viện native mà quên đổi runtime version, update dùng thư viện đó sẽ tới tay binary cũ chưa có code native tương ứng và crash ngay khi gọi tới. Vì vậy tôi chọn policy tự động: fingerprint tính hash từ cấu hình và code native, đổi native là đổi runtime; hoặc appVersion nếu team kỷ luật tăng version mỗi lần đổi native. Kết hợp channel theo môi trường (preview, production), rollout update theo phần trăm, theo dõi crash trước khi mở rộng, và luôn thử update trên build production thật chứ không chỉ trên dev client.
// app.config.ts
import type { ExpoConfig } from 'expo/config';

const config: ExpoConfig = {
  name: 'Shop',
  slug: 'shop',
  version: '2.4.0',
  runtimeVersion: { policy: 'fingerprint' }, // đổi native -> runtime mới
  updates: { url: 'https://u.expo.dev/<project-id>' },
};

export default config;
