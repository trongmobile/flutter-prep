Vì sao override equals() trong Java thì phải override cả hashCode()? Quên thì chuyện gì xảy ra?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Hợp đồng của Object quy định: hai object equals nhau thì bắt buộc có cùng hashCode. HashMap và HashSet dùng hashCode để chọn bucket trước rồi mới so equals; nếu chỉ override equals, hai object bằng nhau vẫn mang hashCode mặc định (thường khác nhau) nên rơi vào bucket khác. Hậu quả là set.contains(...) trả về false, HashSet chứa phần tử trùng, map.get(...) không tìm thấy dù key "bằng" nhau. Chiều ngược lại không bắt buộc: trùng hashCode chưa chắc equals. Nên tính hash từ đúng các field dùng trong equals (ví dụ Objects.hash(...)); trong Kotlin, data class đã tự sinh cả hai.
class Point {
  final int x, y;
  Point(int x, int y) { this.x = x; this.y = y; }

  @Override
  public boolean equals(Object o) {
    if (this == o) return true;
    if (!(o instanceof Point)) return false;
    Point p = (Point) o;
    return x == p.x && y == p.y;
  }

  @Override
  public int hashCode() { return Objects.hash(x, y); }
}
