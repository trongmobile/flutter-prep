Vì sao sealed class kết hợp switch expression là cách tốt để mô hình hóa UI state (loading/success/error)?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
sealed class cho compiler biết toàn bộ subtype (chúng phải nằm cùng library), nên switch trên nó được kiểm tra exhaustiveness: thiếu một case là lỗi compile chứ không phải bug runtime. Khi thêm state mới (ví dụ AuthExpired), mọi chỗ switch chưa xử lý sẽ báo lỗi ngay, rất an toàn khi refactor. Kết hợp object pattern như Authenticated(:final user) để destructure field gọn gàng. Lưu ý: đừng thêm case _ vì nó tắt luôn lợi ích này, và sealed class ngầm là abstract nên không khởi tạo trực tiếp được.
sealed class AuthState {}
class AuthLoading extends AuthState {}
class Authenticated extends AuthState {
  Authenticated(this.user);
  final String user;
}
class AuthFailure extends AuthState {}

String label(AuthState s) => switch (s) {
  AuthLoading() => 'Đang tải...',
  Authenticated(:final user) => 'Xin chào $user',
  AuthFailure() => 'Đăng nhập thất bại',
};
