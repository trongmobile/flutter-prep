Một dev viết flow { withContext(Dispatchers.IO) { emit(readConfig()) } } và app crash với IllegalStateException: Flow invariant is violated. Ngoài ra .catch { } đặt ở cuối pipeline không bắt được lỗi ném trong collect. Giải thích hai bất biến của Flow (context preservation, exception transparency) và cách viết đúng?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Flow có hai bất biến. Context preservation: phần thu thập luôn chạy trong context của collector, nên không được emit từ một context khác (như withContext bên trong flow { }), nếu không sẽ ném IllegalStateException. Muốn upstream chạy ở dispatcher khác thì dùng flowOn(Dispatchers.IO): nó chỉ ảnh hưởng các operator và block phía trên nó, tạo thêm một coroutine và channel (buffer) giữa upstream và downstream, còn collector vẫn ở context ban đầu; nếu cần phát từ nhiều coroutine hoặc callback thì dùng channelFlow/callbackFlow. Exception transparency: flow không được che lỗi của downstream. Operator catch chỉ bắt exception xảy ra ở upstream của nó; lỗi ném trong collect { } hoặc ở onEach đặt sau catch không bị bắt, muốn bắt thì đặt onEach trước catch hoặc bọc try/catch quanh collect. Vì vậy cũng đừng tự try/catch bọc lời gọi emit() trong flow { }, nó sẽ nuốt luôn lỗi của downstream. Với retry, retry/retryWhen chỉ chạy lại upstream; hãy lọc đúng loại lỗi (không retry 4xx hay CancellationException) và đặt delay backoff trong retryWhen. Nhớ rằng flow là cold: mỗi collector chạy lại block, và nên kiểm thử bằng Turbine.
// Sai: emit từ context khác -> IllegalStateException (Flow invariant is violated)
fun readConfig(): Flow<Config> = flow {
  withContext(Dispatchers.IO) { emit(parse(file.readText())) }
}

// Đúng: flowOn chỉ đổi context của phần upstream
fun readConfig(): Flow<Config> = flow { emit(parse(file.readText())) }.flowOn(Dispatchers.IO)

repo.observe()
  .map { it.toUi() }
  .onEach { analytics.track(it) } // nằm trước catch nên lỗi ở đây vẫn bị catch bên dưới bắt
  .retryWhen { cause, attempt ->
    val retry = cause is IOException && attempt < 3
    if (retry) delay(1_000L shl attempt.toInt()) // backoff tăng dần
    retry
  }
  .catch { emit(UiState.Error(it)) } // chỉ bắt lỗi phía trên nó
  .collect { render(it) } // lỗi ném ở đây KHÔNG bị catch phía trên bắt
