Build debug của module :data tốn rất nhiều thời gian ở các task kaptGenerateStubs... và kapt...Kotlin; Hilt, Room và Moshi codegen đều đang chạy qua kapt. Bạn chuyển sang KSP thế nào, vì sao KSP nhanh hơn, và chứng minh được mức cải thiện ra sao?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
kapt không đọc Kotlin trực tiếp: nó sinh Java stub cho toàn bộ class Kotlin của module (kaptGenerateStubs), rồi chạy các annotation processor Java (APT) qua javac trên stub đó, nên tốn thêm một bước sinh stub, một vòng javac và thường làm incremental build kém hiệu quả. KSP cho processor đọc thẳng symbol Kotlin (không cần stub), hỗ trợ xử lý incremental, và tài liệu của KSP ghi nhận nhanh hơn kapt rõ rệt (có thể tới khoảng 2 lần); kapt hiện ở chế độ bảo trì, thư viện mới chỉ hỗ trợ KSP. Cách migrate: thêm plugin com.google.devtools.ksp đúng phiên bản tương thích với Kotlin đang dùng, nâng Hilt/Dagger, Room, Moshi... lên bản có hỗ trợ KSP, đổi từng kapt(...) thành ksp(...) (cấu hình theo variant là kspDebug, kspTest...), và gỡ kotlin-kapt khi module hết dùng. Rủi ro: có thư viện chưa có KSP processor (Data Binding vẫn cần kapt) nên hai cái phải sống chung một thời gian; thư mục code sinh đổi sang build/generated/ksp, script nào đọc đường dẫn cũ sẽ hỏng; tham số processor chuyển từ kapt { arguments { } } sang ksp { arg(...) }; code và thông báo lỗi sinh ra có thể khác nhỏ, nên chạy đủ test và dựng thử bản release. Đo: Build Analyzer hoặc Build Scan xem thời gian task kapt/ksp trước và sau, rồi benchmark clean build và incremental build (sửa một file) bằng gradle-profiler với nhiều lần chạy, tắt build cache khi so sánh để không bị nhiễu.
plugins {
  alias(libs.plugins.android.library)
  alias(libs.plugins.kotlin.android)
  alias(libs.plugins.ksp)    // thay cho kotlin-kapt
  alias(libs.plugins.hilt)
}

dependencies {
  implementation(libs.hilt.android)
  ksp(libs.hilt.compiler)    // trước đây: kapt(libs.hilt.compiler)
  implementation(libs.room.runtime)
  ksp(libs.room.compiler)
  ksp(libs.moshi.kotlin.codegen)
}

ksp { arg("room.schemaLocation", "$projectDir/schemas") }

// Đo: ./gradlew :data:assembleDebug --scan  (hoặc gradle-profiler với kịch bản sửa một file Kotlin)
