Màn danh sách bài viết gọi API mỗi lần mở dù dữ liệu hiếm khi đổi, tốn data và chậm trên mạng yếu. Backend có thể trả ETag và Cache-Control. OkHttp Cache hoạt động thế nào, và khi nào dùng cache HTTP thay vì tự cache bằng Room?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Gắn Cache(directory, maxSize) vào OkHttpClient, OkHttp sẽ làm theo header HTTP. Cache-Control: max-age=60 cho phép dùng thẳng bản đã lưu trong 60 giây mà không gọi mạng. Hết hạn mà response có ETag hoặc Last-Modified, OkHttp tự gửi conditional request (If-None-Match/If-Modified-Since); server trả 304 Not Modified (không có body) thì dùng lại body đã lưu: tiết kiệm băng thông nhưng vẫn mất một round trip. no-cache nghĩa là phải revalidate mỗi lần (vẫn được lưu), no-store là không được lưu. Chỉ cache GET; server không gửi header phù hợp thì không có gì để cache, và chèn header bằng network interceptor chỉ là cách chữa cháy khi không sửa được backend. Cache nằm trong cacheDir nên hệ thống hay người dùng có thể xoá, và xem offline phải ép CacheControl.FORCE_CACHE (chưa có thì nhận 504), nên không đủ đáng tin để làm tính năng offline. Chọn Room khi cần xem offline đáng tin, lọc/sắp xếp/phân trang cục bộ, gộp dữ liệu từ nhiều endpoint, sửa cục bộ (đánh dấu đã đọc, optimistic update) và quan sát bằng Flow: Room là single source of truth. Cache HTTP hợp với dữ liệu nguyên khối ít đổi, cấu hình công khai, ảnh; gần như không tốn code. Hai cách dùng chung được: Room để hiển thị, cache HTTP để lần refresh nhẹ hơn nhờ 304.
val client = OkHttpClient.Builder()
  .cache(Cache(File(context.cacheDir, "http"), 10L * 1024 * 1024)) // 10 MB
  .build()

// Server trả: Cache-Control: max-age=60, ETag: "v42"
//  - trong 60 giây: dùng thẳng bản đã lưu, không gọi mạng
//  - sau 60 giây: gửi If-None-Match: "v42" -> 304 thì dùng lại body cũ

// Offline: chỉ lấy từ cache, chưa có thì OkHttp trả 504 Unsatisfiable Request
val offlineRequest = request.newBuilder()
  .cacheControl(CacheControl.FORCE_CACHE)
  .build()
