Vì sao không nên nhét hết logic vào Activity? MVC, MVP và MVVM khác nhau thế nào ở mức cơ bản, và ViewModel giữ vai trò gì?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Activity/Fragment là lớp UI do hệ thống tạo và huỷ (xoay màn hình, hết bộ nhớ), nên logic và dữ liệu nhét trong đó vừa mất theo vòng đời, vừa khó test vì phải có framework Android, và file nhanh chóng phình thành "God Activity". Vì vậy UI chỉ nên hiển thị và bắt sự kiện, còn logic nằm ở lớp khác. MVC: Controller nhận thao tác rồi cập nhật Model, View đọc Model; trên Android Activity vừa là View vừa là Controller nên vẫn phình. MVP: Presenter chứa logic và gọi View qua một interface (view.showUsers(...)), Activity cài interface đó; dễ test hơn nhưng nhiều boilerplate và phải tự lo vòng đời. MVVM: ViewModel giữ UI state và phơi ra dạng quan sát được (StateFlow, LiveData), View chỉ quan sát và gửi sự kiện lên; ViewModel không biết View nên không leak Activity. ViewModel sống qua configuration change (xoay máy), bị huỷ khi màn hình thật sự kết thúc, nhưng không sống qua process death. Bẫy: không giữ Context, Activity hay View trong ViewModel.
data class CounterUiState(val count: Int = 0)

class CounterViewModel : ViewModel() {
  private val _state = MutableStateFlow(CounterUiState())
  val state: StateFlow<CounterUiState> = _state.asStateFlow()

  fun onIncrement() = _state.update { it.copy(count = it.count + 1) } // logic nằm ở ViewModel
}

@Composable
fun CounterScreen(viewModel: CounterViewModel = viewModel()) {
  val state by viewModel.state.collectAsStateWithLifecycle()     // View chỉ quan sát state
  Button(onClick = viewModel::onIncrement) { Text("Đã bấm ${state.count} lần") }
}
