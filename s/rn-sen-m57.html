Với kiểu có thương hiệu (branded type) như dưới đây, hai lời gọi cancelOrder cho kết quả biên dịch thế nào?

type UserId = string & { readonly __brand: 'UserId' };
type OrderId = string & { readonly __brand: 'OrderId' };

const asUserId = (s: string) => s as UserId;

function cancelOrder(id: OrderId) {
  // ...
}

const userId = asUserId('u_1');
cancelOrder(userId); // (1)
cancelOrder('o_9'); // (2)
  1. ACả hai biên dịch được, vì UserId, OrderId và chuỗi 'o_9' đều là string
  2. BCả hai đều lỗi: (1) sai thương hiệu, (2) chuỗi thường chưa mang thương hiệu OrderId
  3. CChỉ (1) báo lỗi, vì chuỗi literal 'o_9' được tự động gán thương hiệu OrderId
  4. DChỉ (2) báo lỗi, vì UserId là kiểu con của string nên truyền được cho mọi tham số
Xem đáp án
Đáp án đúng: B
UserId và OrderId là hai kiểu giao có thuộc tính __brand khác nhau nên không gán chéo được, và string thường cũng không gán được cho OrderId vì thiếu __brand. Mẫu này chặn lỗi truyền nhầm các ID cùng là chuỗi ngay lúc biên dịch mà không tốn gì lúc chạy: __brand chỉ tồn tại ở mức kiểu, giá trị thật vẫn là một chuỗi bình thường. Việc đổi chuỗi sang kiểu có thương hiệu chỉ nên làm ở biên (parse dữ liệu API, hàm kiểm tra hợp lệ) bằng as có kiểm soát.
