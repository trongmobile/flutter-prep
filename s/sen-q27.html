Bảng messages trong SQLite (Drift) đã lên hàng triệu dòng: mở màn hình chat chậm vài giây, UI đứng khi import dữ liệu, và có yêu cầu mới là mã hoá database. Bạn tối ưu SQLite ở quy mô này thế nào (index, query, transaction, isolate, WAL, mã hoá)?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Đo trước: dùng EXPLAIN QUERY PLAN để xem query quét toàn bảng (SCAN) hay dùng index (SEARCH ... USING INDEX), rồi tạo index khớp với WHERE và ORDER BY thực tế (index kết hợp (conversationId, createdAt) cho truy vấn 'tin nhắn của một cuộc trò chuyện theo thời gian'); index quá nhiều làm ghi chậm và tăng dung lượng. Phân trang bằng keyset (WHERE createdAt < ? ORDER BY createdAt DESC LIMIT 50) thay vì OFFSET lớn vốn phải đọc rồi bỏ qua nhiều dòng. Ghi nhiều dòng phải nằm trong một transaction hoặc batch: mỗi lệnh ghi riêng lẻ là một transaction tự động kèm fsync, nên import 100.000 dòng có thể nhanh hơn hàng chục lần khi gộp lại. Chạy DB ở isolate nền (NativeDatabase.createInBackground) để query và import nặng không chặn UI thread; lưu ý chi phí chuyển dữ liệu qua isolate nên chỉ trả về những cột và số dòng cần. Bật WAL (PRAGMA journal_mode = WAL) để đọc và ghi không chặn nhau, kèm synchronous = NORMAL nếu chấp nhận đánh đổi độ bền khi mất điện đột ngột. Stream watch() chạy lại mỗi lần bảng đổi, nên với bảng ghi dồn dập cần thu hẹp query hoặc gom thay đổi (debounce). Mã hoá toàn bộ database dùng SQLCipher (sqlcipher_flutter_libs, đặt khoá bằng PRAGMA key khi mở) với khoá sinh ngẫu nhiên và cất trong Keychain hoặc Keystore, chấp nhận chi phí hiệu năng và kích thước. Dọn dữ liệu cũ định kỳ (xoá theo lô ở nền), VACUUM khi cần giải phóng dung lượng, kiểm thử migration trên dữ liệu lớn thật, và có chiến lược xử lý DB hỏng (backup, dựng lại từ server) vì không thể giả định chuyện đó không bao giờ xảy ra.
LazyDatabase openDatabase() {
  return LazyDatabase(() async {
    final dir = await getApplicationDocumentsDirectory();
    final file = File(p.join(dir.path, 'app.db'));
    return NativeDatabase.createInBackground( // chạy ở isolate nền, không chặn UI
      file,
      setup: (db) {
        db.execute('PRAGMA journal_mode = WAL;'); // đọc và ghi không chặn nhau
        db.execute('PRAGMA synchronous = NORMAL;');
      },
    );
  });
}

@TableIndex(name: 'idx_messages_conv_time', columns: {#conversationId, #createdAt})
class Messages extends Table {
  IntColumn get id => integer().autoIncrement()();
  TextColumn get conversationId => text()();
  DateTimeColumn get createdAt => dateTime()();
  TextColumn get body => text()();
}

// Phân trang keyset thay vì OFFSET lớn
Future<List<Message>> pageBefore(String convId, DateTime before) =>
    (select(messages)
          ..where((m) => m.conversationId.equals(convId) & m.createdAt.isSmallerThanValue(before))
          ..orderBy([(m) => OrderingTerm.desc(m.createdAt)])
          ..limit(50))
        .get();
