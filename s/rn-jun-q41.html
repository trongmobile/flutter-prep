Hàm getUser(): Promise<User> dùng (await res.json()) as User, TypeScript build xanh nhưng app crash ở user.address.city vì server trả address: null cho một số tài khoản. Vì sao kiểu khai báo không cứu được bạn? Bạn mô hình hoá response (generic ApiResponse<T>, union) và kiểm tra dữ liệu lúc chạy thế nào?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
TypeScript chỉ kiểm tra lúc build, còn dữ liệu từ mạng là dữ liệu lúc chạy: as User chỉ là lời hứa của bạn với compiler, không có gì kiểm tra thật. res.json() trả về Promise<any> nên kiểu sai cứ thế lan vào code mà không ai báo. Cách làm: khai báo kiểu sát thực tế (address: Address | null) và bật strict để compiler buộc xử lý null; coi dữ liệu mạng là unknown rồi kiểm tra bằng schema lúc chạy (Zod, Valibot…) ngay ở biên của app, còn kiểu TypeScript suy ra từ schema (z.infer) nên không bao giờ lệch. Response mô hình hoá bằng discriminated union để mỗi nhánh có đúng dữ liệu của nó; sau if (result.ok) compiler tự thu hẹp kiểu (narrowing) nên không cần ép kiểu. Tránh as và any cho dữ liệu từ ngoài vào; nếu buộc phải kiểm tra thủ công thì viết type guard (function isUser(x: unknown): x is User).
type ApiResponse<T> =
  | { ok: true; data: T }
  | { ok: false; error: { code: string; message: string } };

const UserSchema = z.object({
  id: z.number(),
  name: z.string(),
  address: z.object({ city: z.string() }).nullable(),
});
type User = z.infer<typeof UserSchema>;

async function getUser(id: number): Promise<ApiResponse<User>> {
  const res = await fetch(`${API}/users/${id}`);
  const json: unknown = await res.json(); // không tin dữ liệu từ mạng
  const parsed = UserSchema.safeParse(json);
  return parsed.success
    ? { ok: true, data: parsed.data }
    : { ok: false, error: { code: 'INVALID_RESPONSE', message: parsed.error.message } };
}

const result = await getUser(1);
if (result.ok) {
  console.log(result.data.address?.city); // chỉ nhánh ok mới có data; address có thể null
}
