Màn danh sách đơn hàng dùng suspend fun getOrders(): List<Order>, nên sau khi thêm đơn ở màn khác, quay lại phải gọi tải lại thủ công. Flow giải quyết việc này thế nào, cold flow là gì, và nó khác hàm suspend trả List ở đâu?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Hàm suspend trả List chỉ cho đúng một kết quả rồi kết thúc: dữ liệu đổi sau đó thì phải gọi lại. Flow<T> là luồng nhiều giá trị theo thời gian. Flow là cold: code trong flow { } không chạy cho tới khi có collect, và mỗi collector chạy lại từ đầu (khác StateFlow là hot, luôn giữ giá trị hiện tại dù không ai nghe). collect là hàm suspend nên phải gọi trong coroutine; các operator trung gian như map, filter, onEach chỉ dựng pipeline, đến khi có terminal operator (collect, first, toList) mới chạy. Với Room, DAO khai báo fun observeOrders(): Flow<List<Order>> (không cần suspend): Room chạy query ngoài main thread và phát lại danh sách mới mỗi khi bảng liên quan thay đổi, nên UI tự cập nhật mà không phải tải lại. Bẫy: collect trên Flow của Room không bao giờ kết thúc, nên code viết sau nó trong cùng coroutine không bao giờ chạy, muốn thu thập nhiều flow phải launch riêng từng cái; và Room phát lại khi bảng đổi dù kết quả query vẫn như cũ, thêm distinctUntilChanged() nếu UI không cần vẽ lại.
@Dao
interface OrderDao {
    @Query("SELECT * FROM orders ORDER BY created_at DESC")
    fun observeOrders(): Flow<List<Order>> // không cần suspend, Room tự phát lại khi bảng đổi
}

class OrderViewModel(dao: OrderDao) : ViewModel() {
    val pendingOrders: StateFlow<List<Order>> = dao.observeOrders()
        .map { orders -> orders.filter { it.status == Status.PENDING } } // chưa chạy gì cho tới khi có collector
        .distinctUntilChanged()
        .stateIn(viewModelScope, SharingStarted.WhileSubscribed(5_000), emptyList())
}
