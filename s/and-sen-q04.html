Team vừa chuyển feed từ RecyclerView sang LazyColumn và thấy cuộn kém mượt hơn bản cũ trên máy tầm thấp. Bạn kiểm tra những nguyên nhân đặc thù của Compose nào và tối ưu ra sao?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Trước hết đo trên bản release có R8 và Baseline Profile: Compose là thư viện đi kèm app chứ không nằm sẵn trong hệ điều hành như framework View, nên bản debug hay bản chưa được AOT-compile chậm hơn đáng kể. Sau đó xem item: mỗi item cần key ổn định và contentType theo loại, vì Compose chỉ tái sử dụng composition giữa các item cùng contentType, tương tự view type của RecyclerView. Đưa việc nặng ra khỏi composition của item: format ngày, parse, lọc hay sắp xếp nên làm sẵn trong ViewModel thành UI model; tránh BoxWithConstraints/SubcomposeLayout trong từng item vì subcomposition tốn kém. Ảnh nên tải đúng kích thước hiển thị và giữ chỗ bằng kích thước cố định để item không phải đo lại khi ảnh về. Bật composition tracing để thấy tên composable trong Perfetto, và đo lại bằng Macrobenchmark FrameTimingMetric sau mỗi thay đổi.
LazyColumn {
  items(
    items = feed, // List<FeedItemUi> đã format sẵn trong ViewModel
    key = { it.id },
    contentType = { it::class }, // Post, Ad, Carousel tái sử dụng riêng
  ) { item ->
    when (item) {
      is FeedItemUi.Post -> PostRow(item)
      is FeedItemUi.Ad -> AdRow(item)
      is FeedItemUi.Carousel -> CarouselRow(item)
    }
  }
}
