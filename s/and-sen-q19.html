App có 30 dev cùng làm, CI chạy chậm và test UI hay flaky. Bạn đề xuất chiến lược test thế nào?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Tôi theo hình kim tự tháp và ưu tiên tốc độ phản hồi. Đáy là unit test JVM cho ViewModel, UseCase, Repository với fake thay vì mock tràn lan, coroutine test bằng runTest; thêm integration test cho Room (in-memory) và tầng network (MockWebServer). Phần UI chuyển phần lớn sang screenshot test chạy trên JVM (Paparazzi, hoặc Roborazzi với Robolectric) cho component và màn hình ở nhiều state, nhanh và không cần emulator; Compose UI test cho các tương tác quan trọng. E2E trên emulator hay thiết bị thật (Gradle Managed Devices, Firebase Test Lab) chỉ dành cho vài luồng sống còn như đăng nhập, thanh toán, chạy nightly hoặc trước release. Chống flaky: không Thread.sleep, chờ theo điều kiện, tắt animation, dữ liệu test cố định; đo tỉ lệ flaky và cách ly test flaky kèm owner chịu trách nhiệm sửa. CI chỉ chạy test của module bị ảnh hưởng và shard test song song.
class PrimaryButtonScreenshotTest {
  @get:Rule
  val paparazzi = Paparazzi(deviceConfig = DeviceConfig.PIXEL_5)

  @Test
  fun disabled_darkTheme() {
    paparazzi.snapshot {
      AppTheme(dark = true) {
        PrimaryButton(text = "Thanh toán", enabled = false, onClick = {})
      }
    }
  }
}
