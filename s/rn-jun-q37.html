Bạn merge main vào nhánh feature thì dính conflict ở yarn.lock (hoặc package-lock.json), Podfile.lock và cả project.pbxproj. Bạn xử lý thế nào, và team làm gì để ít gặp conflict kiểu này?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
File lock không sửa tay từng dòng: giải quyết package.json trước (giữ dependency của cả hai bên), lấy bản lock của main làm gốc rồi chạy lại yarn install (hoặc npm install) để công cụ tự sinh phần của nhánh bạn, sau đó commit. Podfile.lock làm tương tự bằng pod install. project.pbxproj do Xcode sinh ra và dễ hỏng khi gộp tay, nên nếu chỉ thêm file hay đổi setting thì giữ bản của main rồi thao tác lại trong Xcode, và kiểm tra project vẫn mở và build được. Với conflict ở code, đọc cả hai phía để hiểu ý định của từng người thay vì bấm "Accept mine" cho nhanh; chưa chắc thì hỏi người sửa đoạn đó. Gộp xong phải chạy lại app, lint và test trước khi push. Giảm conflict bằng nhánh sống ngắn, PR nhỏ, thường xuyên cập nhật main về nhánh của mình, tách commit nâng thư viện khỏi commit tính năng; nhánh dùng chung thì không git push --force.
