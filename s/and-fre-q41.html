Android có những cách lưu dữ liệu cục bộ nào? Bạn chọn thế nào giữa DataStore, file và Room (SQLite) cho ba trường hợp: cài đặt giao diện, ảnh/báo cáo tải về, danh sách đơn hàng?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Chọn theo hình dạng dữ liệu. Cặp key-value nhỏ như cài đặt, cờ đã xem onboarding, theme: dùng Preferences DataStore thay cho SharedPreferences, vì nó bất đồng bộ, đọc bằng Flow và ghi trong transaction, không chặn main thread. Dữ liệu dạng file (ảnh, PDF, JSON lớn): ghi vào internal storage (filesDir) hoặc cacheDir cho dữ liệu có thể tải lại, vì hệ thống được phép xoá cache khi thiếu bộ nhớ. Dữ liệu có cấu trúc, nhiều bản ghi, cần lọc, sắp xếp, join, phân trang hoặc dùng offline: dùng Room (lớp trừu tượng trên SQLite) với SQL được kiểm tra lúc compile và trả về Flow. Bẫy thường gặp: nhét cả danh sách lớn vào SharedPreferences/DataStore dưới dạng chuỗi JSON (phải đọc và ghi lại cả khối, không truy vấn được), hoặc ngược lại dùng cả database chỉ để lưu một cờ true/false. Dữ liệu trong bộ nhớ trong của app bị xoá khi gỡ app hoặc Clear data, còn token và mật khẩu thì không lưu dạng plain text.
// Top-level: một DataStore duy nhất cho mỗi file
private val Context.dataStore by preferencesDataStore(name = "settings")
private val DARK_MODE = booleanPreferencesKey("dark_mode")

// 1) Cài đặt nhỏ -> DataStore
fun darkMode(context: Context): Flow<Boolean> =
  context.dataStore.data.map { it[DARK_MODE] ?: false }

suspend fun setDarkMode(context: Context, enabled: Boolean) {
  context.dataStore.edit { it[DARK_MODE] = enabled }
}

// 2) File lớn -> thư mục riêng của app (gọi ngoài main thread)
