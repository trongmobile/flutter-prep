Swift Testing (@Test, #expect) khác XCTest ở những điểm nào? Dự án đang có vài trăm test XCTest thì có nên chuyển hết không?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Swift Testing dùng macro thay cho quy ước đặt tên: hàm gắn @Test là một test, không cần kế thừa XCTestCase, suite có thể là struct và mỗi test chạy trên một instance mới. #expect(a == b) thay cho cả họ XCTAssert... và khi fail hiển thị rõ giá trị từng vế; #require thì dừng test ngay khi điều kiện sai, hay dùng để unwrap optional. Có sẵn test tham số hoá @Test(arguments:), trait như .tags, .disabled, và mặc định chạy song song nên test dùng chung state toàn cục dễ flaky. Hai framework chạy chung được trong cùng target, nên không cần chuyển hết: viết test mới bằng Swift Testing, chuyển dần khi động vào test cũ. UI test và performance test (XCUIApplication, measure) hiện vẫn viết bằng XCTest.
import Testing

struct PriceFormatterTests {
  @Test(arguments: zip([0, 1000, 25000], ["0 ₫", "1.000 ₫", "25.000 ₫"]))
  func formatVND(amount: Int, expected: String) {
    #expect(PriceFormatter.vnd(amount) == expected)
  }

  @Test func parseValidPrice() throws {
    let value = try #require(PriceFormatter.parse("1.000 ₫")) // nil thì dừng test
    #expect(value == 1000)
  }
}
