State hoisting trong Jetpack Compose là gì? Vì sao một composable SearchBar tự giữ remember { mutableStateOf("") } bên trong lại khó dùng lại và khó test?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
State hoisting là đưa state ra khỏi composable, thay bằng hai tham số: giá trị hiện tại (query) và callback báo sự kiện (onQueryChange). Composable khi đó là stateless: chỉ hiển thị cái được truyền vào và báo lên khi người dùng tương tác, còn nơi giữ state (màn hình hoặc ViewModel) quyết định cập nhật thế nào. Nếu SearchBar tự giữ state, màn hình cha không đọc được text để gọi tìm kiếm, không xoá được text từ bên ngoài, và preview/test phải giả lập thao tác gõ mới vào được trạng thái mong muốn. Nguyên tắc là đẩy state lên tổ tiên chung thấp nhất cần đọc hoặc ghi nó, tạo luồng dữ liệu một chiều: state đi xuống, event đi lên.
@Composable
fun SearchBar(
    query: String,
    onQueryChange: (String) -> Unit,
    modifier: Modifier = Modifier
) {
    TextField(value = query, onValueChange = onQueryChange, modifier = modifier)
}

// Màn hình giữ state, SearchBar chỉ hiển thị và báo sự kiện
val query by viewModel.query.collectAsStateWithLifecycle()
SearchBar(query = query, onQueryChange = viewModel::onQueryChange)
