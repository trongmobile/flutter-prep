Khi viết unit test cho một hàm xử lý logic (như tính phí giao hàng hoặc kiểm tra dữ liệu nhập), bạn chọn các test case thế nào để tránh bỏ sót lỗi? Một hàm test thường có cấu trúc ra sao?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Để unit test có giá trị, cần bao phủ ba nhóm case chính: trường hợp hợp lệ điển hình (happy path), trường hợp dữ liệu không hợp lệ (như chuỗi rỗng, toàn khoảng trắng hoặc số âm) và các trường hợp biên (edge case như giá trị bằng 0, đúng ngưỡng chuyển mức phí hay độ dài tối đa). Mỗi hàm test chỉ nên kiểm tra một hành vi hoặc một điều kiện cụ thể, đặt tên mô tả rõ đầu vào và kết quả mong đợi để khi test fail nhìn vào tên là biết ngay lỗi ở đâu. Bên trong hàm test thường tổ chức theo mô hình Arrange–Act–Assert: chuẩn bị dữ liệu đầu vào ở phần Arrange, gọi hàm cần kiểm tra ở phần Act, rồi dùng các hàm kiểm chứng như assertEquals, assertTrue hay cơ chế bắt exception ở phần Assert. Ngoài ra các test phải độc lập với nhau, không chia sẻ trạng thái thay đổi qua lại để tránh kết quả phụ thuộc vào thứ tự chạy.
import org.junit.Assert.assertEquals
import org.junit.Test

fun calcShippingFee(orderTotal: Int): Int {
  require(orderTotal >= 0) { "Tổng đơn không được âm" }
  return if (orderTotal >= 500_000) 0 else 30_000
}

class ShippingFeeTest {
  @Test
  fun orderBelowFreeThreshold_returnsStandardFee() {
    val total = 499_999                                // Arrange (edge case ngay dưới ngưỡng)
    val fee = calcShippingFee(total)                   // Act
    assertEquals(30_000, fee)                          // Assert
  }

  @Test
  fun orderAtFreeThreshold_returnsZero() {
    assertEquals(0, calcShippingFee(500_000))          // Edge case đúng ngưỡng miễn phí
  }

  @Test(expected = IllegalArgumentException::class)
  fun negativeOrderTotal_throwsException() {
    calcShippingFee(-1)
  }
}
