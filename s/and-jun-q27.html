Fragment dùng ViewBinding bị LeakCanary báo leak sau khi người dùng chuyển sang màn khác. Vì sao phải gán binding về null trong onDestroyView, và nên observe LiveData/Flow bằng viewLifecycleOwner hay this?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Fragment có hai vòng đời: bản thân Fragment và view của nó. Khi Fragment nằm trong back stack, onDestroyView chạy và view bị huỷ, nhưng instance Fragment vẫn sống để khi quay lại gọi onCreateView tạo view mới. Nếu field binding vẫn trỏ tới view cũ thì cả cây view (cùng Context của Activity mà nó giữ) không được GC dù không còn hiển thị, nên mới có mẫu _binding nullable, getter binding ép non-null và gán _binding = null trong onDestroyView. Với observer, dùng viewLifecycleOwner thay vì this: observer gắn vào Fragment không bị gỡ khi view bị huỷ, mỗi lần view được tạo lại lại thêm một observer nữa nên UI bị cập nhật trùng lặp. Cùng lý do, coroutine cập nhật UI nên chạy trong viewLifecycleOwner.lifecycleScope để bị huỷ khi view biến mất, tránh callback chạm vào binding đã null.
class ProfileFragment : Fragment(R.layout.fragment_profile) {
    private var _binding: FragmentProfileBinding? = null
    private val binding get() = _binding!!
    private val viewModel: ProfileViewModel by viewModels()

    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        _binding = FragmentProfileBinding.bind(view)
        viewModel.name.observe(viewLifecycleOwner) { binding.nameText.text = it }
    }

    override fun onDestroyView() {
        super.onDestroyView()
        _binding = null // nhả cây view để GC thu hồi
    }
}
