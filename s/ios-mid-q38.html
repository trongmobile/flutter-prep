Bản cập nhật mới của app nặng gần 180MB, user phàn nàn tải chậm qua 4G và PM yêu cầu giảm kích thước. Bạn đo xem phần nào chiếm dung lượng bằng cách nào, và App Thinning, asset catalog cùng các thư viện bên thứ ba ảnh hưởng ra sao?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Trước hết phân biệt kích thước tải về (đã nén) với kích thước cài đặt, và nhớ App Store tính theo từng thiết bị chứ không có một con số chung. Slicing trong App Thinning chỉ gửi cho mỗi máy kiến trúc CPU và asset phù hợp (đúng @2x/@3x), nhưng chỉ áp dụng với ảnh và data nằm trong asset catalog; file ảnh bỏ rời trong bundle thì máy nào cũng phải tải đủ. Bitcode đã bị Apple loại bỏ từ Xcode 14 nên không còn là công cụ giảm size. Cách đo: Archive, rồi Distribute App và chọn xuất App Thinning (all compatible device variants) để có App Thinning Size Report cho từng biến thể thiết bị; bật Write Link Map File để xem symbol nào nặng; theo dõi kích thước giữa các build trong App Store Connect. Cách giảm: chuyển ảnh vào asset catalog, dùng vector (PDF/SVG) hoặc SF Symbols thay cho nhiều bản PNG; video, âm thanh, font, model ML lớn thì tải từ server sau khi cài (hoặc On-Demand Resources) thay vì nhét vào bundle; bản Release bật Dead Code Stripping, Strip Linked Product, Strip Swift Symbols và optimization -Osize; xoá asset và code không dùng. Thư viện bên thứ ba là thủ phạm hay gặp: SDK quảng cáo, analytics hay framework dynamic được nhúng vào app đều cộng thẳng vào bundle, còn link static thường được dead-strip tốt hơn; thử gỡ từng SDK rồi so lại báo cáo kích thước để biết cái nào đáng ngờ.
