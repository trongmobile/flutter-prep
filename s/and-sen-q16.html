Bạn lưu access token và refresh token trên Android thế nào cho an toàn? EncryptedSharedPreferences còn là lựa chọn tốt không?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
androidx.security:security-crypto (gồm EncryptedSharedPreferences, MasterKey) đã deprecated, nên với code mới tôi tự mã hoá: tạo AES key trong Android Keystore (key không export được, có thể nằm trong TEE/StrongBox), mã hoá token bằng AES-GCM rồi lưu IV cùng ciphertext vào DataStore hoặc file trong internal storage. Keystore không ngăn kẻ đã root máy gọi key thông qua chính process của app, nhưng ngăn việc copy key ra khỏi thiết bị. Access token ngắn hạn có thể chỉ giữ trong memory, refresh token mới cần lưu bền và nên được backend rotate. Không log token, loại file chứa token khỏi backup (dataExtractionRules, với Android 11 trở xuống là fullBackupContent), vì key Keystore không đi theo bản backup nên dữ liệu restore sang máy mới không giải mã được. Cuối cùng phải xử lý KeyPermanentlyInvalidatedException (key yêu cầu xác thực người dùng bị vô hiệu khi user tắt khoá màn hình hoặc thêm vân tay) bằng cách xoá key và cho đăng nhập lại.
fun encrypt(plain: ByteArray): Pair<ByteArray, ByteArray> {
  val ks = KeyStore.getInstance("AndroidKeyStore").apply { load(null) }
  val key = ks.getKey(ALIAS, null) as? SecretKey ?: KeyGenerator
    .getInstance(KeyProperties.KEY_ALGORITHM_AES, "AndroidKeyStore")
    .apply {
      init(KeyGenParameterSpec.Builder(ALIAS, KeyProperties.PURPOSE_ENCRYPT or KeyProperties.PURPOSE_DECRYPT)
        .setBlockModes(KeyProperties.BLOCK_MODE_GCM)
        .setEncryptionPaddings(KeyProperties.ENCRYPTION_PADDING_NONE)
        .build())
    }.generateKey()
  val cipher = Cipher.getInstance("AES/GCM/NoPadding")
  cipher.init(Cipher.ENCRYPT_MODE, key) // Keystore tự sinh IV ngẫu nhiên
  return cipher.iv to cipher.doFinal(plain) // lưu cả IV và ciphertext
}
