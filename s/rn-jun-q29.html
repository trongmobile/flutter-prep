Bạn có CountryPicker và CategoryPicker gần như giống hệt nhau, chỉ khác kiểu dữ liệu. Làm sao gộp thành một component SelectList dùng chung mà onSelect vẫn nhận đúng kiểu, không phải dùng any?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Dùng generic: khai báo tham số kiểu T cho component để items: T[] và onSelect: (item: T) => void cùng một kiểu. TypeScript tự suy ra T từ items ở nơi dùng, nên onSelect nhận đúng Country hay Category và gõ sai thuộc tính bị báo ngay. Phần component cần đọc nhưng không biết kiểu thì nhận qua prop như getLabel, hoặc ràng buộc T extends { id: string } để dùng item.id làm key. Bẫy hay gặp: trong file .tsx, arrow function generic phải viết <T,>(props) => ... hoặc <T extends object> vì <T> bị hiểu là thẻ JSX; khai báo bằng function thì không bị. Bọc React.memo làm mất tham số kiểu, cần ép lại bằng memo(SelectList) as typeof SelectList. Custom hook cũng dùng generic được, như useFetch<T>, nhưng kiểu chỉ có lúc biên dịch, dữ liệu server thật vẫn có thể sai.
type SelectListProps<T extends { id: string }> = {
  items: T[];
  getLabel: (item: T) => string;
  onSelect: (item: T) => void;
};

function SelectList<T extends { id: string }>({ items, getLabel, onSelect }: SelectListProps<T>) {
  return (
    <FlatList
      data={items}
      keyExtractor={(item) => item.id}
      renderItem={({ item }) => (
        <Pressable onPress={() => onSelect(item)}>
          <Text>{getLabel(item)}</Text>
        </Pressable>
      )}
    />
  );
}

// T được suy ra là Country, nên country.dialCode có gợi ý và được kiểm tra kiểu
<SelectList items={countries} getLabel={(c) => c.name} onSelect={(country) => setDial(country.dialCode)} />
