Cách debug cơ bản trong Xcode: breakpoint, po trong lldb, print khác os.Logger thế nào? Exception breakpoint dùng khi nào và đọc crash log đơn giản ra sao?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Breakpoint (bấm vào số dòng ở lề) dừng chương trình tại dòng đó để xem biến, rồi dùng Step Over/Into/Out để chạy tiếp từng bước. Breakpoint có thể có điều kiện, bỏ qua n lần, hoặc chỉ ghi log rồi tự chạy tiếp (Action cộng Automatically continue) mà không phải sửa code. Khi đang dừng, console lldb cho gõ lệnh: po expr in mô tả object, p in giá trị có kiểu, bt xem call stack. print đơn giản nhưng in mọi thứ ra console, không có mức độ, không lọc được; os.Logger (import os) có mức debug/info/error, lọc theo subsystem/category trong Xcode hoặc Console.app, xem được log cả từ máy thật, và giá trị chuỗi động mặc định bị che khi xem ngoài Xcode trừ khi đánh dấu privacy: .public. Exception breakpoint (Breakpoint navigator, dấu +) dừng ngay tại dòng gây lỗi thay vì chỉ thấy SIGABRT ở main hay AppDelegate, hữu ích với lỗi như unrecognized selector hoặc outlet nối sai. Đọc crash log: xem Exception Type (ví dụ EXC_BAD_ACCESS, hoặc EXC_BREAKPOINT khi force unwrap nil), rồi trong thread có dòng Crashed tìm frame đầu tiên thuộc code của app; log từ bản release chỉ có địa chỉ hex nếu thiếu dSYM.
import os

private let logger = Logger(subsystem: "com.example.shop", category: "checkout")

struct CartItem {
    let name: String
    let price: Int
}

func placeOrder(items: [CartItem]) {
    // print("placeOrder \(items)")                        // in hết ra console, không có mức độ, không lọc được
    logger.info("Đặt hàng với \(items.count) sản phẩm")

    guard !items.isEmpty else {
        logger.error("Giỏ hàng trống khi đặt hàng")
        return
    }

    // Đặt breakpoint ở dòng dưới, rồi gõ trong lldb:
    //   po items.map(\.name)
    //   p items.count
    let total = items.reduce(0) { $0 + $1.price }
    logger.debug("Tổng tiền: \(total, privacy: .public)")
}
