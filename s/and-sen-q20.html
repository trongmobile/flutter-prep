Mô tả quy trình release bạn muốn có cho một app Android vài triệu người dùng, từ lúc merge code tới khi 100% user nhận bản mới.

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Tôi dùng release train cố định, ví dụ hai tuần: cắt branch release, sau đó chỉ nhận bug fix. CI build AAB, ký bằng upload key (Play App Signing giữ app signing key), tự tăng versionCode, upload mapping file và native symbols để crash được deobfuscate. Bản build đi qua internal testing, rồi closed testing cho QA và dogfood nội bộ, sau đó lên production với staged rollout tăng dần (1% → 5% → 20% → 50% → 100%). Mỗi bước có tiêu chí qua cửa rõ ràng: crash-free users trên Crashlytics, crash rate và ANR rate trên Android vitals, cùng các metric nghiệp vụ chính. Vượt ngưỡng thì halt rollout ngay; user đã cài không thể bị hạ phiên bản, nên phải sửa bằng hotfix có versionCode cao hơn hoặc tắt tính năng bằng feature flag. Việc upload và tăng rollout được tự động hoá qua Play Developer API (Gradle Play Publisher hoặc fastlane), nhưng quyết định tăng % vẫn dựa trên số liệu.
