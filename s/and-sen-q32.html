Google Play yêu cầu nâng targetSdk hằng năm. Khi nâng lên các bản gần đây (35, 36), những behavior change nào dễ làm vỡ app nhất, và bạn quản lý việc nâng targetSdk thế nào để không dồn thành một đợt lớn?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Tôi đọc phần behavior changes của từng API level và chia thành thay đổi áp dụng cho mọi app với thay đổi chỉ áp dụng khi nâng targetSdk. Với target 35, edge-to-edge bị bắt buộc: nội dung vẽ dưới status bar và navigation bar, nên layout nào dựa vào việc hệ thống tự chừa chỗ sẽ bị đè, cần xử lý WindowInsets (enableEdgeToEdge(), Scaffold/safeDrawingPadding trong Compose, ViewCompat.setOnApplyWindowInsetsListener với View). App có thư viện native còn phải hỗ trợ page size 16KB (Play yêu cầu từ 1/11/2025 cho app target Android 15 trở lên): các file .so phải căn lề 16KB, NDK r28 trở lên làm đúng theo mặc định và AGP 8.5.1 trở lên lo phần zip-align. Với target 36, predictive back được bật mặc định nên onBackPressed() và KEYCODE_BACK không còn được gọi, phải chuyển sang OnBackPressedCallback/BackHandler; trên màn hình lớn (từ 600dp) hệ thống bỏ qua khoá hướng xoay và giới hạn tỉ lệ khung hình, nên layout phải thích ứng bằng window size class. Về quy trình: nâng compileSdk trước vì không đổi hành vi lúc chạy, rồi thử targetSdk mới trên nhánh riêng với thiết bị hoặc emulator của bản mới, bật từng thay đổi bằng App Compatibility Changes trong Developer options để biết cái nào làm vỡ, sau đó staged rollout. Bắt đầu ngay khi có bản beta thay vì đợi sát hạn của Play.
class MainActivity : ComponentActivity() {
  override fun onCreate(savedInstanceState: Bundle?) {
    enableEdgeToEdge() // target 35 bắt buộc vẽ dưới system bars, nên chủ động xử lý
    super.onCreate(savedInstanceState)
    setContent {
      Scaffold(modifier = Modifier.fillMaxSize()) { innerPadding ->
        // insets đi qua innerPadding: nội dung không bị status bar hay thanh điều hướng đè lên
        AppContent(Modifier.padding(innerPadding))
      }
    }
  }
}

// Target 36: onBackPressed() không còn được gọi, dùng BackHandler / OnBackPressedCallback
BackHandler(enabled = hasUnsavedChanges) { showDiscardDialog = true }
