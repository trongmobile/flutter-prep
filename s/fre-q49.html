Khi tách một phần giao diện thành widget con (ví dụ thanh tìm kiếm hoặc nút lọc), làm sao để widget con gửi dữ liệu hoặc sự kiện ngược lên widget cha khi chưa dùng thư viện state management?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Khi state nằm ở widget cha để dùng chung hoặc xử lý logic, widget cha sẽ truyền giá trị hiện tại xuống widget con qua tham số constructor, đồng thời truyền kèm một hàm callback (như VoidCallback khi không có dữ liệu hoặc ValueChanged<T> / void Function(T) khi có dữ liệu). Ở widget con, khi người dùng thao tác (như bấm nút hay đổi nội dung), widget con chỉ gọi callback đó và truyền giá trị mới lên chứ không tự sửa state của cha. Widget cha nhận được callback thì gọi setState để cập nhật biến state của mình, khiến Flutter rebuild lại phần UI phụ thuộc với dữ liệu mới. Cách này gọi là lifting state up, giúp luồng dữ liệu đi một chiều rõ ràng và widget con vẫn giữ được dạng StatelessWidget gọn nhẹ, dễ tái sử dụng.
class SearchBarWidget extends StatelessWidget {
  const SearchBarWidget({super.key, required this.onSearch});
  final ValueChanged<String> onSearch;

  @override
  Widget build(BuildContext context) {
    return TextField(onChanged: onSearch);
  }
}

class _ProductPageState extends State<ProductPage> {
  String _keyword = '';

  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        SearchBarWidget(
          onSearch: (value) => setState(() => _keyword = value),
        ),
        Text('Đang tìm: $_keyword'),
      ],
    );
  }
}
