Bạn viết component AppInput bọc TextInput kèm nhãn và viền báo lỗi. Màn hình cha gọi passwordRef.current?.focus() nhưng ref luôn là null, và TypeScript cũng phàn nàn khi truyền ref vào AppInput. Vì sao, xử lý thế nào, và khi nào nên (hay không nên) dùng ref kiểu imperative?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Với React 18 trở về trước, ref không phải prop thường: truyền ref vào function component thì bị bỏ qua (kèm cảnh báo), nên phải bọc component bằng forwardRef rồi gắn ref nhận được vào TextInput bên trong. Từ React 19 (React Native 0.78 trở lên), function component nhận ref như một prop bình thường, chỉ cần khai báo ref?: Ref<TextInput> và truyền xuống; forwardRef vẫn chạy nhưng sẽ bị loại dần. Muốn che bớt TextInput và chỉ cho cha gọi vài hàm như focus() hay clear() thì dùng useImperativeHandle để tự định nghĩa "giao diện" của ref. Ref imperative dành cho việc props/state không diễn tả được: focus, cuộn (scrollToIndex), đo layout, điều khiển player. Đừng dùng nó để đổi dữ liệu hay nội dung hiển thị (kiểu ref.current.setValue(...)): luồng dữ liệu bị giấu đi, khó theo dõi và khó test; việc đó thuộc về state và props.
type AppInputProps = TextInputProps & {
  label: string;
  error?: string;
  ref?: Ref<TextInput>; // React 19: ref là prop thường
};

function AppInput({ label, error, ref, ...rest }: AppInputProps) {
  return (
    <View>
      <Text>{label}</Text>
      <TextInput ref={ref} style={[styles.input, error ? styles.inputError : null]} {...rest} />
      {error ? <Text style={styles.error}>{error}</Text> : null}
    </View>
  );
}

// Màn hình cha
const passwordRef = useRef<TextInput>(null);

<AppInput label="Email" returnKeyType="next" onSubmitEditing={() => passwordRef.current?.focus()} />
<AppInput label="Mật khẩu" ref={passwordRef} secureTextEntry />

// React 18: bọc bằng forwardRef<TextInput, AppInputProps>((props, ref) => ...) rồi gắn ref vào TextInput
