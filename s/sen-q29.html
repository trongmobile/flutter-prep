Bạn thiết kế hệ thống ghi sự kiện analytics phía Flutter cho app triệu người dùng: không mất sự kiện khi mất mạng hoặc app bị kill, không làm chậm UI hay hao pin, và tuân thủ quyền riêng tư. Thiết kế thế nào?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Tôi tách thành API tầng ứng dụng, hàng đợi bền và bộ gửi. API chỉ có một interface Analytics.track(event) (ẩn vendor như Firebase, Amplitude hay backend riêng) và chỉ nhận event theo tracking plan có kiểu (tên, thuộc tính), có thể sinh code từ tài liệu plan để tránh sai tên. Mỗi event được gắn ngay lúc phát sinh: id duy nhất (UUID, để server loại trùng khi retry), thời điểm ở client, session id, anonymous id, phiên bản app và màn hình hiện tại. Event được ghi vào hàng đợi bền (SQLite hoặc file nối đuôi) thay vì chỉ giữ trong bộ nhớ nên app bị kill cũng không mất; việc ghi chạy ngoài luồng UI và gom thành lô nhỏ. Bộ gửi (flush) chạy theo ngưỡng: đủ N event, quá T giây, hoặc khi app chuyển sang paused (qua AppLifecycleListener); gửi theo lô nén, retry với exponential backoff kèm jitter, chỉ xoá khỏi hàng đợi sau khi server xác nhận, giới hạn dung lượng hàng đợi (bỏ event cũ nhất hoặc ít quan trọng nhất khi đầy) và tôn trọng trạng thái mạng cùng chế độ tiết kiệm pin. Server dùng thời điểm nhận cùng độ lệch giữa giờ client và server để hiệu chỉnh thời gian vì đồng hồ máy có thể sai. Quyền riêng tư: chỉ bật khi người dùng đồng ý (consent theo khu vực, iOS ATT nếu dùng định danh quảng cáo), không đưa dữ liệu cá nhân (email, số điện thoại, nội dung nhập) vào thuộc tính, hash hoặc bỏ đi, cho phép xoá dữ liệu khi người dùng yêu cầu và ngừng thu thập khi họ rút consent. Lấy mẫu với event tần suất cao (cuộn, frame) nhưng không bao giờ lấy mẫu event quan trọng như mua hàng, và đo chính chi phí của hệ thống analytics (kích thước hàng đợi, tỉ lệ gửi lỗi). abstract interface class AnalyticsSink {
  Future<bool> send(List<AnalyticsEvent> batch); // true: server đã xác nhận
}

class AnalyticsClient {
  AnalyticsClient(this._queue, this._sink, {this.batchSize = 20});
  final EventQueue _queue; // bền: SQLite hoặc file, không chỉ giữ trong RAM
  final AnalyticsSink _sink;
  final int batchSize;
  bool _flushing = false;

  void track(String name, [Map<String, Object?> props = const {}]) {
    final event = AnalyticsEvent(
      id: const Uuid().v4(), // server dùng id để loại event trùng khi retry
      name: name,
      props: scrubPii(props), // bỏ dữ liệu cá nhân trước khi ghi
      clientTime: DateTime.now().toUtc(),
      sessionId: _session.id,
    );
    unawaited(_queue.add(event).then((_) => _flushIfNeeded()));
  }

  Future<void> flush() async {
    if (_flushing) return;
    _flushing = true;
    try {
      while (true) {
        final batch = await _queue.peek(batchSize);
        if (batch.isEmpty) break;
        if (!await _sink.send(batch)) break; // lỗi: giữ nguyên trong hàng đợi, thử lại sau với backoff
        await _queue.remove(batch.map((e) => e.id)); // chỉ xoá sau khi server xác nhận
      }
    } finally {
      _flushing = false;
    }
  }
}
