static và final trong Java nghĩa là gì? Vì sao giữ Activity hoặc View trong một field static lại gây memory leak?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
static gắn member vào class chứ không vào từng instance: chỉ có một bản dùng chung, truy cập không cần tạo object, và sống suốt thời gian class còn được nạp, thường là cả vòng đời process. final nghĩa là không đổi sau khi gán: biến final chỉ gán một lần (tham chiếu không đổi nhưng object bên trong vẫn có thể bị sửa), method final không được override, class final không được kế thừa (như String); static final tạo thành hằng số. Vì field static sống lâu hơn mọi Activity, nếu lưu Activity, Context hay một View (view luôn giữ tham chiếu tới Activity chứa nó) vào đó thì Garbage Collector không thu hồi được Activity đã bị huỷ, chẳng hạn sau khi xoay màn hình, kéo theo cả cây view và bitmap của nó: memory leak. Cần context sống lâu thì dùng applicationContext; nếu bắt buộc giữ thì dùng WeakReference hoặc gỡ tham chiếu ở onDestroy. companion object và object của Kotlin có rủi ro tương tự.
public class MainActivity extends AppCompatActivity {
  static final int MAX_RETRY = 3;        // hằng số: static final

  // SAI: field static sống đến hết process, giữ luôn cả Activity đã destroy
  static TextView sTitleView;

  @Override
  protected void onCreate(Bundle savedInstanceState) {
    super.onCreate(savedInstanceState);
    setContentView(R.layout.activity_main);
    sTitleView = findViewById(R.id.title); // leak sau mỗi lần xoay màn hình
  }
}
