PR của bạn đổi một dòng style và CI fail vì 14 snapshot bị lệch; đồng nghiệp bảo cứ chạy jest -u cho qua. Snapshot test khác test hành vi bằng React Native Testing Library ở đâu, khi nào snapshot hữu ích, và vì sao snapshot lớn dần trở nên vô dụng?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Snapshot test (toMatchSnapshot) lưu lại cây render lần đầu rồi so với các lần sau: viết nhanh và bắt được thay đổi ngoài ý muốn, nhưng chỉ nói "khác trước" chứ không nói "đúng hay sai". Đổi style, bọc thêm một View, đổi tên prop đều làm vỡ dù hành vi không đổi. Snapshot cả màn hình tạo ra diff hàng trăm dòng không ai đọc, dẫn tới phản xạ jest -u, và khi có lỗi thật thì nó cũng bị "cập nhật cho qua". Test hành vi với RNTL kiểm theo cách người dùng thấy và thao tác (getByRole, getByText, press, findBy* để chờ UI): câu hỏi là "bấm Đăng nhập khi email trống thì có báo lỗi không", nên bền vững khi refactor bên trong. Snapshot hữu ích với output nhỏ, ổn định và ít đổi: kết quả hàm thuần như formatPrice, file cấu hình, một component trình bày nhỏ (icon, badge); dùng toMatchInlineSnapshot để giá trị mong đợi nằm ngay trong test. Quy tắc: snapshot nhỏ, review diff như review code, không bấm cập nhật khi chưa đọc, còn thay đổi hành vi thì viết assertion rõ ràng.
// Dễ vỡ, ít giá trị: snapshot cả màn hình
it('renders', () => {
  expect(render(<CheckoutScreen />).toJSON()).toMatchSnapshot();
});

// Kiểm hành vi người dùng thấy
it('báo lỗi khi bấm Đăng nhập với email trống', async () => {
  const user = userEvent.setup();
  render(<LoginScreen />);

  await user.press(screen.getByRole('button', { name: 'Đăng nhập' }));

  expect(await screen.findByText('Vui lòng nhập email')).toBeOnTheScreen();
});

// Snapshot hợp lý: output nhỏ, ổn định, giá trị mong đợi nằm ngay trong test
it('format giá', () => {
  expect(formatPrice(1250000)).toMatchInlineSnapshot(`"1.250.000 ₫"`);
});
