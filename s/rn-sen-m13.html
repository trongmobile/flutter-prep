Lớp API client dùng withTimeout dưới đây để báo lỗi nếu server không trả lời sau 5 giây. Khi timeout xảy ra, request fetch ra sao?

function withTimeout<T>(p: Promise<T>, ms: number): Promise<T> {
  return Promise.race([
    p,
    new Promise<T>((_, reject) =>
      setTimeout(() => reject(new Error('timeout')), ms),
    ),
  ]);
}

const res = await withTimeout(fetch(url), 5000);
  1. AVẫn chạy ngầm tới khi xong; muốn huỷ thật phải dùng AbortController
  2. BBị huỷ, vì Promise.race tự huỷ promise thua cuộc khi có kết quả
  3. CBị reject với AbortError ngay khi timer bắn ra lỗi timeout
  4. DBị GC thu hồi ngay nên kết nối mạng được đóng và response bị bỏ

Đáp án đúng: A
Promise không có cơ chế huỷ: Promise.race chỉ settle theo promise xong trước, còn fetch vẫn tiếp tục chiếm kết nối, băng thông và chạy các then phía sau. Truyền signal của AbortController vào fetch và gọi abort() khi hết giờ (đồng thời clearTimeout khi request xong trước) mới thực sự huỷ request.
