Unit test là gì? Viết test JUnit cho một hàm tính tiền thế nào, và vì sao hàm thuần (pure function) dễ test hơn code gắn với Activity?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Unit test kiểm tra một đơn vị nhỏ (một hàm, một class) một cách tự động, chạy nhanh và độc lập. Test đặt ở src/test chạy trực tiếp trên JVM của máy dev nên không cần máy ảo; còn src/androidTest (instrumented test) chạy trên thiết bị hoặc emulator, dùng cho thứ cần Android thật như UI hay database. Với JUnit, @Test đánh dấu một test, assertEquals(expected, actual) so sánh kết quả (giá trị mong đợi đứng trước), @Before chuẩn bị dữ liệu chung. Mỗi test nên theo mẫu Arrange–Act–Assert, kiểm một điều và đặt tên mô tả hành vi, đồng thời phải thử cả trường hợp biên (rỗng, 0, giá trị âm), không chỉ đường chạy đẹp. Hàm thuần có kết quả chỉ phụ thuộc đầu vào, không đụng Context, UI, mạng hay thời gian, nên chỉ cần gọi và so sánh; logic nằm trong Activity thì phải dựng cả framework mới test được, đó là lý do nên tách logic ra class riêng. Bẫy: test JVM mà gọi Log.d hay API của framework thường lỗi Method ... not mocked.
// src/main: hàm thuần, kết quả chỉ phụ thuộc đầu vào
fun calculateTotal(prices: List<Int>, discountPercent: Int): Int {
  require(discountPercent in 0..100) { "Giảm giá phải từ 0 đến 100" }
  val sum = prices.sum()
  return sum - sum * discountPercent / 100
}

// src/test: chạy trên JVM của máy dev, không cần emulator
class PriceCalculatorTest {
  @Test
  fun `giảm 10 phần trăm cho đơn 200`() {
    assertEquals(180, calculateTotal(listOf(100, 100), 10))
  }

  @Test
  fun `giỏ rỗng thì tổng bằng 0`() {
    assertEquals(0, calculateTotal(emptyList(), 50))
  }

  @Test(expected = IllegalArgumentException::class)
  fun `giảm giá ngoài khoảng cho phép thì ném lỗi`() {
    calculateTotal(listOf(100), 120)
  }
}
