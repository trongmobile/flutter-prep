Công ty có 3 app RN (khách hàng, tài xế, merchant) dùng chung nhiều UI và logic. Bạn tổ chức monorepo thế nào, và những bẫy riêng của RN trong monorepo là gì?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Tôi dùng workspace của package manager (pnpm hoặc Yarn workspaces), thêm Turborepo/Nx để cache và chỉ chạy task bị ảnh hưởng. Cấu trúc: apps/* cho từng app; packages/* cho design system (token, component), API client có type, utils và các feature package có ranh giới rõ, chỉ export qua entry public. Bẫy riêng của RN: thứ nhất, cả repo chỉ được có một bản react và react-native — hai bản react gây lỗi 'Invalid hook call', hai bản thư viện native gây đăng ký trùng hoặc autolinking sai — nên package dùng chung khai báo chúng là peerDependencies và ép version thống nhất ở root. Thứ hai, Metro phải được cấu hình để thấy code ngoài thư mục app (watchFolders, resolve node_modules ở root; Expo tự cấu hình việc này trong các SDK gần đây). Thứ ba, thư viện có native code nên được khai báo trong package.json của app để autolinking nhận đúng. Cuối cùng, các app nên đi cùng phiên bản RN để chia sẻ được native dependency, nên cần lịch nâng cấp chung.
// apps/driver/metro.config.js
const path = require('path');
const { getDefaultConfig } = require('@react-native/metro-config');

const root = path.resolve(__dirname, '../..');
const config = getDefaultConfig(__dirname);

config.watchFolders = [root]; // thấy được packages/*
config.resolver.nodeModulesPaths = [
  path.resolve(__dirname, 'node_modules'),
  path.resolve(root, 'node_modules'),
];

module.exports = config;
