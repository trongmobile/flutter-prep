TypeScript 5 với strict bật (không bật noUncheckedIndexedAccess). Dòng nào dưới đây báo lỗi biên dịch?

const a: Record<string, string> = { home: '/', cart: '/cart' };
const b = { home: '/', cart: '/cart' } satisfies Record<string, string>;

a.profile.length; // (1)
b.profile.length; // (2)
  1. ACả hai dòng, vì cả hai object đều không khai báo thuộc tính nào tên là profile
  2. BChỉ dòng (2): satisfies giữ kiểu cụ thể của object nên profile không tồn tại
  3. CChỉ dòng (1): annotation Record<string, string> là kiểu chặt hơn so với satisfies
  4. DKhông dòng nào, vì satisfies chỉ là cách viết khác của annotation kiểu thông thường
Xem đáp án
Đáp án đúng: B
Annotation : Record<string, string> biến kiểu của a thành đúng Record<string, string>, một kiểu có index signature, nên a.profile hợp lệ (kiểu string) dù thực tế không tồn tại và sẽ ném TypeError lúc chạy. satisfies (TypeScript 4.9 trở lên) chỉ kiểm tra object khớp với kiểu đó nhưng vẫn giữ kiểu suy luận { home: string; cart: string }, nên b.profile báo lỗi và keyof typeof b chỉ là 'home' | 'cart'. satisfies hoàn toàn là kiểm tra lúc biên dịch. Bật noUncheckedIndexedAccess thì a.profile thành string | undefined và dòng (1) cũng lỗi, nhưng đó là cờ riêng.
