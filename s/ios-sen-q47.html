PM muốn hiện trạng thái giao hàng trên Lock Screen và Dynamic Island, cùng một widget "đơn gần nhất" trên Home Screen. Live Activity và widget cập nhật dữ liệu khác nhau thế nào, và bạn thiết kế kiến trúc ra sao để cập nhật kịp lúc mà không vượt giới hạn của hệ thống?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Widget (WidgetKit) chạy theo timeline: bạn cung cấp các entry theo thời điểm, hệ thống quyết định lúc nạp lại theo ngân sách và có thể trì hoãn; WidgetCenter.shared.reloadTimelines(ofKind:) chỉ là một yêu cầu và cũng bị tính vào ngân sách. Widget không chạy code liên tục, dữ liệu dùng chung với app qua App Group. Live Activity (ActivityKit) hợp với sự kiện có điểm đầu và điểm cuối như một chuyến giao hàng: ActivityAttributes gồm phần cố định cộng ContentState kiểu Codable đổi được; app khởi tạo bằng Activity.request, cập nhật bằng activity.update khi còn chạy, còn khi app bị suspend thì server cập nhật qua APNs: mỗi activity có push token riêng (pushTokenUpdates) để gửi lên server, push dùng apns-push-type: liveactivity và payload có event cùng content-state; từ iOS 17.2 có push-to-start để server bắt đầu activity khi app không chạy. Giới hạn: tổng dữ liệu của attributes và state khoảng 4KB, activity sống tối đa khoảng 8 giờ rồi bị hệ thống kết thúc, push có ngân sách (priority cao tốn ngân sách nên chỉ dùng cho thay đổi quan trọng), và người dùng có thể tắt Live Activities nên phải kiểm tra areActivitiesEnabled. Cập nhật rất dày cần khai NSSupportsLiveActivitiesFrequentUpdates, nhưng người dùng vẫn có thể giới hạn. Về thiết kế: ActivityAttributes, ContentState và các view dùng chung đặt trong một Swift Package nhỏ cho cả app lẫn Widget Extension; UI chỉ render state, không gọi mạng; đồng hồ đếm ngược dùng Text(timerInterval:) hay Text(date, style: .timer) để khỏi phải push từng giây; gọi activity.end khi đơn hoàn tất; và đừng đưa thông tin nhạy cảm lên Lock Screen.
import ActivityKit

struct DeliveryAttributes: ActivityAttributes {
  enum Status: String, Codable { case preparing, onTheWay, arrived }

  struct ContentState: Codable, Hashable {
    var status: Status
    var eta: Date
  }

  let orderID: String // phần cố định, đặt một lần lúc request
}

func startTracking(orderID: String, eta: Date) throws {
  guard ActivityAuthorizationInfo().areActivitiesEnabled else { return } // user có thể tắt

  let state = DeliveryAttributes.ContentState(status: .preparing, eta: eta)
  let content = ActivityContent(state: state, staleDate: eta.addingTimeInterval(600))
  let activity = try Activity.request(
    attributes: DeliveryAttributes(orderID: orderID),
    content: content,
    pushType: .token // cho phép server cập nhật qua APNs
  )

  // Thực tế nên giữ handle của Task này để huỷ khi activity kết thúc
  Task {
    for await token in activity.pushTokenUpdates {
      let hex = token.map { String(format: "%02x", $0) }.joined()
      await api.registerActivityToken(orderID: orderID, token: hex)
    }
  }
}
