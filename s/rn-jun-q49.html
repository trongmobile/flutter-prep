Lần đầu bạn tự build bản release gửi QA: file Android vẫn ký bằng debug key nên không đưa lên Play Store được, iOS báo thiếu provisioning profile, và một đồng nghiệp lỡ commit file .keystore lên Git. Các bước build release cơ bản cho Android và iOS là gì, và xử lý keystore thế nào?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Android: tạo upload keystore một lần bằng keytool, khai báo signingConfigs.release trong android/app/build.gradle và đọc đường dẫn, mật khẩu từ ~/.gradle/gradle.properties hoặc biến môi trường trên CI, tuyệt đối không viết vào repo. Template React Native mặc định ký bản release bằng debug keystore nên phải đổi trước khi lên store. Mỗi lần upload phải tăng versionCode (số nguyên) và đặt versionName (hiển thị). Build ./gradlew bundleRelease ra AAB cho Play, hoặc assembleRelease ra APK để QA cài trực tiếp. Nên bật Play App Signing để Google giữ khoá ký chính, nhưng vẫn phải sao lưu upload key cẩn thận. Bản release dùng Hermes bytecode; bật R8/ProGuard (enableProguardInReleaseBuilds) thì cần test kỹ vì dễ thiếu rule giữ class cho thư viện native. iOS: cần tài khoản Apple Developer, bundle id, certificate và provisioning profile (cách đơn giản là bật Automatically manage signing trong Xcode), tăng marketing version và build number mỗi lần upload, chọn scheme Release rồi Product → Archive và đẩy lên TestFlight. Với Expo thì eas build quản lý credentials hộ. Keystore đã commit coi như lộ: tạo upload key mới và xin Google đổi trong Play Console, thêm *.keystore/*.jks vào .gitignore; xoá khỏi lịch sử Git không đủ vì các bản clone khác vẫn còn file đó. Riêng debug.keystore của template công khai nên không sao.
