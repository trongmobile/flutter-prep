Khi nào đặt test ở src/test, khi nào ở src/androidTest? Viết một UI test Compose cơ bản cho màn đăng nhập thế nào, và vì sao UI test hay chập chờn?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
src/test là local unit test chạy trên JVM của máy dev: nhanh, không có Android thật, dùng cho logic thuần như ViewModel, use case, mapper. src/androidTest là instrumented test chạy trên thiết bị hoặc emulator, có Context, Activity, Room và UI thật, dùng cho test UI (Espresso với View, compose-ui-test với Compose) và tích hợp Room; chậm hơn nhiều nên chỉ viết cho luồng quan trọng như đăng nhập, thanh toán. Với Compose, dùng createComposeRule(), dựng màn bằng setContent { }, tìm node bằng onNodeWithTag/onNodeWithText, tương tác bằng performClick()/performTextInput(), kiểm tra bằng assertIsDisplayed(); rule tự đồng bộ với recomposition nên không cần Thread.sleep. Test chập chờn thường do việc bất đồng bộ ngoài tầm của rule (gọi mạng thật) hoặc animation: dùng fake repository hay MockWebServer, tắt animation trên máy test, với View dùng IdlingResource của Espresso.
class LoginScreenTest {
    @get:Rule
    val composeRule = createComposeRule()

    @Test
    fun emptyEmail_showsError() {
        composeRule.setContent { LoginScreen(onLoggedIn = {}) }

        composeRule.onNodeWithTag("login_button").performClick()

        composeRule.onNodeWithText("Vui lòng nhập email").assertIsDisplayed()
    }
}
