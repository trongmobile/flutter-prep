Nút 'Đặt hàng' gọi bloc.add(SubmitOrder()), handler await API tạo đơn rồi mới emit. Người dùng bấm hai lần liên tiếp rất nhanh và hệ thống tạo ra hai đơn. Giá trị transformer nào của bloc_concurrency xử lý đúng nhất?

on<SubmitOrder>(
  (event, emit) async {
    emit(state.copyWith(status: Status.loading));
    await orderRepository.create(event.cart);
    emit(state.copyWith(status: Status.success));
  },
  transformer: ???,
);
  1. Adroppable(): bỏ qua event mới khi event hiện tại còn đang xử lý
  2. Bsequential(): xếp hàng các event rồi xử lý lần lượt từng cái một, không chồng nhau
  3. Crestartable(): hủy event đang chạy rồi bắt đầu lại với event mới nhất vừa tới
  4. Dconcurrent(): xử lý đồng thời các event, mỗi event chạy độc lập với nhau

Đáp án đúng: A
droppable() bỏ qua mọi event đến trong lúc handler đang chạy, nên bấm đúp chỉ tạo một đơn. sequential() vẫn xử lý event thứ hai ngay sau khi event đầu xong, nên vẫn tạo hai đơn (chỉ là không chồng nhau). restartable() chỉ hủy phần emit của handler cũ chứ không hủy lời gọi API đã gửi đi (Future không có cơ chế hủy), nên request vẫn được gửi hai lần; nó hợp với ô tìm kiếm khi chỉ quan tâm kết quả mới nhất. concurrent() (mặc định) cho hai handler chạy song song. Server cũng nên chống trùng bằng idempotency key vì client không thể chặn tuyệt đối.
