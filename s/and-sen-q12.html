App có khoảng 20 feature module. Bạn đặt quy tắc phụ thuộc giữa các module thế nào? Feature A cần mở màn hình của feature B thì làm sao để A không phụ thuộc B?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Quy tắc tôi đặt: :app phụ thuộc mọi feature; feature chỉ phụ thuộc các module :core:* (designsystem, data, domain, network…), tuyệt đối không phụ thuộc feature khác; :core không biết gì về feature. Nhờ vậy các feature build song song, sửa feature A không làm recompile B, và không bao giờ có vòng phụ thuộc. Để điều hướng chéo, feature A chỉ expose callback như onOpenProfile, còn :app — nơi duy nhất biết mọi feature — nối callback đó tới route của B. Nếu cần chia sẻ contract (route, interface service), tách feature thành :feature:b:api nhẹ và :feature:b:impl; A chỉ được phụ thuộc b:api, còn implementation được nối qua DI ở :app. Quy tắc này phải được kiểm tra tự động trong CI (plugin kiểm tra module graph hoặc custom Gradle task), không chỉ dựa vào review.
// :feature:feed — không biết gì về feature profile
fun NavGraphBuilder.feedScreen(onOpenProfile: (userId: String) -> Unit) {
  composable<FeedRoute> { FeedScreen(onUserClick = onOpenProfile) }
}

// :app — nơi duy nhất ghép các feature với nhau
NavHost(navController, startDestination = FeedRoute) {
  feedScreen(onOpenProfile = { id -> navController.navigate(ProfileRoute(id)) })
  profileScreen(onBack = { navController.popBackStack() })
}
