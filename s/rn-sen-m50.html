Nút tim dùng optimistic update như dưới. QA thấy thỉnh thoảng nút bật đỏ rồi nháy về trạng thái cũ vài trăm ms mới đỏ lại, nhất là khi feed đang refetch (pull-to-refresh). Thiếu bước nào trong onMutate?

const like = useMutation({
  mutationFn: (postId: string) => api.likePost(postId),
  onMutate: async (postId) => {
    const previous = queryClient.getQueryData<Post[]>(['feed']);
    queryClient.setQueryData<Post[]>(['feed'], (old) =>
      old?.map((p) => (p.id === postId ? { ...p, liked: true } : p)),
    );
    return { previous };
  },
  onError: (_err, _postId, ctx) => {
    queryClient.setQueryData(['feed'], ctx?.previous);
  },
  onSettled: () => queryClient.invalidateQueries({ queryKey: ['feed'] }),
});
  1. AThêm retry: false cho mutation để request like không bị gửi lặp lại khi mạng chậm
  2. BGọi await queryClient.cancelQueries({ queryKey: ['feed'] }) để huỷ refetch đang bay trước khi ghi cache
  3. CĐặt staleTime: Infinity cho query ['feed'] để cache không bao giờ bị refetch tự động nữa khi mở màn hình
  4. DGọi invalidateQueries ngay trong onMutate để cache luôn khớp với dữ liệu mới nhất từ server trả về cho client

Đáp án đúng: B
Nếu một refetch của ['feed'] đang chạy khi user bấm, nó sẽ trả về dữ liệu chụp trước lúc like và ghi đè bản optimistic vừa đặt, cho tới khi onSettled refetch lại mới đúng. Vì vậy tài liệu của TanStack Query yêu cầu await queryClient.cancelQueries(...) trong onMutate trước setQueryData. invalidateQueries trong onMutate còn kích hoạt thêm refetch có thể trả dữ liệu trước khi server xử lý like; retry và staleTime không liên quan tới việc dữ liệu cũ ghi đè.
