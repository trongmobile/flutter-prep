Sandbox của app Android là gì? Internal storage và external storage khác nhau thế nào, permission "normal" khác "dangerous" ra sao, và xin quyền lúc chạy cần lưu ý gì?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Mỗi app chạy trong process riêng với Linux user id riêng (sandbox), nên app khác không đọc được dữ liệu của bạn trừ khi bạn chủ động chia sẻ qua ContentProvider hay Intent. Internal storage (filesDir, cacheDir, database, DataStore) là riêng tư và bị xoá khi gỡ app. External storage thì người dùng hoặc app khác có thể truy cập: thư mục riêng của app trên external (getExternalFilesDir) không cần xin quyền, còn vùng chung như ảnh hay Downloads chịu scoped storage từ Android 10, nên dùng Photo Picker, MediaStore hoặc Storage Access Framework thay vì xin quyền đọc toàn bộ. Permission normal (INTERNET, VIBRATE...) tự được cấp khi cài, chỉ cần khai báo trong manifest. Permission dangerous (CAMERA, ACCESS_FINE_LOCATION, READ_CONTACTS, POST_NOTIFICATIONS từ API 33) phải khai báo và xin lúc chạy; người dùng có thể từ chối hoặc thu hồi bất cứ lúc nào, nên kiểm tra quyền trước mỗi lần dùng và xử lý trường hợp bị từ chối mà không crash. Chỉ xin quyền khi tính năng cần, kèm giải thích. Không lưu mật khẩu hay token dạng plain text và không log dữ liệu nhạy cảm.
// Internal storage: riêng tư, app khác không đọc được
val file = File(filesDir, "profile.json")

// External riêng của app: không cần xin quyền, vẫn bị xoá khi gỡ app
val photoDir = getExternalFilesDir(Environment.DIRECTORY_PICTURES)

// Quyền dangerous: khai báo trong manifest, rồi xin lúc chạy
private val requestCamera =
  registerForActivityResult(ActivityResultContracts.RequestPermission()) { granted ->
    if (granted) openCamera() else showCameraDeniedMessage()   // bị từ chối vẫn phải chạy được
  }

fun onTakePhotoClicked() {
  val granted = ContextCompat.checkSelfPermission(this, Manifest.permission.CAMERA) ==
    PackageManager.PERMISSION_GRANTED
  if (granted) openCamera() else requestCamera.launch(Manifest.permission.CAMERA)
}

  • Đồng nghiệp hardcode một API key trong code rồi commit lên Git. Có những rủi ro gì, bạn xử lý ngay và về lâu dài thế nào? Đưa key vào BuildConfig có an toàn không? Junior
  • Server staging dùng chứng chỉ tự ký nên OkHttp báo SSLHandshakeException. Một đồng nghiệp "sửa" bằng cách tạo X509TrustManager không kiểm tra gì và hostnameVerifier { _, _ -> true }, app chạy ngay. Vì sao tuyệt đối không được làm vậy, và cách xử lý đúng khi cần gọi server staging? Junior
  • Review PR thấy: Activity khai báo android:exported="true" không cần thiết, PendingIntent tạo không có cờ, WebView bật addJavascriptInterface cho nội dung bên ngoài, và token lưu trong SharedPreferences dạng thường. Những lỗi bảo mật Android phổ biến này nguy hiểm thế nào và sửa ra sao? Middle
