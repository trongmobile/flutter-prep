Khi nào việc đánh dấu @unchecked Sendable như class cache dưới đây là chấp nhận được?

final class ImageDataCache: @unchecked Sendable {
  private let lock = NSLock()
  private var storage: [URL: Data] = [:]

  func data(for url: URL) -> Data? {
    lock.lock(); defer { lock.unlock() }
    return storage[url]
  }

  func store(_ data: Data, for url: URL) {
    lock.lock(); defer { lock.unlock() }
    storage[url] = data
  }
}
  1. AKhi state mutable được lock bảo vệ mà compiler không tự kiểm chứng
  2. BKhi muốn tắt cảnh báo nhanh, vì runtime vẫn tự kiểm tra data race
  3. CKhi class đã là final, vì như vậy là đủ an toàn giữa các thread
  4. DKhi class chỉ được dùng trên main thread, dù bên trong không có lock
Xem đáp án
Đáp án đúng: A
@unchecked nghĩa là bạn tự cam kết thread safety: compiler bỏ qua kiểm tra và runtime cũng không kiểm tra gì thêm. Nó hợp lý cho class bọc state bằng lock hoặc queue nội bộ; còn final chỉ là một điều kiện để compiler kiểm tra Sendable, không làm state mutable trở nên an toàn.
