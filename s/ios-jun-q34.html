Màn danh sách SwiftUI có @State var selected: Product? và @State var showDetail = false; bấm một dòng thì gán selected = product; showDetail = true, còn sheet viết .sheet(isPresented: $showDetail) { DetailView(product: selected!) }. Thỉnh thoảng sheet hiện sản phẩm cũ hoặc crash vì nil. Vì sao, và .sheet(item:) giải quyết thế nào?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Cách trên tách một ý (đang xem sản phẩm nào) thành hai state độc lập: chỉ cần quên gán, gán sai thứ tự, hoặc đóng sheet mà selected vẫn giữ giá trị cũ là hai state lệch nhau, và selected! gặp nil thì crash. .sheet(item: $selected) dùng một nguồn duy nhất: selected khác nil thì sheet hiện, và closure nhận luôn product đã unwrap nên không cần force unwrap. Khi sheet đóng, dù bấm nút hay vuốt xuống, SwiftUI tự gán selected về nil nên không còn trạng thái thừa. Kiểu dữ liệu phải conform Identifiable. Mẫu này áp dụng tương tự cho fullScreenCover(item:). Nguyên tắc chung là biểu diễn trạng thái bằng một giá trị optional (nil nghĩa là không hiện) thay vì một cờ Bool kèm dữ liệu rời.
struct Product: Identifiable {
  let id: Int
  let name: String
}

struct ProductListView: View {
  let products: [Product]
  @State private var selected: Product? // nil = không hiện sheet

  var body: some View {
    List(products) { product in
      Button(product.name) { selected = product }
    }
    .sheet(item: $selected) { product in // product không phải Optional
      ProductDetailView(product: product)
    }
  }
}
