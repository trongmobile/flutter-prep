Unit test dưới dùng MockK nhưng chưa stub findName. Khi chạy test này, kết quả là gì?

interface UserRepository {
  fun findName(id: Long): String
}

class Greeter(private val repo: UserRepository) {
  fun greet(id: Long) = "Xin chào ${repo.findName(id)}"
}

class GreeterTest {
  private val repo = mockk<UserRepository>()

  @Test
  fun greetsUser() {
    val text = Greeter(repo).greet(1L)
    assertEquals("Xin chào An", text)
  }
}
  1. AFail với MockKException: mock chưa có câu trả lời cho lời gọi findName(1)
  2. BFail ở assertEquals: findName chưa stub trả chuỗi rỗng nên text là Xin chào
  3. CFail với NullPointerException vì mock trả null cho hàm chưa được stub
  4. DLỗi compile vì mockk<UserRepository>() chỉ dùng được với class, không dùng với interface
Xem đáp án
Đáp án đúng: A
mockk<T>() mặc định là strict mock: gọi hàm chưa được stub bằng every { ... } returns ... sẽ ném MockKException (no answer found for ...) ngay tại lời gọi, nên test fail ở đó chứ chưa tới assertEquals. Chỉ mockk<T>(relaxed = true) mới trả giá trị mặc định (chuỗi rỗng, 0...), nhưng relaxed mock dễ che lỗi quên stub nên hãy stub rõ ràng: every { repo.findName(1L) } returns "An". MockK mock được cả interface lẫn class và không trả null cho kiểu non-null như String.
