Dự án React Native mới tạo đã có sẵn Jest. Viết test đầu tiên cho hàm formatPrice(120000) thế nào? Vì sao hàm thuần dễ test hơn component, và snapshot test là gì, có hạn chế gì?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Jest là test runner mặc định của React Native: template có sẵn cấu hình, file test đặt tên *.test.ts(x) hoặc nằm trong __tests__/, chạy bằng npm test. Một test gồm test('mô tả', () => { ... }) (hoặc it), nhóm bằng describe, kiểm tra bằng expect(actual).toBe(expected); toBe so sánh bằng Object.is, còn toEqual so sánh sâu cho object và mảng, toThrow cho lỗi. Hàm thuần (cùng đầu vào luôn ra cùng kết quả, không đụng mạng, thời gian hay state bên ngoài) chỉ cần gọi rồi so kết quả, không phải mock gì; nên tách logic như định dạng tiền, validate email, tính tổng giỏ hàng ra hàm riêng thay vì viết thẳng trong component. Test component phải render, phải mock module native nên nặng hơn nhiều. Snapshot test (toMatchSnapshot()) lưu kết quả render vào file .snap ở lần chạy đầu rồi so sánh ở các lần sau. Hạn chế: chỉ cần đổi UI hợp lệ là vỡ, nên dễ thành thói quen chạy jest -u mà không đọc diff; snapshot lớn rất khó review; và nó không kiểm tra hành vi (bấm nút có làm đúng việc không). Chỉ nên dùng cho đầu ra nhỏ, ổn định.
// formatPrice.ts
export function formatPrice(value: number): string {
  const digits = Math.round(value).toString().replace(/\B(?=(\d{3})+(?!\d))/g, '.');
  return `${digits} ₫`;
}

// formatPrice.test.ts
import { formatPrice } from './formatPrice';

describe('formatPrice', () => {
  test('thêm dấu chấm ngăn cách hàng nghìn', () => {
    expect(formatPrice(120000)).toBe('120.000 ₫');
  });

  test('làm tròn số lẻ', () => {
    expect(formatPrice(1999.6)).toBe('2.000 ₫');
  });

  test('số nhỏ hơn 1000 không có dấu chấm', () => {
    expect(formatPrice(0)).toBe('0 ₫');
  });
});
