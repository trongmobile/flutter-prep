Hub lưu các listener vào một mảng như dưới. Sau khi screen = nil, điều gì đúng và nên sửa thế nào?

protocol Listener: AnyObject {
  func didUpdate()
}

final class Hub {
  private var listeners: [Listener] = []
  func add(_ listener: Listener) { listeners.append(listener) }
}

final class Screen: Listener {
  func didUpdate() {}
  deinit { print("Screen deinit") }
}

let hub = Hub()
var screen: Screen? = Screen()
hub.add(screen!)
screen = nil
print("done")
  1. AIn Screen deinit rồi done, vì : AnyObject làm Hub giữ listener bằng tham chiếu yếu
  2. BChỉ in done; Hub vẫn giữ Screen, cần wrapper weak hoặc NSHashTable.weakObjects()
  3. CChỉ in done; sửa bằng cách khai báo lại thành private var listeners: [weak Listener] trong Hub
  4. DCrash vì Hub giữ tham chiếu tới object đã bị giải phóng sau khi screen = nil
Xem đáp án
Đáp án đúng: B
Mảng [Listener] giữ strong reference, nên sau screen = nil object vẫn sống nhờ Hub và deinit không chạy (đây chính là kiểu leak của multicast delegate). : AnyObject chỉ giới hạn protocol cho class chứ không làm tham chiếu thành yếu, và Swift không có cú pháp [weak Listener] vì weak chỉ áp dụng cho biến hoặc property. Cách đúng là bọc từng listener trong struct WeakBox { weak var value: Listener? } (và lọc phần tử nil khi duyệt) hoặc dùng NSHashTable<AnyObject>.weakObjects().
