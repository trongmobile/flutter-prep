Bạn dùng struct Product làm phần tử của Set và làm key của Dictionary, compiler báo Type 'Product' does not conform to protocol 'Hashable'. Khi nào compiler tự sinh Equatable/Hashable, khi nào phải tự viết, và Comparable, Identifiable liên quan thế nào?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Với struct và enum, chỉ cần khai báo : Hashable (trong định nghĩa kiểu hoặc extension cùng file) là compiler tự sinh == và hash(into:), miễn mọi stored property hay associated value đều đã Hashable; lỗi trên nghĩa là chưa khai báo, hoặc có một property không conform (như [String: Any]). Class thì không được sinh tự động. Phải tự viết khi 'cùng một đối tượng' chỉ xét theo một phần dữ liệu, ví dụ id: để compiler sinh theo mọi field thì cùng sản phẩm mà đổi giá đã thành hai phần tử khác nhau trong Set. Luật cần nhớ: hai giá trị == thì phải có cùng hash, nên đã so theo id thì chỉ băm id, vi phạm sẽ làm Set/Dictionary tìm sai. Hashable cũng là điều kiện của item trong UICollectionViewDiffableDataSource: băm theo mọi field thì sửa một field là item bị coi như item mới (xoá rồi chèn, mất animation và vị trí cuộn), nên dùng id làm item identifier và reconfigureItems khi nội dung đổi. Identifiable chỉ cần id: Hashable cho ForEach/List, không kéo theo Equatable. Comparable chỉ cần tự viết <, các toán tử còn lại có sẵn; enum không có raw value được sinh < theo thứ tự khai báo case.
struct Product: Hashable, Identifiable {
  let id: Int
  var name: String
  var price: Int

  // So sánh và băm theo id: đổi giá vẫn là cùng một sản phẩm
  static func == (lhs: Product, rhs: Product) -> Bool { lhs.id == rhs.id }
  func hash(into hasher: inout Hasher) { hasher.combine(id) }
}

enum Priority: Comparable { case low, medium, high } // compiler sinh `<` theo thứ tự case

var cart: Set<Product> = [Product(id: 1, name: "Áo", price: 200)]
cart.insert(Product(id: 1, name: "Áo", price: 250))  // bị bỏ qua vì đã có id 1
print(cart.count, Priority.low < .high)              // 1 true
