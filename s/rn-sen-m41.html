Màn Home bắn 5 request song song đúng lúc access token vừa hết hạn. Server dùng refresh token rotation: mỗi refresh token chỉ dùng được một lần, bị dùng lại sẽ bị coi là đã lộ và thu hồi cả phiên đăng nhập. Với interceptor dưới đây, điều gì xảy ra và nên sửa thế nào?

api.interceptors.response.use(undefined, async (error) => {
  const original = error.config;
  if (error.response?.status === 401 && !original._retry) {
    original._retry = true;
    const refreshToken = await tokenStore.getRefreshToken();
    const { data } = await axios.post('/auth/refresh', { refreshToken });
    await tokenStore.save(data);
    original.headers.Authorization = `Bearer ${data.accessToken}`;
    return api(original);
  }
  throw error;
});
  1. AChỉ request đầu tiên được retry vì _retry dùng chung cho cả 5 request; nên gắn cờ này lên instance api
  2. BAxios tự gộp các lời gọi /auth/refresh giống nhau thành một nên không có vấn đề; chỉ cần thêm timeout cho request refresh
  3. CCả 5 request cùng refresh bằng một refresh token nên các lần sau bị từ chối; hãy cho chúng dùng chung một promise refresh
  4. D5 callback chạy lần lượt nên request sau luôn thấy token mới và không có race; chuyển refresh token sang AsyncStorage cho nhanh hơn

Đáp án đúng: C
Các response 401 về gần như cùng lúc, mỗi interceptor đều đọc cùng một refresh token (chưa ai kịp lưu token mới) rồi gọi /auth/refresh. Lần đầu thành công và xoay token; các lần sau dùng lại token đã bị dùng nên bị từ chối, thậm chí kích hoạt thu hồi phiên và user bị đăng xuất. _retry nằm trên config của từng request nên không dùng chung, và Axios không tự gộp request. Cách đúng là giữ một promise refresh duy nhất (single-flight): request nào gặp 401 mà thấy refresh đang chạy thì chờ promise đó rồi retry với token mới.
