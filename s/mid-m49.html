PR bị reviewer chặn vì file firebase_options.dart (do flutterfire configure sinh ra) chứa apiKey và sắp được commit lên repo công khai. Nhận định nào đúng?

  1. AKey này cấp quyền đọc/ghi mọi dữ liệu của project nên phải giấu và chỉ nạp lúc build
  2. BChỉ an toàn khi repo private; repo public thì phải rotate key sau mỗi lần release
  3. CKey chỉ định danh project, không phải secret; dữ liệu được bảo vệ bởi Security Rules
  4. DCần mã hoá key bằng AES rồi giải mã lúc runtime để kẻ tấn công không đọc được
Xem đáp án
Đáp án đúng: C
API key của Firebase chỉ giúp SDK xác định project, không cấp quyền truy cập dữ liệu; quyền đó do Security Rules (cùng Auth và App Check) quyết định, nên rule để mở mới là lỗ hổng thật. Ngược lại, service account hay server key tuyệt đối không được đưa vào app, vì mọi thứ trong binary đều có thể bị trích xuất.
