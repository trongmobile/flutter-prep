Sau khi thêm một thư viện mới, build lỗi Duplicate class kotlin.collections.jdk8.CollectionsJDK8Kt found in modules ..., hoặc app crash NoSuchMethodError ở bản chạy thật vì hai thư viện kéo hai phiên bản OkHttp khác nhau. Gradle chọn phiên bản dependency thế nào, và bạn chẩn đoán, xử lý xung đột ra sao (dependencyInsight, BOM, constraints, exclude)?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Khi cùng một thư viện được kéo vào với nhiều phiên bản, Gradle mặc định chọn phiên bản cao nhất trong số được yêu cầu (không phải phiên bản khai báo đầu tiên); đa số thư viện tương thích ngược nên thường ổn. Vấn đề xuất hiện khi thư viện A cần API đã bị gỡ ở phiên bản mới (NoSuchMethodError, ClassNotFoundException lúc chạy), hoặc khi hai artifact khác tên chứa cùng class (lỗi Duplicate class, ví dụ kotlin-stdlib-jdk7 và jdk8 đã được gộp vào kotlin-stdlib từ Kotlin 1.8 nhưng thư viện cũ vẫn kéo chúng). Chẩn đoán: ./gradlew :app:dependencies --configuration releaseRuntimeClasspath xem cả cây; ./gradlew :app:dependencyInsight --dependency okhttp --configuration releaseRuntimeClasspath cho biết ai yêu cầu phiên bản nào và vì sao Gradle chọn phiên bản đang dùng. Cách xử lý: ưu tiên nâng thư viện gây xung đột lên bản đồng bộ; dùng BOM (platform("...:okhttp-bom:..."), compose-bom, firebase-bom) để các artifact cùng họ có phiên bản khớp nhau và bỏ số phiên bản ở từng dòng; ép phiên bản bằng constraints { ... because("...") } (rõ ràng, có ghi lý do) hoặc strictly trong version nếu thật sự phải khoá; exclude(group, module) để loại artifact trùng class. Tránh resolutionStrategy.force rải rác vì che giấu vấn đề. Gom phiên bản vào version catalog để cả team dùng chung, và dùng Renovate hoặc Dependabot để nâng cấp có kế hoạch. Sau khi sửa, build lại bản release (có R8) và chạy test, vì xung đột có thể chỉ lộ ra lúc chạy.
// build.gradle.kts của app
dependencies {
  // BOM: các artifact cùng họ có phiên bản khớp nhau, các dòng dưới không cần ghi version
  implementation(platform("com.squareup.okhttp3:okhttp-bom:4.12.0"))
  implementation("com.squareup.okhttp3:okhttp")
  implementation("com.squareup.okhttp3:logging-interceptor")

  // Ép phiên bản có lý do rõ ràng, thay vì force rải rác
  constraints {
    implementation("com.squareup.okio:okio:3.9.0") {
      because("SDK analytics kéo okio 2.x, gây NoSuchMethodError với OkHttp 4.12")
    }
  }

  // Loại artifact trùng class với kotlin-stdlib
  implementation(libs.legacy.sdk) {
    exclude(group = "org.jetbrains.kotlin", module = "kotlin-stdlib-jdk7")
    exclude(group = "org.jetbrains.kotlin", module = "kotlin-stdlib-jdk8")
  }
}

// Xem ai yêu cầu phiên bản nào, và vì sao Gradle chọn phiên bản đang dùng:
// ./gradlew :app:dependencyInsight --dependency okio --configuration releaseRuntimeClasspath
