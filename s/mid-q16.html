Lỗi từ Dio (timeout, 401, 500) nên được xử lý ở layer nào và trả lên trên dưới dạng gì?

Tự trả lời thành tiếng trước, rồi mới xem đáp án mẫu nhé.

Xem đáp án mẫu
Bắt và chuyển đổi ở data layer (repository implementation hoặc data source), vì DioException là chi tiết hạ tầng mà domain và UI không nên biết. Repository map lỗi sang Failure của domain (NetworkFailure, UnauthorizedFailure, ServerFailure…) rồi trả về kiểu Result dạng sealed (hoặc Either của fpdart), buộc caller xử lý cả hai nhánh bằng switch exhaustive. Presentation chỉ việc map Failure sang thông điệp thân thiện. Nhờ vậy có thể thay Dio bằng client khác hay thêm cache mà không chạm UI, và test dễ hơn vì mock trả Err(...) thay vì phải dựng DioException.
sealed class Result<T> { const Result(); }
final class Ok<T> extends Result<T> { const Ok(this.value); final T value; }
final class Err<T> extends Result<T> { const Err(this.failure); final Failure failure; }

// data layer: bắt DioException, trả về Failure của domain
Future<Result<User>> getUser(String id) async {
  try {
    final dto = await _api.fetchUser(id);
    return Ok(dto.toEntity());
  } on DioException catch (e) {
    return Err(e.response == null ? NetworkFailure() : ServerFailure());
  }
}
